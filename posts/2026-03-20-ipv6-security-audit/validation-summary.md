## Issues Found
- The FRRouting example used `show ipv6 neighbors`, but FRR documents the command as `show ipv6 neighbor`. I corrected the command to match the current FRRouting CLI.
- The `dig` example used argument ordering that does not match the documented syntax. I changed it to `dig @internal-dns example.internal AAAA`, which follows the `dig [@server] [name] [type]` form shown by the tool.
- The ICMPv6 test suggested sending a Packet Too Big message directly with `hping3`. That is misleading because Packet Too Big is an ICMPv6 error generated by a node on the path, and RFC 8201 says PMTUD relies on receiving those PTB messages. I replaced that with an oversized `ping -6 -M do` probe plus a `tcpdump` check for ICMPv6 type 2.
- The log-check examples assumed a literal `ICMPv6` or `IPv6` string would reliably appear in syslog and that a non-zero count alone proves SIEM coverage. I changed those checks to a broader local log search and clarified that exact log patterns are implementation-specific and must be verified end-to-end in the SIEM.
- The Cisco NetFlow verification command used `show ip flow export` for IPv6 monitoring. I corrected this to `show ipv6 flow export` for classic IPv6 NetFlow and added `show flow exporter <exporter-name>` for Flexible NetFlow platforms, which aligns with Cisco documentation.

## Review Notes
- The post is technically sound after the corrections above.
- The Linux firewall examples use `ip6tables`, which remains valid, but many modern Linux systems run it through the nftables backend rather than the legacy xtables backend.
- The packet-capture filters are reasonable for standard audit traffic, but deeper evasion testing involving extension headers is a separate advanced check and is relevant to the RA-Guard caveats described in RFC 7113.
