## Issues Found
- **Duplicate YAML key in Helm hook annotation** (in the `Helm Hooks for Lifecycle Management` section, `job-db-migrate.yaml`): The original snippet declared `"helm.sh/hook": pre-upgrade` and `"helm.sh/hook": pre-install` as two separate keys under `annotations:`. YAML does not allow duplicate keys at the same level — only the last value would have been applied, so the job would not have run on `pre-install`. Fixed by combining them into a single comma-separated annotation: `"helm.sh/hook": pre-install,pre-upgrade`, which is the documented Helm syntax for assigning multiple hook events to one resource.

## Review Notes
- The K3s install command (`curl -sfL https://get.k3s.io | sh -`), kubeconfig path (`/etc/rancher/k3s/k3s.yaml`), and default storage class (`local-path`) / default ingress class (`traefik`) are all correct per K3s docs.
- The Helm install script URL (`https://raw.githubusercontent.com/helm/helm/main/scripts/get-helm-3`) is the official one.
- The Helm v3.14.0 version reference and example `helm version` output format are consistent with real Helm output.
- The Bitnami chart values used in the nginx and WordPress examples (`serverBlock`, `service.nodePorts.http`, `wordpressPassword: ""` for auto-generation, `mariadb.primary.persistence`, `ingress.ingressClassName`) are valid keys in those charts as of recent versions.
- The custom chart's `deployment.yaml` template uses the standard `helm create` helper names (`myapp.fullname`, `myapp.labels`, `myapp.selectorLabels`, `myapp.serviceAccountName`) which match the scaffold generated by `helm create`.
- `helm.sh/hook-weight` lower-runs-first semantics are correct; valid `hook-delete-policy` values include `hook-succeeded`, `hook-failed`, `before-hook-creation`.
- `helm uninstall --no-hooks` is a real flag (skips hook execution during uninstall) — appropriate for clearing stuck releases.
- `kubectl delete all -l app.kubernetes.io/instance=...` is a known limitation pattern: `kubectl delete all` does not cover every resource type (e.g., it does not delete ConfigMaps, Secrets, PVCs, Ingresses by default). This is a minor caveat but acceptable for a troubleshooting tip — leaving as written.
- The empty-string pattern `password: ""` to trigger Bitnami auto-generation is a documented Bitnami convention, though some Bitnami charts now prefer omitting the field entirely. Behaviour is chart-version-specific; leaving as written since it matches the chart-author convention shown in older Bitnami examples.
