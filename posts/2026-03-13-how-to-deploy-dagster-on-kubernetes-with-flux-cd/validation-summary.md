## Issues Found
- Updated the Dagster chart version selector from `1.6.x` to `1.13.x`, matching the latest chart series available in the official Dagster Helm repository on 2026-05-13.
- Added `spec.releaseName: dagster` to the Flux HelmRelease. Without this, Flux defaults the Helm release name to `dagster-dagster` when `targetNamespace: dagster` is set, which would make the later service and deployment names incorrect.
- Moved webserver ingress configuration from `dagsterWebserver.ingress` to the chart's top-level `ingress.dagsterWebserver` structure.
- Replaced the unsupported `userDeployments` Helm values key with the chart's actual `dagster-user-deployments` key.
- Replaced Bitnami newer-style PostgreSQL values (`auth`, `primary`) with the Dagster chart's supported PostgreSQL values (`postgresqlUsername`, `postgresqlDatabase`, `existingSecret`, `persistence`, and `resources`), and disabled generated PostgreSQL secret creation when using the externally managed secret.
- Added the `dagster` Namespace before the externally managed PostgreSQL Secret so the Secret can be applied before the HelmRelease installs.
- Changed run-job TTL configuration from unsupported `jobTtlSecondsAfterFinished` to `runK8sConfig.jobSpecConfig.ttlSecondsAfterFinished`, which maps to Kubernetes Job `.spec.ttlSecondsAfterFinished`.
- Corrected run namespace RBAC to bind the actual `dagster` service account used by the chart and added a binding for the run pod service account.
- Expanded the run namespace Role to include job status, pod status, events, and update/deletecollection verbs consistent with the Dagster chart's own Kubernetes Role.
- Removed `wait: true` from the Flux Kustomization because Flux ignores `healthChecks` when `wait` is true.
- Corrected the daemon health check deployment name and daemon log selector to match the labels and object names generated by the chart.

## Review Notes

The guide still uses `dagsterApiGrpcArgs`, which remains supported; future updates could consider `codeServerArgs` for code-server reload support where appropriate.
