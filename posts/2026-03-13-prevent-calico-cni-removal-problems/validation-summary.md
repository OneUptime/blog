## Issues Found
- **Invalid `calicoctl ipam release` syntax.** The original Step 2 used `calicoctl ipam release --from-report=all`. The `--from-report` flag requires a JSON file path generated by `calicoctl ipam check --output=<file>` — `all` is not a valid value. The two commands were also in the wrong order (release before check). Fixed by generating an IPAM report first with `calicoctl ipam check --show-all-ips --output=ipam-report.json` and then running `calicoctl ipam release --from-report=ipam-report.json --force`, which matches the documented Calico workflow.

## Review Notes
- The `kubectl wait --for=delete pod -l k8s-app=calico-node ... --timeout=120s` command is correct, but the label may vary if Calico was installed via the Tigera operator (pods may live in `calico-system` namespace with operator-managed labels). The post implicitly targets manifest-based installs in `kube-system`, which is reasonable but worth noting for readers using the operator.
- CNI config filenames (`10-calico.conflist`, `calico-kubeconfig`) match Calico defaults; some installs may also leave `/etc/cni/net.d/calico.conflist.template` or operator-managed files behind.
- `kubectl get configmap kubeadm-config` only works for kubeadm-provisioned clusters; managed clusters (EKS, GKE, AKS) will not have this ConfigMap. Not strictly an error since the comment frames it as a note, but readers on managed Kubernetes should look elsewhere for the pod CIDR.
- The script's use of `awk '{print $1}' | xargs kubectl delete crd` to delete Calico CRDs is correct, but as the post itself notes, CRDs with finalizers may hang — readers should follow the linked "Fix" post procedure to patch finalizers if deletion stalls.
