## Issues Found
- The Bitbucket Cloud OAuth setup used a fixed callback URL and insufficient permissions. Updated the instructions to tell readers to copy the callback URL generated by HCP Terraform, set the app URL to `https://app.terraform.io`, mark the OAuth consumer private, and use the permissions required by HashiCorp: Account Write, Repositories Admin, Pull Requests Write, and Webhooks Read and Write.
- The `tfe_workspace` example referenced `data.tfe_oauth_client.bitbucket` without defining it. Added a matching `tfe_oauth_client` data source using `service_provider = "bitbucket_hosted"`.
- The `tfe_workspace` example used the deprecated `execution_mode` argument. Removed it because VCS-connected HCP Terraform workspaces use the remote workflow by default and the current provider documentation recommends managing execution settings separately.
- The Bitbucket Deployments section referred to "Required reviewers" for deployment environments. Updated this to "deployment permissions" and clarified that the approval gate comes from using deployment permissions together with a manual pipeline step.

## Review Notes
The Bitbucket Pipelines examples use a pinned Terraform image, valid `condition.changesets.includePaths` syntax, valid manual step syntax, and a valid Bitbucket pull request comments API endpoint shape. Terraform was not installed in the local environment, so CLI flags were verified against official documentation rather than local `terraform --help` output.
