## Issues Found
- The direct Terragrunt download command pinned `v0.55.0`, which is outdated. Updated the example to use `v1.0.5`, matching the current Terragrunt install documentation consulted during review.
- The S3 backend examples used `dynamodb_table` for locking. Terraform's S3 backend now marks DynamoDB-based locking as deprecated, so the examples were changed to `use_lockfile = true`.
- The explanation of `if_exists = "overwrite_terragrunt"` said Terragrunt would leave existing hand-written files untouched. Official Terragrunt docs state it overwrites only files previously generated by Terragrunt and errors for other existing files. Updated the explanation and noted `if_exists = "skip"` for transitional cases.
- The state-path migration text said to use `terraform state` commands, but the example used `aws s3 cp`. Updated the wording to accurately describe moving the backend object to the new key.
- The CI examples used the legacy `--terragrunt-non-interactive` flag and `run-all` form. Updated them to the current `--non-interactive` flag and `terragrunt run --all plan` command form from the Terragrunt CLI documentation.

## Review Notes
The remaining examples are illustrative and depend on matching the user's real module paths, existing backend keys, AWS accounts, and variable names. State migration should still be tested with `terragrunt plan` before any apply, as the post recommends.
