## Issues Found
- The post said official extension image tags typically match Talos versions, with examples like `iscsi-tools:v1.7.0`. GHCR tag checks and Talos docs show official extension images have their own versioning, while Image Factory/catalog compatibility selects builds for a Talos release. Updated the versioning explanation and examples.
- The Image Factory schematic examples used inline JSON with a JSON content type. Talos docs describe schematics as YAML and show uploading them with `curl --data-binary @schematic.yaml`. Updated the examples to create YAML schematics and upload them with `--data-binary`.
- The post implied Image Factory can update a fixed official extension while keeping the same Talos version and same extension set. Image Factory schematics do not pin official extension versions; they select versions for the requested Talos release. Updated the scenario to cover changing the extension set at the same Talos version, and noted that extension bug fixes should come via a Talos patch release or a custom `imager` build when pinning is required.
- Installer image references used `factory.talos.dev/installer/...`. Current Talos boot asset examples use `factory.talos.dev/metal-installer/...` for bare-metal installer images generated by Image Factory. Updated all example image references consistently.
- Worker-node `kubectl cordon`, `drain`, and `uncordon` commands used Talos node IPs as Kubernetes node names. `kubectl` operates on Kubernetes node resource names, which are not guaranteed to match Talos node IPs. Updated scripts to pass separate Talos node IPs and Kubernetes node names.
- The automated update script drained worker nodes without first cordoning them. Added `kubectl cordon` before `kubectl drain` to match the surrounding manual workflow.

## Review Notes
Talos itself cordons, drains, and uncordons during upgrades, so the manual Kubernetes drain steps are conservative and environment-dependent. They are acceptable as an operator workflow, but users should ensure the Kubernetes node names and workload disruption settings match their cluster.
