## Issues Found
- The Todo GraphQL examples used `title` and `completed`, but the default Amplify Todo schema commonly generated by the CLI uses `name` and `description`. Added the matching schema so the API operations align with the code.
- The Gradle example did not enable Compose and did not include the Material icon dependency needed for `Icons.Default.Add`. Added `buildFeatures.compose`, Compose compiler options, and `androidx.compose.material:material-icons-core`.
- The Amplify Android dependency versions were outdated. Updated the Amplify dependencies from `2.14.0` to `2.36.0`.
- The sign-up example compared `result.nextStep.signUpStep.name` to a string. Replaced it with the documented `AuthSignUpStep.CONFIRM_SIGN_UP_STEP` enum comparison.
- The custom GraphQL mutation passed variables as a JSON string and used a null serializer. Changed it to pass the variables map with `GsonVariablesSerializer()`, matching official examples.
- The Storage example used deprecated key/access-level APIs and collected progress before awaiting the result. Updated it to use `StoragePath.fromIdentityId` for private files and collect progress concurrently while awaiting `upload.result()`.
- Removed an unused `android.net.Uri` import from the Storage example.

## Review Notes
The tutorial uses the Gen 1 Amplify CLI workflow, which remains documented but is in maintenance mode and scheduled for end of life on May 1, 2027. A future revision should consider a Gen 2 backend workflow using `ampx` and `amplify_outputs.json`.
