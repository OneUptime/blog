## Issues Found

1. **git-secrets installation via apt was incorrect.** The post originally used `sudo apt install git-secrets -y`. The `git-secrets` package is not available in the default Ubuntu apt repositories; per the official awslabs/git-secrets README, it must be installed from source via `make install`. **Fixed**: replaced with the source install (`git clone` + `sudo make install`).

2. **SOPS age public-key extraction used wrong awk field.** The post used `awk '{print $3}'` to extract the public key from `~/.config/sops/age/keys.txt`. The line generated by `age-keygen` has the format `# public key: age1...`, which has four whitespace-separated fields: `#`, `public`, `key:`, `age1...`. Extracting `$3` would return the literal `key:` rather than the key, breaking the `sops --age` call. **Fixed**: changed `awk '{print $3}'` to `awk '{print $4}'`.

3. **TruffleHog installation method was inconsistent with the command syntax shown.** The post used `pip install trufflehog` to install TruffleHog, but `pip` installs the deprecated v2 Python version, which does not support the `trufflehog git file://. --json` v3 syntax shown in the next command. **Fixed**: replaced the pip install with the official v3 install script from the TruffleHog repository, which matches the command syntax used in the post.

## Review Notes

- The bash `load_env` function uses `${line// }` to test for whitespace-only lines. This removes only spaces (not tabs), so a tab-only line would not be skipped, but the subsequent regex check for `^[A-Za-z_][A-Za-z0-9_]*=` would safely reject it anyway. Functionally correct.
- The gitleaks download URL hardcodes version `8.18.2`. Newer versions exist (e.g., `8.30.x` as of mid-2026), but the URL pattern remains valid and the version pinned is still downloadable. A future revision could point readers at the `/latest` release page.
- `pip install git-filter-repo` is correct, but `git-filter-repo` is also available via apt on recent Ubuntu releases (`sudo apt install git-filter-repo`). Either is acceptable; the post's choice works.
- The `dotenv-cli` global npm install is correct, but readers may want to consider language-native loaders (e.g., `python-dotenv`, the Node.js `dotenv` package) instead of a global CLI dependency for production scenarios.
- The `load_env` bash function safely avoids `source`/`eval` injection but does not strip surrounding quotes from values (e.g., `KEY="value"` would export `KEY` as the literal string `"value"` including the quotes). This is a minor caveat not worth changing in this guide, as the focus is safety-against-execution rather than full dotenv parity.
- `auditctl -w ... -p r -k secret-access` is correct, and `aureport --file` does accept piped `ausearch` output via stdin. Both are valid usages.
