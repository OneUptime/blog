# How to Configure IPv6 Firewall on Home Routers - A Practical Guide

Author: [nawazdhandala](https://www.github.com/nawazdhandala)

Tags: IPv6, Firewall, Home Router, Security, Ip6tables, OpenWrt

Description: Configure IPv6 firewall rules on home routers to protect devices from inbound internet threats, allowing stateful return traffic while blocking unsolicited connections.

## Why IPv6 Firewall Matters

With IPv6, devices can have globally routable addresses - there is no NAT to hide them by default. A firewall is essential.

```text
IPv4 with NAT:
  Internet → Router NAT → All home devices hidden

IPv6 without NAT:
  Internet → Router → Each device can have a public IPv6 address
  → Firewall rules REQUIRED to block unsolicited inbound
```

## OpenWrt IPv6 Firewall (fw4/nftables)

OpenWrt 22.03 and later uses firewall4 (`fw4`) with nftables for IPv6 packet filtering.

```bash
# View current firewall rules generated by fw4

fw4 print
nft list ruleset

# Default OpenWrt IPv6 firewall zones:
#   WAN zone: input REJECT, output ACCEPT, forward REJECT
#   LAN zone: input ACCEPT, output ACCEPT, forward ACCEPT

# Add or change rules through UCI/LuCI so they persist across reloads.
```

## Essential ICMPv6 Rules

ICMPv6 is mandatory for IPv6 to work - do not block it all. If you are writing raw Netfilter rules, permit the required control traffic instead of dropping all ICMPv6 from WAN.

```bash
# ICMPv6 traffic commonly permitted for healthy IPv6 operation (RFC 4890)

# Allow Neighbor Discovery Protocol on directly connected links
ip6tables -A INPUT -p ipv6-icmp --icmpv6-type router-solicitation -j ACCEPT
ip6tables -A INPUT -p ipv6-icmp --icmpv6-type router-advertisement -j ACCEPT
ip6tables -A INPUT -p ipv6-icmp --icmpv6-type neighbor-solicitation -j ACCEPT
ip6tables -A INPUT -p ipv6-icmp --icmpv6-type neighbor-advertisement -j ACCEPT

# Allow essential IPv6 error reporting
ip6tables -A INPUT -p ipv6-icmp --icmpv6-type destination-unreachable -j ACCEPT
ip6tables -A INPUT -p ipv6-icmp --icmpv6-type packet-too-big -j ACCEPT
ip6tables -A INPUT -p ipv6-icmp --icmpv6-type time-exceeded -j ACCEPT
ip6tables -A INPUT -p ipv6-icmp --icmpv6-type parameter-problem -j ACCEPT

# Allow Ping (optional but useful)
ip6tables -A INPUT -p ipv6-icmp --icmpv6-type echo-request -j ACCEPT
ip6tables -A INPUT -p ipv6-icmp --icmpv6-type echo-reply -j ACCEPT

# Let the chain policy handle everything else.
```

## OpenWrt Firewall Configuration (UCI)

Manage IPv6 firewall via OpenWrt's Unified Configuration Interface.

```bash
# View current firewall config
cat /etc/config/firewall

# Add rule to allow inbound SSH to specific home server
uci add firewall rule
uci set firewall.@rule[-1].name='Allow-SSH-inbound-IPv6'
uci set firewall.@rule[-1].src='wan'
uci set firewall.@rule[-1].dest='lan'
uci set firewall.@rule[-1].dest_ip='2001:db8:42::1337'
uci set firewall.@rule[-1].proto='tcp'
uci set firewall.@rule[-1].dest_port='22'
uci set firewall.@rule[-1].target='ACCEPT'
uci set firewall.@rule[-1].family='ipv6'
uci commit firewall
/etc/init.d/firewall restart

# Verify rule was added
nft list ruleset | grep "tcp dport 22"
```

## nftables IPv6 Firewall (Modern Linux Routers)

Many modern routers use nftables instead of ip6tables.

```bash
# /etc/nftables.conf - IPv6 home router firewall

table inet filter {
    chain input {
        type filter hook input priority 0; policy drop;

        # Allow established connections
        ct state established,related accept

        # Allow loopback
        iif lo accept

        # Allow ICMPv6 (simple home-router policy)
        ip6 nexthdr icmpv6 accept

        # Allow SSH from LAN only
        iif "br-lan" tcp dport 22 accept

        # Allow DHCPv6 client replies from ISP
        ip6 nexthdr udp udp sport 547 udp dport 546 accept

        # Drop everything else
        drop
    }

    chain forward {
        type filter hook forward priority 0; policy drop;

        # Allow established connections (stateful)
        ct state established,related accept

        # Allow ICMPv6 through (PMTU, error reporting, etc.)
        ip6 nexthdr icmpv6 accept

        # Allow LAN to WAN (outbound)
        iif "br-lan" oif "eth0" accept

        # Drop new inbound from WAN
        iif "eth0" drop
    }
}
```

## Test Firewall Effectiveness

```bash
# From an external IPv6 host (or phone on LTE with IPv6)

# Test that random ports are blocked
nc -6 -v 2001:db8:42::1337 80   # Should not connect
nc -6 -v 2001:db8:42::1337 443  # Should not connect (if not server)

# Test that allowed services work
nc -6 -v 2001:db8:42::1337 22   # Should connect (if SSH allowed)

# From home device - verify outbound still works
ping -6 2606:4700:4700::1111    # Should work (stateful allows return)
curl -6 https://google.com    # Should work

# Check if NDP/RA still works (ICMPv6 not blocked)
rdisc6 eth0    # Replace eth0 with the LAN-side interface on your client
```

## Conclusion

IPv6 firewall on home routers must block all unsolicited inbound connections while allowing stateful return traffic for outbound sessions. Do not indiscriminately block ICMPv6; permit the control traffic needed for Neighbor Discovery, Path MTU Discovery, Router Advertisements, and error reporting. On OpenWrt, use the UCI firewall interface to add specific inbound allow rules for services you intend to expose (SSH, HTTPS). Use nftables for modern routers - define forward chain policy as `drop` and add explicit accept rules for LAN→WAN traffic. Test firewall effectiveness by scanning your public IPv6 addresses from an external connection on mobile data.
