## Issues Found
- The wheelhouse explanation said `--no-index --find-links=...` installs only from the wheelhouse. `--no-index` disables package indexes, but requirements files may still contain direct URL or local-path requirements. The wording now limits the claim to named requirements and explicitly calls out that direct references must be excluded for a wheelhouse-only final-stage install.
- The dependency-control paragraph described pins and hashes as providing "bit-for-bit dependency control." pip's hash-checking mode verifies the specific distribution artifacts consumed; it does not by itself make the complete installed environment bit-for-bit reproducible. The paragraph now describes exact dependency-artifact verification and notes that an sdist hash is not the hash of a wheel built from that sdist.
- The compatibility guidance called `python:3.14-slim` a pinned image even though Docker image tags are mutable. The post now calls it an explicit image variant and recommends a digest when rebuilds must use identical base-image contents.
- The `--target` section implied that setting `PYTHONPATH` is sufficient for every installation. Python adds that directory to `sys.path`, but it does not treat an arbitrary `PYTHONPATH` entry as a site directory or automatically process its `.pth` files. The post now limits the claim to ordinary imports and documents `site.addsitedir()` as an explicit option for packages that depend on `.pth` processing.

## Review Notes
- The `python:3.14-slim` tag exists and Python 3.14 is supported at the validation date. When installing OS packages, deployments may also want an explicit Debian suite tag to reduce disruption when the default suite changes.
- `build-essential` covers common compiler tooling, but individual native dependencies may require additional development headers in the builder and corresponding shared libraries in the runtime image.
- The Dockerfile examples are syntactically current. `RUN --mount=type=cache` is supported by the declared Dockerfile frontend, and the named-stage `COPY --from=...`, numeric `USER`, and exec-form `CMD` usages are valid.
