## Issues Found
- The prerequisites said pods in one cluster must be able to reach pods in another. That is only true for single-network multicluster installs. For the different-network setup shown in the post, workloads communicate through east-west gateways. Updated the wording to distinguish direct pod routing from reachable east-west gateways.
- The CA generation commands created intermediate certificates directly with `openssl x509 -req` and did not create the full Istio CA file layout expected by the documented `cacerts` secret. Replaced them with Istio's documented `Makefile.selfsigned.mk` flow, which generates `ca-cert.pem`, `ca-key.pem`, `root-cert.pem`, and `cert-chain.pem` for each cluster.
- The CA secret commands referenced the wrong generated file names and used only the intermediate certificate as `cert-chain.pem`. Updated the commands to use the per-cluster files generated by Istio's certificate Makefile.
- Because the post creates `istio-system` before installing Istio, the namespaces also need the `topology.istio.io/network` labels used by Istio's different-network multicluster flow. Added the network labels for both clusters.
- The manually written east-west gateway IstioOperator was missing the current `values.gateways.istio-ingressgateway.injectionTemplate: gateway` setting used by Istio's generated east-west gateway manifest. Added that setting.

## Review Notes
- The sample manifest URLs for Istio release 1.24 still resolve successfully, but the current Istio documentation reviewed is for Istio 1.30. A future refresh could update sample URLs and examples to a single explicitly stated Istio version.
- The post explains primary-remote conceptually but only walks through the multi-primary different-network installation. That is not technically incorrect, but a future version could either add the primary-remote procedure or narrow the description to the implemented topology.
