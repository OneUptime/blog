# How to Configure Elemental for Air-Gapped Environments

Author: [nawazdhandala](https://www.github.com/nawazdhandala)

Tags: Elemental, Air-Gap, Kubernetes, Edge, Security

Description: Set up Elemental in air-gapped environments by mirroring required images and configuring offline registries.

## Introduction

Air-gapped deployments require all container images, charts, and OS artifacts to be available from internal infrastructure. Elemental supports air-gapped operation through private registries, mirrored OS images, and seed images built from a `MachineRegistration`. This guide covers the complete setup for air-gapped Elemental deployments.

## Prerequisites

- Private container registry (Harbor, Nexus, or similar)
- Rancher air-gapped installation already configured
- Access to mirror required charts, images, and OS artifacts before going air-gapped
- Optional internal HTTP server for seed ISO and RAW image distribution

## Step 1: Mirror Elemental Images

```bash
# Download the official air-gap helper script
wget https://raw.githubusercontent.com/rancher/elemental-operator/main/scripts/elemental-airgap.sh
chmod 755 elemental-airgap.sh

PRIVATE_REGISTRY="my-registry.internal.example.com"

# Download the operator charts, required container images,
# and a custom channel image that points to your private registry
./elemental-airgap.sh stable -r "${PRIVATE_REGISTRY}"

# The script creates:
# - elemental-operator-crds-chart-<VERSION>.tgz
# - elemental-operator-chart-<VERSION>.tgz
# - elemental-images.txt
# - elemental-images.tar.gz
```

## Step 2: Configure Helm for Air-Gapped Install

```bash
# Load the mirrored images archive into the private registry
docker login my-registry.internal.example.com

rancher-load-images.sh \
  --image-list elemental-images.txt \
  --images elemental-images.tar.gz \
  --registry my-registry.internal.example.com

# Install the local charts generated by elemental-airgap.sh
# The script prints the exact install command for the chart version it downloaded.
helm upgrade --create-namespace -n cattle-elemental-system \
  --install elemental-operator-crds elemental-operator-crds-chart-<VERSION>.tgz

helm upgrade --create-namespace -n cattle-elemental-system \
  --install elemental-operator elemental-operator-chart-<VERSION>.tgz \
  --set registryUrl=my-registry.internal.example.com \
  --set channel.repository=rancher/elemental-channel-my-registry.internal.example.com
```

## Step 3: Configure Private Registry on Nodes

```yaml
# machine-registration-airgap.yaml
apiVersion: elemental.cattle.io/v1beta1
kind: MachineRegistration
metadata:
  name: airgap-nodes
  namespace: fleet-default
spec:
  config:
    cloud-config:
      write_files:
        # K3s reads registry configuration from /etc/rancher/k3s/registries.yaml
        - path: /etc/rancher/k3s/registries.yaml
          content: |
            mirrors:
              docker.io:
                endpoint:
                  - "https://my-registry.internal.example.com"
              registry.k8s.io:
                endpoint:
                  - "https://my-registry.internal.example.com"
              registry.suse.com:
                endpoint:
                  - "https://my-registry.internal.example.com"
            configs:
              "my-registry.internal.example.com":
                auth:
                  username: "robot$elemental"
                  password: "your-registry-password"
                tls:
                  ca_file: /etc/ssl/certs/internal-ca.pem
          permissions: "0600"

        # RKE2 uses the same format, but reads it from /etc/rancher/rke2/registries.yaml
        - path: /etc/rancher/rke2/registries.yaml
          content: |
            mirrors:
              docker.io:
                endpoint:
                  - "https://my-registry.internal.example.com"
              registry.k8s.io:
                endpoint:
                  - "https://my-registry.internal.example.com"
              registry.suse.com:
                endpoint:
                  - "https://my-registry.internal.example.com"
            configs:
              "my-registry.internal.example.com":
                auth:
                  username: "robot$elemental"
                  password: "your-registry-password"
                tls:
                  ca_file: /etc/ssl/certs/internal-ca.pem
          permissions: "0600"

        # Provide the CA file referenced by the registry configuration
        - path: /etc/ssl/certs/internal-ca.pem
          content: |
            -----BEGIN CERTIFICATE-----
            <internal-registry-ca>
            -----END CERTIFICATE-----
          permissions: "0644"

        # In a true air-gap, disable fallback to upstream default endpoints
        - path: /etc/rancher/k3s/config.yaml.d/20-airgap-registry.yaml
          content: |
            disable-default-registry-endpoint: true
          permissions: "0644"

        - path: /etc/rancher/rke2/config.yaml.d/20-airgap-registry.yaml
          content: |
            disable-default-registry-endpoint: true
          permissions: "0644"

    elemental:
      install:
        device: /dev/sda
        reboot: true
```

## Step 4: Build Air-Gapped Seed Images

```bash
# Build an ISO seed image from a mirrored Elemental ISO base image
cat > seedimage-iso-airgap.yaml << 'EOF'
apiVersion: elemental.cattle.io/v1beta1
kind: SeedImage
metadata:
  name: airgap-seed-iso
  namespace: fleet-default
spec:
  type: iso
  cleanupAfterMinutes: 0
  # Use one of the mirrored ISO images produced by Step 1
  baseImage: my-registry.internal.example.com/suse/sl-micro/6.0/baremetal-iso-image:2.1.1-3.36
  registrationRef:
    apiVersion: elemental.cattle.io/v1beta1
    kind: MachineRegistration
    name: airgap-nodes
    namespace: fleet-default
EOF

# Build a RAW seed image from a mirrored Elemental container base image
cat > seedimage-raw-airgap.yaml << 'EOF'
apiVersion: elemental.cattle.io/v1beta1
kind: SeedImage
metadata:
  name: airgap-seed-raw
  namespace: fleet-default
spec:
  type: raw
  cleanupAfterMinutes: 0
  # Use one of the mirrored container images produced by Step 1
  baseImage: my-registry.internal.example.com/suse/sl-micro/6.0/baremetal-os-container:2.1.1-3.29
  registrationRef:
    apiVersion: elemental.cattle.io/v1beta1
    kind: MachineRegistration
    name: airgap-nodes
    namespace: fleet-default
EOF

kubectl apply -f seedimage-iso-airgap.yaml
kubectl apply -f seedimage-raw-airgap.yaml

kubectl wait --for=condition=ready pod -n fleet-default airgap-seed-iso
kubectl wait --for=condition=ready pod -n fleet-default airgap-seed-raw

kubectl get seedimage -n fleet-default airgap-seed-iso -o jsonpath="{.status.downloadURL}"
kubectl get seedimage -n fleet-default airgap-seed-raw -o jsonpath="{.status.downloadURL}"
```

## Step 5: Internal HTTP Server for OS Distribution

```bash
# Download the generated seed artifacts from the Elemental operator
# If Rancher uses a self-signed certificate, add --cacert /path/to/rancher-ca.pem
curl -L "$(kubectl get seedimage -n fleet-default airgap-seed-iso -o jsonpath='{.status.downloadURL}')" \
  -o elemental-seed.iso

curl -L "$(kubectl get seedimage -n fleet-default airgap-seed-raw -o jsonpath='{.status.downloadURL}')" \
  -o elemental-seed.raw

# Set up Nginx to serve OS images internally
cat > /etc/nginx/conf.d/elemental.conf << 'EOF'
server {
    listen 80;
    server_name files.internal.example.com;

    location /elemental/ {
        root /var/www/html;
        autoindex on;
        # Support range requests for large files
        add_header Accept-Ranges bytes;
    }
}
EOF

# Copy OS images to serving directory
mkdir -p /var/www/html/elemental
cp elemental-seed.iso /var/www/html/elemental/
cp elemental-seed.raw /var/www/html/elemental/

systemctl restart nginx
```

## Conclusion

Air-gapped Elemental deployments require careful pre-staging of all required artifacts: operator charts, container images, OS base images, custom channel metadata, and seed boot media. By mirroring all dependencies to an internal registry, configuring K3s or RKE2 to use it, and generating seed images from `MachineRegistration`, you achieve a fully functional Elemental deployment with no external network access. This approach is essential for high-security environments, military deployments, and industrial sites with strict network isolation requirements.
