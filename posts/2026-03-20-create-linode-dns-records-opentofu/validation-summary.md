## Issues Found
- **SRV record used `name` field instead of `service`/`protocol`.** The original example set `name = "_sip._tcp"` on the SRV record. Per the Linode Terraform provider docs, "Setting this is invalid for `SRV` records as it is generated by the API." The correct configuration uses the dedicated `service` and `protocol` arguments (without leading underscores), as confirmed by the provider's own SRV template (`service = "myservice"`, `protocol = "tcp"`). I replaced `name = "_sip._tcp"` with `service = "sip"` and `protocol = "tcp"`.

## Review Notes
- All `ttl_sec` values used (300 and 3600) are in the Linode-supported set (`30, 120, 300, 3600, 7200, 14400, ...`).
- `linode_domain` `type` values `"master"` and `"slave"` are still the current/valid values in the Linode provider; no rename has occurred.
- Empty string for `name` on `linode_domain_record` to represent the apex (`@`) is the documented convention.
- The CNAME example points `api.example.com` at `api.example.com` (effectively a self-referential CNAME). The HCL is syntactically valid and serves as an illustration of CNAME syntax, but readers should substitute a real external target (e.g., a load balancer hostname) when applying it. Left unchanged to preserve author intent.
- `linode_instance.web.ip_address` is a real attribute of `linode_instance`; references in the A-record examples are valid.
- MX `priority = 1` and `priority = 5` are valid (Linode permits priorities 0–255).
