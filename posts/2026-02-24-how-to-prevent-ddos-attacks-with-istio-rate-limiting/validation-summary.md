## Issues Found
- The post said local rate limiting runs entirely within each Envoy sidecar, but the example targets an ingress gateway. Changed this to "Envoy proxy" so it applies correctly to sidecars and gateway proxies.
- The per-route local rate limiting example only patched route-level filter config. Envoy still needs the `envoy.filters.http.local_ratelimit` HTTP filter in the filter chain, so I added the matching `HTTP_FILTER` patch and explicit enable/enforce settings.
- The global rate limiting EnvoyFilter added a custom cluster named `rate_limit_cluster` but the rate limit filter referenced Istio's generated `outbound|8081||ratelimit.istio-system.svc.cluster.local` cluster. Removed the unused custom cluster patch and kept the Istio service cluster reference used by the official Istio example.
- The client IP section implied that the rate-limit action alone extracts the real client IP. Added the Istio gateway topology caveat for deployments behind a load balancer or reverse proxy.
- The monitoring section omitted Istio's requirement to include local rate-limit stats with `proxyStatsMatcher`. Added the required stats matcher example.
- The Prometheus example used a metric name that did not include the configured `stat_prefix`. Updated it to match Envoy's Prometheus conversion of `http_local_rate_limiter.http_local_rate_limit.rate_limited`.

## Review Notes
The examples still rely on `EnvoyFilter`, which Istio documents as exposing internal Envoy implementation details that can change during upgrades. For production use, pin the `envoyproxy/ratelimit` image instead of using `latest`, and verify the exact virtual host names generated by Istio for the target Gateway and VirtualService.
