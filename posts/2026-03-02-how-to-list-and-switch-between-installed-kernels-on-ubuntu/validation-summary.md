## Issues Found

1. **Incorrect awk indexing for GRUB menu entries** (two occurrences). The original command used `NR-1`, which prints the file line number (minus 1) rather than the 0-based menu entry index that `grub-reboot` / `grub-set-default` expect. Reproduced against a sample grub.cfg: `NR-1` produced `2`, `5`, `13` while the correct entry indices were `0`, `1`, `2`. Replaced `NR-1` with `i++` (an auto-incrementing counter that only advances on matching lines), which yields the proper 0-based menu entry indices.

2. **Broken wget command for Mainline Kernel download.** The command embedded a shell-style wildcard (`linux-image-unsigned-*.deb`) directly inside an HTTPS URL. Per `man wget`, globbing only applies to FTP — HTTP requests would attempt to fetch the literal URL and fail. Replaced with the standard recursive directory-crawl form: `wget -r -l 1 -nd -A "*.deb" "https://kernel.ubuntu.com/~kernel-ppa/mainline/${VERSION}/amd64/"`, which is the documented approach for grabbing all .deb files from a mainline build directory.

## Review Notes
- `grub-set-default` (Method 1) only takes effect when `/etc/default/grub` has `GRUB_DEFAULT=saved`; otherwise the next `update-grub` overwrites the saved entry. The post does cover `GRUB_DEFAULT=saved` in Method 2 but does not explicitly link the two — readers using Method 1 in isolation may be surprised. Left as-is since adding clarifying content is out of scope for technical-error fixes.
- The Mainline Kernel section comments "Using the Ubuntu Mainline Kernel PPA tool" but actually demonstrates manual `wget` usage, not the `mainline` / `ubuntu-mainline-kernel.sh` tool. Wording mismatch but the procedure itself is valid.
- `apt autoremove` behavior around kernels depends on `/etc/apt/apt.conf.d/01autoremove-kernels` (generated by unattended-upgrades) and is roughly "keeps running + previous", which matches the post. Not always exactly two — can vary by configuration.
- The mainline kernel URL `https://kernel.ubuntu.com/~kernel-ppa/mainline/` is the long-standing path and currently still resolves; the canonical path has been mirrored at `https://kernel.ubuntu.com/mainline/` in recent years. Either works today.
- Kernel versions referenced (5.15.0-89, 5.15.0-91, 6.2.0-39, v6.8 mainline) are plausible/realistic Ubuntu versions and used purely as examples.
