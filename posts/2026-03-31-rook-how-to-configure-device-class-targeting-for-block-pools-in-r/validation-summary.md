## Review Notes
- The CRUSH rule dump example uses a comment (`# ~ separates root and device class`) inside a JSON-like output block. Since the block is marked as `text` (not `json`), this is acceptable as an educational annotation, though readers should understand this comment would not appear in actual command output.
- The CRUSH rule name `replicated_ssd_pool` in the example is illustrative. The actual rule name generated by Rook may differ (often based on the pool name). The post correctly instructs readers to first check the rule name via `ceph osd pool get ssd-pool crush_rule` before dumping it.
- The `ceph device ls` command listed under "Checking Current Device Classes" shows physical device information rather than device class assignments directly, but it is still useful context and not incorrect to include.
