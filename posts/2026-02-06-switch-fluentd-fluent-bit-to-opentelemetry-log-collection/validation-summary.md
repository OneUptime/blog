## Issues Found
- The Kubernetes filelog example attempted to parse Kubernetes metadata from `attributes["log.file.name"]` while matching a full `/var/log/containers/...` path. The filelog receiver only adds the basename to `log.file.name` by default, and the current container parser metadata extraction expects `log.file.path`. Updated the example to tail `/var/log/pods/*/*/*.log`, set `include_file_path: true`, and rely on the `container` operator to extract Kubernetes resource attributes.
- The Kubernetes example associated pods only by a non-semantic `pod_name` resource generated by a regex parser. Updated `pod_association` to use `k8s.pod.uid`, with a fallback using `k8s.pod.name` and `k8s.namespace.name`.
- The routing example used the older routing processor configuration shape with `from_attribute`, `attribute_source`, and `default_exporters`. Updated the section to use the current routing connector with `default_pipelines`, OTTL conditions, and separate output pipelines.
- The Transform processor example used the older context-specific path form for setting severity. Updated it to the current documented path form, `set(log.severity_text, log.attributes["level"])`.
- The post described OTTL as SQL-like. Adjusted the wording to describe OTTL more accurately as functions, paths, and conditions.
- Updated related prose references from "routing processor" to "routing connector" where the corrected example now uses the connector.

## Review Notes
- The OpenTelemetry Collector component set depends on the distribution in use. The corrected examples assume a distribution that includes contrib/k8s components such as `filelog`, `k8sattributes`, `routing`, and `elasticsearch`.
- The routing connector is currently marked alpha in the official component README, while many processors and the filelog receiver are beta for logs.
