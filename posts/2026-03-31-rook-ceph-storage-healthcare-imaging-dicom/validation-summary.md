## Issues Found

### 1. Horos incorrectly listed as a DICOM server with S3 support
**What was wrong:** The Architecture Overview listed "Orthanc, dcm4chee, and Horos" as DICOM servers that can use S3-compatible backends. Horos is a macOS DICOM viewer (forked from OsiriX), not a DICOM server, and has no S3 storage backend support.
**What was changed:** Removed Horos from the list, keeping only Orthanc and dcm4chee.

### 2. Orthanc StorageEncryption MasterKey format incorrect
**What was wrong:** `"MasterKey": "base64-encoded-key"` — a plain string. The Orthanc object-storage plugin expects an array: `[key-id, "path/to/key-file"]` where the first element is a uint32 key version ID and the second is a file path to the AES-256 key.
**What was changed:** Updated to `"MasterKey": [1, "/path/to/master.key"]`.

### 3. ObjectBucketClaim additionalConfig used non-existent fields
**What was wrong:** The OBC `additionalConfig` included `objectLockEnabled`, `defaultRetentionMode`, and `defaultRetentionDays`. These are not valid fields in Rook's OBC provisioner. Object Lock must be enabled at the CephObjectStore CR level (`spec.security.objectLock.enabled`), and retention policies must be configured via the S3 API after bucket creation.
**What was changed:** Added `security.objectLock.enabled: true` to the CephObjectStore spec. Replaced invalid OBC additionalConfig fields with standard fields. Added an S3 API command (`aws s3api put-object-lock-configuration`) to configure COMPLIANCE retention after bucket creation.

### 4. radosgw-admin audit logging command had incorrect syntax
**What was wrong:** `radosgw-admin log show --bucket=dicom-archive --date=2026-03-31 --bucket-id=<bucket-id>` — the `--bucket` and `--date` flags are not valid parameters for the `log show` subcommand. Additionally, `log show` is a legacy internal logging mechanism not suited for HIPAA audit trails.
**What was changed:** Replaced with `radosgw-admin usage show --uid=<uid> --start-date=2026-03-01 --end-date=2026-03-31 --show-log-entries=true`, which is the correct command for querying per-user/per-bucket access usage data.

## Review Notes
- The CephBlockPool comment "DICOM images are already compressed" is a simplification — uncompressed DICOM transfer syntaxes are common. However, disabling compression is a reasonable default since re-compressing already-compressed data wastes CPU with minimal size benefit.
- The example AWS-style credentials (AKIAIOSFODNN7EXAMPLE) are recognizable placeholder values from AWS documentation. For a Ceph RGW deployment, credentials would be generated by `radosgw-admin user create` and look different, but the placeholders are acceptable for illustration.
- For production HIPAA audit logging, consider also enabling RGW ops logging via `rgw_ops_log_rados` or `rgw_ops_log_file_path` Ceph configuration options, which provide per-request operation logs more suitable for compliance audit trails than usage summaries alone.
