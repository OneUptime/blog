## Issues Found
- The local path-specific rate limiting example defined descriptor token buckets but did not configure any `rate_limits` actions to generate the `path` descriptor. Added a `request_headers` action for `:path` so the descriptors can match.
- The global per-user rate limit service configuration did not match the composed descriptor produced by the Envoy actions. Changed the `user-id` limit to a nested descriptor under `header_match: user-id`.
- Several descriptor examples used extra keys such as `path_value`, `method_value`, and `user_value` that were not generated by the matching Envoy actions. Updated the descriptor hierarchy so the configured keys and values match the descriptors Envoy sends.
- The quota example used `unit: month`, but the Envoy rate limit service supports `second`, `minute`, `hour`, and `day`. Changed that example to a daily storage quota.
- The adaptive rate limit example used `limit_override`, which is not the Envoy route rate limit field name. Changed it to `limit`.
- The multi-stage rate limiting text implied all configured stages are evaluated automatically by one filter. Clarified that each stage requires a rate limit HTTP filter configured with the matching `stage` value.
- The sequence diagram described the rate limit service returning `OK (200)`, which is misleading for the gRPC rate limit decision. Changed it to `OK decision`.

## Review Notes
EnvoyFilter exposes Envoy implementation details and can be sensitive to Istio/Envoy version changes. The examples now align with current official documentation, but production users should still test generated Envoy config with `istioctl proxy-config` after Istio upgrades.
