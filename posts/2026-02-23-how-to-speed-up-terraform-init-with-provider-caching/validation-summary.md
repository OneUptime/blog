## Issues Found
- The post said `.terraform.lock.hcl` stores version constraints. Terraform stores provider dependency selections and checksums there, while constraints come from configuration. Updated the wording.
- The plugin cache example described `plugin_cache_may_break_dependency_lock_file` as a symlink optimization. HashiCorp documents it as an exceptional setting that can allow incomplete lock file entries. Updated the comment.
- The filesystem mirror example said the `direct` block fell back for anything not in the mirror, but its `exclude` pattern prevents direct installation for HashiCorp providers. Updated the comment and air-gapped wording.
- The GitHub Actions and Docker examples used older Terraform/setup action versions. Updated `hashicorp/setup-terraform` to v4 and Terraform examples to 1.14.6.
- The Docker mirror build script used relative paths that could point outside the intended build context after changing directories. Updated it to use an absolute `MIRROR_DIR`.
- The network mirror section suggested a simple reverse proxy to the Terraform Registry. Terraform network mirrors must implement the provider network mirror protocol, so the Nginx example was changed to serve a static mirror generated by `terraform providers mirror`.
- The summary overstated provider downloads as always the biggest bottleneck and implied all filesystem mirrors eliminate all network access. Updated it to account for backend work and direct fallback behavior.

## Review Notes
Terraform was not installed in the local workspace, so CLI behavior was validated against official HashiCorp documentation rather than local `terraform --help` output. The performance timings are plausible examples but will vary by provider versions, runner bandwidth, backend configuration, and cache state.
