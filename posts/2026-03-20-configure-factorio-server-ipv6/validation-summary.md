## Issues Found
- The post stated that Factorio could be configured straightforwardly for IPv6-only or dual-stack hosting. Current stable Factorio `2.0.76` does not provide full IPv6 support, and official staff posts state the networking stack can bind either IPv4 or IPv6, not both. I corrected the introduction, bind example, `systemd` example, and conclusion to reflect that limitation.
- The post claimed a `server-settings.json` file could be generated by starting the server with `--server-settings`. Official docs point readers to the bundled `data/server-settings.example.json` instead. I replaced that step with copying the bundled example and added creation of the `saves` directory before `--create`.
- The JSON snippet was not valid JSON because it included a `//` comment line. I removed the comment line so the snippet is valid JSON.
- The JSON snippet set `"visibility": { "public": true }` while leaving `username`, `password`, and `token` blank. The official example marks Factorio.com credentials as required for public visibility. I changed `public` to `false` so the example is internally consistent.
- The firewall persistence example used `sudo ip6tables-save > /etc/ip6tables/rules.v6`, which would not elevate the shell redirection. I changed it to `sudo sh -c 'ip6tables-save > /etc/ip6tables/rules.v6'`.
- The verification example used `2001:db8::factorio`, which is not a valid IPv6 literal. I changed it to `2001:db8::1`.
- The whitelist section said Factorio uses Steam usernames and suggested enabling the whitelist with `"use_server_whitelist": true` inside `server-settings.json`. Official command-line docs expose `--use-server-whitelist` as a startup flag, and Factorio account usernames are distinct from Steam account identifiers. I changed the wording to Factorio player names and corrected the whitelist enablement instructions.
