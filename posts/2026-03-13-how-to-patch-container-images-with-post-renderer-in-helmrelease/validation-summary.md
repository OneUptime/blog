## Issues Found
- The introduction said Flux post-renderers can patch images in any resource generated by a Helm chart. Flux documents that Helm post-renderers are not applied to chart hooks, so the wording was changed to "rendered Helm chart resources" and a hook limitation note was added.
- The first image transformer explanation said it replaces any occurrence of an image string across all rendered resources. Kustomize's images transformer updates matching image references, not arbitrary text occurrences, so the wording was narrowed to "matching container image references."
- The Flux Image Automation section implied the marker alone updates tags when images are pushed. The marker must be used with configured `ImagePolicy` and `ImageUpdateAutomation` resources, so the explanation was updated.
- The conclusion repeated the broader "Helm chart resources" wording. It was changed to "rendered Helm chart resources" to match the verified Helm post-renderer behavior.

## Review Notes
The HelmRelease examples use the current `helm.toolkit.fluxcd.io/v2` API and valid `postRenderers.kustomize.images` / `postRenderers.kustomize.patches` fields. Kustomize supports `newName`, `newTag`, and `digest` in the `images` list, and the inline strategic merge patch format is valid for a Kubernetes `Deployment`. The kubectl verification commands use supported `-o jsonpath` output.
