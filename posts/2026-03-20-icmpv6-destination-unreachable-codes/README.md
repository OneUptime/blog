Description: Deep-dive into each ICMPv6 Destination Unreachable code, when to generate each, how applications interpret them, and the correct firewall and router behaviors for each code.

## Introduction

The currently assigned codes of ICMPv6 Destination Unreachable (Type 1) each represent a distinct failure scenario. RFC 4443 defines codes 0 through 6, and later RFCs add codes 7, 8, and 9 for specialized routing and header-processing failures. Routers and endpoints generate different codes based on why the packet cannot be delivered. Applications may see these conditions as socket errors, but the exact errno mapping depends on the OS and transport protocol. Firewalls should generate the correct code when rejecting traffic. Using the wrong code misleads diagnostics and can reveal or hide information about network topology.

## Code-by-Code Analysis

```text
Code 0: No Route to Destination
  Generated by: Router (not the destination)
  When: No routing table entry matches the destination address
  Application sees: On Linux, commonly ENETUNREACH (Network unreachable)
  Example: Packet to 2001:db8::1 when no route to 2001:db8::/32 exists

Code 1: Administratively Prohibited
  Generated by: Router or endpoint (firewall)
  When: Packet matches a "reject" firewall rule
  Application sees: On Linux, commonly EACCES (Permission denied)
  Note: Tells the source traffic is blocked; use if transparency is acceptable
  Example: ip6tables -j REJECT --reject-with icmp6-adm-prohibited

Code 2: Beyond Scope of Source Address
  Generated by: Router or endpoint
  When: Source address scope is insufficient for the destination
  Application sees: On Linux, commonly EHOSTUNREACH (generic reachability failure)
  Example: Host uses link-local source address to reach global destination
           through a router (router rejects: link-local src cannot be routed)

Code 3: Address Unreachable
  Generated by: Router (after NDP failure)
  When: Neighbor Discovery fails to resolve the destination link-layer address
  Application sees: On Linux, commonly EHOSTUNREACH (Host unreachable)
  Example: IPv6 address exists in routing table, but the host doesn't respond
           to Neighbor Solicitation on the link

Code 4: Port Unreachable
  Generated by: Destination host (not a router)
  When: No process is listening on the destination port (UDP only)
  Application sees: On Linux, commonly ECONNREFUSED (Connection refused)
  Note: TCP sends RST instead of using ICMPv6 for port unreachable
  Example: UDP packet to 2001:db8::1:53 when no DNS server runs

Code 5: Source Address Failed Ingress/Egress Policy
  Generated by: Router or firewall performing source-validation or ingress filtering
  When: Packet fails Unicast Reverse Path Forwarding check
  Application sees: On Linux, commonly EACCES
  Example: Packet arrives on wrong interface relative to routing table
           (BCP 38 anti-spoofing filter)

Code 6: Reject Route
  Generated by: Router or firewall
  When: Forwarding policy explicitly rejects the route instead of silently dropping it
  Application sees: On Linux, commonly EACCES
  Example: ip6tables -j REJECT --reject-with icmp6-reject-route

Code 7: Error in Source Routing Header
  Generated by: Router processing an RPL Source Routing Header
  When: The next hop in the strict source route is not on-link or the route cannot be satisfied
  Application sees: If surfaced to user space on Linux, often EPROTO
  Example: RPL source-routed packet whose next hop is not directly reachable

Code 8: Headers too long
  Generated by: Router or endpoint
  When: Aggregate IPv6 header processing exceeds the node's parsing limit
  Application sees: If surfaced to user space on Linux, often EPROTO
  Example: Device drops a packet because the IPv6 header chain is too long to parse

Code 9: Error in P-Route
  Generated by: RPL node forwarding along a projected route
  When: Packet cannot be forwarded along a P-Route in an RPL network
  Application sees: If surfaced to user space on Linux, often EPROTO
  Example: Packet reaches a broken projected route segment and the node reports the failure to the RPL root
```

## Application Error Mapping

```python
import socket
import errno

# Common Linux mappings for ICMPv6 Destination Unreachable codes.
# Exact behavior is OS- and transport-dependent.

CODE_TO_ERRNO = {
    0: (errno.ENETUNREACH,  "ENETUNREACH: No route to destination"),
    1: (errno.EACCES,       "EACCES: Administratively prohibited"),
    2: (errno.EHOSTUNREACH, "EHOSTUNREACH: Beyond scope of source address"),
    3: (errno.EHOSTUNREACH, "EHOSTUNREACH: Address unreachable"),
    4: (errno.ECONNREFUSED, "ECONNREFUSED: Port unreachable"),
    5: (errno.EACCES,       "EACCES: Source address policy failure"),
    6: (errno.EACCES,       "EACCES: Reject route"),
    7: (errno.EPROTO,       "EPROTO: Error in Source Routing Header"),
    8: (errno.EPROTO,       "EPROTO: Headers too long"),
    9: (errno.EPROTO,       "EPROTO: Error in P-Route"),
}

def diagnose_os_error(err: OSError) -> str:
    """Interpret common Linux socket errors related to IPv6 delivery failures."""
    error_map = {
        errno.ENETUNREACH: "No route to destination (Code 0)",
        errno.EHOSTUNREACH: "Address unreachable or beyond-scope failure (commonly Code 2 or 3)",
        errno.ECONNREFUSED: "UDP port unreachable (Code 4) or a TCP reset from the peer",
        errno.EACCES: "Administrative, policy, or reject-route failure (Code 1, 5, or 6)",
        errno.EPROTO: "Less common ICMPv6 control error (commonly Code 7, 8, or 9)",
        errno.ETIMEDOUT: "Timeout or silent filtering; no ICMPv6 error was delivered",
    }
    return error_map.get(err.errno, f"Unknown error: {err}")

try:
    s = socket.socket(socket.AF_INET6, socket.SOCK_STREAM)
    s.settimeout(5)
    s.connect(("2001:db8::1", 80))
except OSError as e:
    print(diagnose_os_error(e))
else:
    s.close()
    print("Connected successfully")
```

## Generating the Correct Code in ip6tables

```bash
# Code 0: No route (use when dropping due to missing route)
# This is automatically generated by the kernel for routing failures

# Code 1: Administratively prohibited (explicit reject)
sudo ip6tables -A FORWARD -d 2001:db8:bad::/48 \
    -j REJECT --reject-with icmp6-adm-prohibited

# Code 3: Address unreachable
sudo ip6tables -A FORWARD \
    -j REJECT --reject-with icmp6-addr-unreachable

# Code 4: Port unreachable (for UDP port blocking)
sudo ip6tables -A INPUT -p udp --dport 123 \
    -j REJECT --reject-with icmp6-port-unreachable

# Code 5: Source address failed ingress/egress policy
sudo ip6tables -A FORWARD -s 2001:db8:100::/48 \
    -j REJECT --reject-with icmp6-policy-fail

# Code 6: Reject route
sudo ip6tables -A FORWARD -d 2001:db8:feed::/48 \
    -j REJECT --reject-with icmp6-reject-route

# Using DROP instead of REJECT (sends no ICMPv6 at all)
# Use when you want to hide that traffic is being filtered
sudo ip6tables -A FORWARD -s 2001:db8:dead::/48 -j DROP

# Codes 2, 7, 8, and 9 are not generic firewall reject cases:
# they arise from source-scope checks or specialized routing/header-processing failures.

# List reject rules showing the reject-with type
sudo ip6tables -L -v -n | grep REJECT
```

## Conclusion

The correct use of ICMPv6 Destination Unreachable codes provides accurate feedback to sources about why their packets failed. Code 0 for routing failures, Code 1 for administrative policy blocks, Code 3 for NDP resolution failures, and Code 4 for closed UDP ports are the most common. Codes 5 and 6 are also available as explicit reject types in modern Linux `ip6tables`, while Codes 7, 8, and 9 are specialized extensions from later RFCs. Using REJECT with the appropriate `--reject-with` value in `ip6tables` generates the correct code for the common firewall-driven cases. When security requires hiding the reason for packet drops, use DROP instead to send no ICMPv6 error at all.
