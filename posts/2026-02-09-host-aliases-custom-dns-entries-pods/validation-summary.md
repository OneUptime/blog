## Issues Found
- The post stated that all containers in a pod share the same /etc/hosts file. Updated this to say they receive the same /etc/hosts entries, matching kubelet's per-container managed hosts file behavior.
- The service mesh section claimed that hostAliases bypasses the mesh. Updated it to explain that hostAliases changes DNS resolution only, and whether traffic bypasses the sidecar depends on the mesh interception rules.
- The hostNetwork limitation said hostAliases does not work with hostNetwork pods. Updated it for current Kubernetes behavior: kubelet can generate a hosts file based on the node's /etc/hosts and append HostAliases.
- The post said hostAliases entries are prepended to /etc/hosts. Updated it to say they are added after the default Kubernetes-managed entries, as shown in the official HostAliases documentation and kubelet source.
- The init-container example attempted to modify /etc/hosts using an emptyDir volume mounted at /etc/hosts. Replaced it with guidance that dynamic hostAliases cannot be generated by init containers and direct /etc/hosts modification is unreliable because kubelet manages the file.
- The security example used an invalid IPv4 address, 10.0.0.999. Changed it to the valid example address 10.0.0.99.
- The security section recommended Pod Security Policies, which were deprecated in Kubernetes v1.21 and removed in v1.25. Updated the recommendation to ValidatingAdmissionPolicy or admission webhooks.
