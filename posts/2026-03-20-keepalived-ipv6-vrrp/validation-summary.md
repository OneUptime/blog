## Issues Found
- The IPv6 example addresses used identifiers such as `::vip`, `::vip2`, and `::server1`, which are not valid IPv6 literals. I replaced them with valid documentation-prefix addresses such as `2001:db8::100` and `2001:db8:1::10`.
- The VRRPv3 examples included `authentication` blocks. RFC 9568 states that VRRPv3 does not define authentication, and keepalived's current documentation reflects that. I removed the authentication blocks and replaced them with an accurate note.
- The IPv6 VRRP examples omitted the required link-local virtual address as the first advertised IPv6 address. I added a `fe80::/64` virtual address first in each IPv6 `virtual_ipaddress` block to make the examples RFC-compliant.
- The dual-stack section claimed a single VRRP instance could carry both IPv4 and IPv6 VIPs together. RFC 9568 treats IPv4 and IPv6 as separate virtual router instances, and keepalived requires `virtual_ipaddress` entries to be the same address family. I replaced the example with separate IPv4 and IPv6 `vrrp_instance` definitions.
- The LVS/IPVS example used older directive names (`lb_algo`, `lb_kind`, `nb_get_retry`) instead of the current keepalived syntax (`lvs_sched`, `lvs_method`, `retry`). I updated the configuration to match the current keepalived manual.
- The failover timing claim said the VIP should move "within 3 seconds" with `advert_int 1`. Based on VRRP timing (`3 * advert_int + skew_time`) and the shown BACKUP priority of `100`, the takeover is about 3.6 seconds. I corrected the note.

## Review Notes
- The post is now technically correct against the current keepalived configuration manual and the current VRRP standard, RFC 9568.
- keepalived can still operate with a non-link-local first IPv6 VIP when `vrrp_strict` is not enabled, but that behavior is explicitly less strict than the RFC. The updated examples use the standards-compliant form.
- The `HTTP_GET` health checks are syntactically valid with `status_code 200`; readers who want response-body validation rather than status-only validation could additionally use `digest` checks generated by `genhash`.
