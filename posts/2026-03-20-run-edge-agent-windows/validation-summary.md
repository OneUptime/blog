## Issues Found
1. **Edge communication ports were described too narrowly**: The post said the Edge Agent initiates all outbound connections to Portainer on port 8000 over WSS. Portainer documents that agents poll the Portainer API on the UI/API port, usually 9443, and standard mode opens an outbound tunnel to port 8000 only when interactive management is needed. **Fix:** Updated the diagram and explanation to show API polling on 9443 and an on-demand TLS tunnel on 8000.
2. **The Edge environment API example used the wrong request format and missing fields**: `POST /api/endpoints` accepts `multipart/form-data`, not the JSON payload shown. For an Edge Agent on Docker, the request also needs the Portainer API `URL` and `ContainerEngine=docker`; otherwise current Portainer treats an empty container engine as Kubernetes. **Fix:** Changed the example to use `curl -F`, added `URL` and `ContainerEngine`, and extracted `EDGE_ID` / `EDGE_KEY` from the response for the deployment commands.
3. **Async mode command used unsupported environment variables**: The Portainer Agent recognizes `EDGE_ASYNC`, but not `EDGE_CHECKIN_INTERVAL` or `EDGE_SNAPSHOT_INTERVAL`. Async intervals are configured on the Portainer environment, and async mode is a Business Edition feature. **Fix:** Removed the unsupported variables, added `EDGE_INSECURE_POLL=0`, and noted the Business Edition requirement in the command comment.
4. **Windows command did not match the current generated Portainer command**: The previous Windows example used a short `-v //./pipe/docker_engine://./pipe/docker_engine` mount and omitted the Windows Docker volumes/data mounts. Portainer's generated Windows standalone command uses a named-pipe mount plus `C:\ProgramData\docker\volumes` and `C:\data`. **Fix:** Replaced the example with a PowerShell command using `--mount type=npipe`, the Docker volumes bind mount, and the agent data volume.
5. **Verification skipped valid Edge environments when `EdgeID` is empty**: Portainer can associate the Edge ID on first poll unless generated Edge IDs are enforced, so filtering API results by `EdgeID` can miss Edge environments. **Fix:** Changed the filter to use endpoint types 4 and 7, which represent Edge Agent on Docker and Edge Agent on Kubernetes.
6. **Metadata typo**: The tag list used `Window` instead of `Windows`. **Fix:** Corrected the tag.

## Review Notes
- The examples still use `portainer/agent:latest` to preserve the post's style. In production, Portainer recommends matching the Agent image version to the Portainer Server version or using the command generated by the Portainer UI.
- The Windows command now explicitly targets Windows containers mode. Docker Desktop on Windows in Linux containers mode generally uses the Linux socket-style deployment command.
- The `--insecure` curl flag is appropriate only for self-signed or test deployments; production setups should use trusted TLS certificates.
