## Issues Found
- The HelmRelease values used non-existent chart keys such as `controller.replicas`, `scheduler.config`, and `admission.resources`. Updated the snippet to use the current Volcano chart's `custom.controller_replicas`, `custom.scheduler_replicas`, `custom.admission_replicas`, `custom.scheduler_config_override`, and component resource keys.
- The PyTorch Volcano job referenced `VC_TASK_NUM` and `VC_MASTER_HOST`, which are not the service discovery variables generated by Volcano. Added the `env` and `svc` plugins and changed the command to use `VC_MASTER_NUM`, `VC_WORKER_NUM`, `VC_TASK_INDEX`, and `/etc/volcano/master.host`.
- The ResourceQuota section described queue-level enforcement, but Kubernetes ResourceQuota is namespace-scoped. Updated the section to describe namespace limits alongside Volcano queue capabilities and added the required namespaces.
- The GPU ResourceQuota used `limits.nvidia.com/gpu`, but Kubernetes extended resource quotas use the `requests.` prefix. Removed the invalid limit quota key.
- The MPI example used only `ssh` and `svc` plugins and referenced `/etc/volcano/mpihost`, which is not the documented MPI host source. Updated it to use the Volcano `mpi` plugin and `${MPI_HOST}`.
- The Flux Kustomization health check targeted Helm-created Deployments directly. Updated it to health-check the `HelmRelease`, matching Flux guidance for Kustomizations that contain HelmRelease resources.
- The repository structure omitted files introduced later in the post and used `kustomization.yaml` for the Flux Kustomization manifest. Updated the structure and snippet path to use `volcano-kustomization.yaml`, leaving `kustomization.yaml` available for Kustomize configuration if needed.
