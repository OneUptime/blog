## Issues Found
1. **Outdated lockfile name** — The post recommended `bun.lockb` as the lockfile to commit. Since Bun 1.2 (released early 2025), the default lockfile is the text-based `bun.lock`. Updated the best-practices section accordingly.
2. **Incorrect TypeScript `types` entry** — The `tsconfig.json` example listed `"types": ["bun-types"]`. The current package generated by `bun init` and recommended by the docs uses `"types": ["bun"]` (the `@types/bun` package is referenced via the short name `bun`). The `bun-types` package is legacy. Updated to `"types": ["bun"]`. This also makes the snippet consistent with the `package.json` example earlier in the post, which already uses `@types/bun`.

## Review Notes
- The `curl -fsSL https://bun.sh/install | bash` URL still works (it redirects to `bun.com`), so it was left intact. Future revisions could switch to `https://bun.com/install` for precision.
- `bun init` in current versions also generates a `CLAUDE.md` file and a `.cursor/rules/...` file in addition to the five files mentioned. The five listed in the post (`package.json`, `tsconfig.json`, `index.ts`, `.gitignore`, `README.md`) are still all created and correct as the "basic" project structure, so the list was not expanded.
- The `bun:test` example imports `beforeAll` and `afterAll` but does not use them. This is a minor stylistic point, not a technical error, so it was left alone.
- The claim that `Bun.env` is "typed and more explicit" than `process.env` is a soft stylistic recommendation; both objects are functionally equivalent in Bun. Not corrected as it is not factually wrong.
- Startup time figures (~25ms Bun, ~100ms Node.js, ~50ms Deno) are approximate, environment-dependent numbers and are presented as such; left as-is.
