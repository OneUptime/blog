## Issues Found
- The post said AWS generates the temporary SSH key pair. AWS documentation states the EC2 Instance Connect API pushes a public key to instance metadata; the key pair can be generated by the client flow. Changed the wording and diagram to say a temporary key pair is generated without assigning generation to AWS.
- The prerequisites implied the instance security group should always allow SSH from the EC2 Instance Connect service IP range. That is correct for public-IP console access, but endpoint-based private access uses the endpoint path. Updated the prerequisite to distinguish the two cases.
- The tag-restricted IAM policy used `ec2-instance-connect:osUser`. AWS documents the OS-user condition key as `ec2:osuser`. Corrected the policy.
- The endpoint connection section omitted `ec2-instance-connect:OpenTunnel`, which AWS requires for EC2 Instance Connect Endpoint connections. Added a focused IAM example for endpoint use.
- The Terraform example referenced `aws_security_group.ic_endpoint.id` without defining that security group. Added the missing endpoint security group with SSH egress.
- The auditing section said every session is logged in CloudTrail and implied full SSH visibility. AWS logs EC2 Instance Connect API/connection requests such as `SendSSHPublicKey` and endpoint tunnel requests such as `OpenTunnel`, not SSH command contents. Updated the wording and noted `OpenTunnel` for endpoint-based connections.
