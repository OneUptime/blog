## Issues Found
- The post implied `dnsConfig.nameservers` simply adds arbitrary custom resolvers without explaining Kubernetes merge behavior or the three-nameserver limit. Added a note that Kubernetes merges `dnsConfig` with the base DNS configuration generated by `dnsPolicy`, and that at most three nameserver IPs can be specified in `dnsConfig`.
- The Google DNS example included Kubernetes cluster search domains, which would not make Kubernetes Service names resolvable unless the configured resolvers can answer or forward the cluster domain. Replaced the cluster search domains with `example.com` and added a caveat about Kubernetes Service resolution.
- The ClusterFirst combination example said the pod uses cluster DNS first with additional resolvers. Clarified that `dnsConfig.nameservers` is appended to the resolver list and `searches` is merged with the policy-generated search list.
- The corporate DNS example said it maintains Kubernetes cluster search domains. Clarified that those search domains are useful only when corporate DNS is configured to forward Kubernetes zones to CoreDNS.
- The split DNS section incorrectly described nameservers as if they route internal, corporate, and public DNS by domain. Reworked the explanation and example to use `ClusterFirst` with an additional corporate search domain, and noted that true split DNS by domain belongs in CoreDNS forwarding configuration.
- The multi-network pod section implied DNS servers could be tied to specific pod interfaces through `dnsConfig`. Clarified that `dnsConfig` applies to the pod resolver as a whole and adjusted the example to add only network-specific search domains.
- The service-specific API example added public DNS for external API calls under `ClusterFirst`, which is misleading because CoreDNS normally forwards external queries and extra nameservers are resolver failover, not normal external lookup routing. Removed the public nameserver and kept the `ndots` optimization.
- The IPv6 example mixed ClusterFirst with three custom nameservers and used the deprecated `inet6` resolver option. Changed it to `dnsPolicy: None` with IPv6 public resolvers and removed `inet6`.
- The troubleshooting snippet suggested adding public DNS as a ClusterFirst fallback. Changed it to an explicit temporary `dnsPolicy: None` example for isolating upstream resolver issues.
