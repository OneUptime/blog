# How to Create Elemental Seed Images

Author: [nawazdhandala](https://www.github.com/nawazdhandala)

Tags: Elemental, Kubernetes, Seed Images, Edge, ISO

Description: Step-by-step guide to creating Elemental seed images (ISOs and raw disk images) that embed registration configuration for automated bare metal provisioning.

## Introduction

Elemental seed images are bootable media (ISOs or raw disk images) that contain the registration configuration from a `MachineRegistration` so a machine can register itself with Rancher and install the Elemental OS. In current Elemental / OS Manager deployments, the supported way to generate them is with the `SeedImage` resource, which injects the registration URL, CA data, and optional cloud-config into the media automatically.

## Prerequisites

- Elemental Operator installed
- A `MachineRegistration` resource configured
- `kubectl` access to the management cluster
- A base Elemental image available in `registry.suse.com`
- Docker or Podman (only if you are building a custom base image)
- TPM 2.0 on target machines, or `spec.config.elemental.registration.emulate-tpm: true` for environments without TPM

## Types of Seed Images

| Type | Use Case |
|------|----------|
| ISO | Physical media, virtual machines, iDRAC/iLO virtual media |
| Raw disk image | USB drives, SD cards |
| PXE/iPXE | Separate network boot workflow; not generated by the `SeedImage` resource used in this guide |

## Step 1: Gather Registration Configuration

```bash
# Export registration URL
REG_URL=$(kubectl get machineregistration my-nodes \
  -n fleet-default \
  -o jsonpath='{.status.registrationURL}')

echo "Registration URL: $REG_URL"

# Optional: inspect the generated registration file that SeedImage injects
wget --no-check-certificate "$REG_URL" -O initial-registration.yaml
```

## Step 2: Create the Seed Image Configuration

The install target, reboot behavior, and registration settings stay on the referenced `MachineRegistration`. The `SeedImage` resource links that registration to a downloadable ISO or raw image and can add optional `cloud-config` customizations.

```yaml
# seed-image-iso.yaml
apiVersion: elemental.cattle.io/v1beta1
kind: SeedImage
metadata:
  name: elemental-seed-iso
  namespace: fleet-default
spec:
  type: iso
  baseImage: registry.suse.com/suse/sl-micro/6.1/baremetal-iso-image:latest
  registrationRef:
    apiVersion: elemental.cattle.io/v1beta1
    kind: MachineRegistration
    name: my-nodes
    namespace: fleet-default
  cloud-config:
    users:
      - name: root
        passwd: "$6$rounds=4096$salt$hashedpassword"
        ssh_authorized_keys:
          - "ssh-ed25519 AAAAC3NzaC1lZDI1NTE5AAAA... admin@example.com"
    write_files:
      - path: /etc/motd
        permissions: "0644"
        content: |
          Elemental seed image booted successfully.
```

## Step 3: Build an ISO Seed Image

```bash
# Create the SeedImage resource
kubectl apply -f seed-image-iso.yaml

# Wait for the SeedImage to be ready
kubectl wait --for=condition=Ready seedimage/elemental-seed-iso \
  -n fleet-default \
  --timeout=30m

# Download the generated ISO
wget --no-check-certificate \
  "$(kubectl get seedimage elemental-seed-iso \
    -n fleet-default \
    -o jsonpath='{.status.downloadURL}')" \
  -O elemental-seed.iso

# Verify the ISO was created
ls -lh elemental-seed.iso
```

## Step 4: Build a Raw Disk Image (USB)

```yaml
# seed-image-raw.yaml
apiVersion: elemental.cattle.io/v1beta1
kind: SeedImage
metadata:
  name: elemental-seed-raw
  namespace: fleet-default
spec:
  type: raw
  baseImage: registry.suse.com/suse/sl-micro/6.1/baremetal-os-container:latest
  registrationRef:
    apiVersion: elemental.cattle.io/v1beta1
    kind: MachineRegistration
    name: my-nodes
    namespace: fleet-default
```

```bash
# Create the raw SeedImage resource
kubectl apply -f seed-image-raw.yaml

# Wait for the SeedImage to be ready
kubectl wait --for=condition=Ready seedimage/elemental-seed-raw \
  -n fleet-default \
  --timeout=30m

# Download the generated raw disk image
wget --no-check-certificate \
  "$(kubectl get seedimage elemental-seed-raw \
    -n fleet-default \
    -o jsonpath='{.status.downloadURL}')" \
  -O elemental-seed.raw

# Write to USB drive (replace /dev/sdX with your USB device)
sudo dd if=elemental-seed.raw of=/dev/sdX bs=4M status=progress conv=fsync
sync
```

## Step 5: Customize the Seed Image

### Adding Custom Files

For simple user, file, or first-boot customization, prefer the `cloud-config` field in the `SeedImage`. For package-level changes, build a custom base image first.

```dockerfile
# custom-seed.Dockerfile
FROM registry.suse.com/suse/sl-micro/6.1/baremetal-os-container:latest AS os

# Install additional tools
RUN zypper install -y \
    vim \
    jq \
    && zypper clean -a

# Copy custom configuration
COPY my-custom-config.yaml /system/oem/90-custom-config.yaml
COPY custom-scripts/ /usr/local/bin/

ARG IMAGE_REPO=myrepo/custom-build
ARG IMAGE_TAG=v1.0.0
RUN sed -i -e "s|^IMAGE_REPO=.*|IMAGE_REPO=\"${IMAGE_REPO}\"|g" /etc/os-release && \
    sed -i -e "s|^IMAGE_TAG=.*|IMAGE_TAG=\"${IMAGE_TAG}\"|g" /etc/os-release && \
    sed -i -e "s|^IMAGE=.*|IMAGE=\"${IMAGE_REPO}:${IMAGE_TAG}\"|g" /etc/os-release && \
    elemental init --force elemental-rootfs,grub-config,dracut-config,cloud-config-essentials,elemental-setup

FROM registry.suse.com/suse/sl-micro/6.1/baremetal-os-container:latest AS builder

ARG TARGETARCH
WORKDIR /iso
COPY --from=os / rootfs

# Work around buildah issue
RUN rm -f rootfs/etc/resolv.conf
RUN elemental build-iso \
    dir:rootfs \
    --bootloader-in-rootfs \
    --squash-no-compression \
    -o /output -n "elemental-${TARGETARCH}"

FROM busybox
COPY --from=builder /output /elemental-iso
ENTRYPOINT ["busybox", "sh", "-c"]
```

```bash
# Build and push the custom ISO container image
docker build -t myrepo/custom-build-iso:v1.0.0 \
  --build-arg IMAGE_REPO=myrepo/custom-build \
  --build-arg IMAGE_TAG=v1.0.0 \
  -f custom-seed.Dockerfile .

docker push myrepo/custom-build-iso:v1.0.0
```

Then set `baseImage` in `seed-image-iso.yaml` to `myrepo/custom-build-iso:v1.0.0` and apply it again.

## Verifying the Seed Image

For lab VMs, either attach a virtual TPM or set `spec.config.elemental.registration.emulate-tpm: true` on the referenced `MachineRegistration`. On x86_64, boot the VM in UEFI mode. Adjust the OVMF paths if your distribution stores them outside `/usr/share/OVMF`.

```bash
# Test the ISO in a VM (requires QEMU/KVM and OVMF for UEFI boot)
qemu-img create -f qcow2 /tmp/test-disk.qcow2 40G
cp /usr/share/OVMF/OVMF_VARS.fd /tmp/OVMF_VARS.fd

qemu-system-x86_64 \
  -m 4096 \
  -drive if=pflash,format=raw,readonly=on,file=/usr/share/OVMF/OVMF_CODE.fd \
  -drive if=pflash,format=raw,file=/tmp/OVMF_VARS.fd \
  -cdrom elemental-seed.iso \
  -drive file=/tmp/test-disk.qcow2,format=qcow2 \
  -boot d \
  -nographic
```

## Distributing Seed Images

```bash
# Upload to an S3-compatible bucket
aws s3 cp elemental-seed.iso s3://my-bucket/elemental-images/

# Or serve via HTTP
python3 -m http.server 8080 --directory $(pwd)
```

## Conclusion

Elemental seed images provide the zero-touch provisioning foundation for your edge and bare metal fleet. By pairing a `MachineRegistration` with a `SeedImage`, you can generate installation media that carries the registration configuration automatically. That keeps the provisioning workflow repeatable and aligned with the current Elemental / OS Manager tooling, whether you are delivering an ISO through virtual media or writing a raw image to removable storage.
