## Issues Found
- The Compose example used `version: "3.8"`, which is now an obsolete informational field in current Compose. Replaced it with `name: myapp` so later examples using `myapp-api-1` and `myapp_default` match the Compose project name generated by Docker Compose.
- The `frontend` and `api` services both combined replicas with fixed host-port publishing. This prevents clean scaling because each replica cannot bind the same host port. Removed the frontend replica count and changed the API service from `ports: "3000:3000"` to `expose: "3000"` so API replicas remain internal behind the frontend.
- The API healthcheck used `curl`, but the post did not show an API image that installs curl. Replaced it with a Python standard-library healthcheck command that fits the Python API container.
- The Flask Redis fallback caught only `ConnectionError`, but redis-py can raise `TimeoutError` when socket timeouts occur. Updated the example to import and catch both exception types so the network-partition and timeout behavior matches the post's explanation.
- Commands and monitoring examples called `http://localhost:3000` directly even after using multiple internal API replicas. Updated them to call `http://localhost` through the frontend, which is the host-published service in the corrected Compose setup.
- The automated experiment filters used broad `name=api` and `name=redis` matches. Updated them to `name=myapp-api` and `name=myapp-redis` to align with the explicit Compose project name.
