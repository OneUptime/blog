## Issues Found
- **Submariner Helm chart values keys had wrong casing.** The post used `clusterCIDR`, `serviceCIDR`, and `clusterID` under `values.submariner.*` in the `submariner-operator` HelmRelease. The actual chart values keys in 0.17.x are camelCase with lowercase `d`/`d`: `clusterCidr`, `serviceCidr`, `clusterId` (verified by extracting `values.yaml` from `submariner-operator-0.17.6.tgz`). With the original casing Helm would silently treat them as unknown values and the operator would be deployed with empty cluster ID/CIDRs, breaking the deployment. Fixed the three keys in Step 2.

## Review Notes
- The `submariner-k8s-broker` chart in 0.17.x is minimal (`rbac.create`, `crd.create`, `serviceAccounts.client.*`) and does not consume `ipsec.psk` or `serviceDiscovery` values. The values shown for the broker HelmRelease in Step 1 are silently ignored by Helm; they are conceptually informative but not functional. The actual PSK is generated by `subctl deploy-broker` and Service Discovery / IPsec PSK are configured on the member clusters via the `submariner-operator` chart. Left as-is to preserve the author's narrative, since the unknown values do not cause a deployment failure.
- Step 1 (Helm-based broker install) and Step 3 (`subctl deploy-broker`) describe two different broker installation paths that can be redundant — `subctl deploy-broker` already installs the broker chart and emits `broker-info.subm`. Most production setups pick one approach. This is a stylistic / workflow comment, not a correctness issue.
- The prerequisites list UDP 4500 (IPsec NAT-T) and TCP 8080 (metrics). For libreswan, UDP 500 (IKE) may also be required when clusters are not behind NAT; UDP 4490 is used for libreswan NATT discovery; and the VXLAN cable driver uses UDP 4800 instead. Not incorrect, but incomplete for non-NAT-T scenarios — worth a future note.
- `subctl verify --kubeconfig X --toconfig Y --only connectivity` is valid: subctl builds prefixed flags via `WithPrefixedContext("to")`, which produces `--toconfig` (path to the second kubeconfig) and `--tocontext` (context name within it). The docs more commonly show the `--context` / `--tocontext` form, but the kubeconfig-path form used in the post works.
- ServiceExport `multicluster.x-k8s.io/v1alpha1`, `clusterset.local` DNS zone, `subctl deploy-broker`, `subctl show all`, and the Flux apiVersions (`source.toolkit.fluxcd.io/v1`, `helm.toolkit.fluxcd.io/v2`, `kustomize.toolkit.fluxcd.io/v1`) are all current and correct.
- `colorCodes` default in the chart is the bare value `blue` (the chart default is unquoted); quoting it as `"blue"` in the post is fine — YAML accepts both.
