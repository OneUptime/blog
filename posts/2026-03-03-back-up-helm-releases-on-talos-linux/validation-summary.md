## Review Notes
- The Method 2 restore section is technically correct (applying Helm Secrets re-registers the releases with Helm), but it does not re-create the actual Kubernetes workloads owned by those releases — that requires `helm rollback` or running `helm upgrade` afterward. The post does not claim otherwise, but readers unfamiliar with Helm internals might assume otherwise.
- The `alpine/helm:3.14` image tag in the CronJob example is a community-maintained image (alpine/helm on Docker Hub). The minor-version tag pattern works; specifying a patch version (e.g., `3.14.4`) would be more reproducible.
- The `while read name namespace` loop in the backup script would be more robust with `read -r` to prevent backslash interpretation, but it works correctly for the simple `name namespace` input being generated by jq.
- The Helm release Secret backup approach captures release metadata only; PV/PVC data is not part of the Helm release and would need a separate backup strategy (Velero with the node agent covers this, but the simple Method 1/2 scripts do not).
