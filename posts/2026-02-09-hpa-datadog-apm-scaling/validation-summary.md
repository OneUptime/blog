## Issues Found
- The setup snippet used a standalone Secret and ConfigMap with keys that are not the documented Helm values for enabling the Cluster Agent metrics provider. Replaced it with documented Helm values for `datadog.apiKey`, `datadog.appKey`, `clusterAgent.metricsProvider.enabled`, and `clusterAgent.metricsProvider.useDatadogMetrics`.
- The Helm command enabled the metrics provider but not DatadogMetric query support. Added `clusterAgent.metricsProvider.useDatadogMetrics=true`.
- The APIService verification command grepped for Datadog text rather than checking the registered external metrics API directly. Updated it to `kubectl get apiservice v1beta1.external.metrics.k8s.io`.
- Several HPA examples used invented metric names such as `datadog.trace.requests_per_second`, `datadog.trace.error_rate`, and `datadog.trace.p99_latency_ms`. Replaced them with `DatadogMetric` resources using Datadog APM trace metric names in the documented `trace.<SPAN_NAME>.<METRIC_SUFFIX>` format and HPA references in the documented `datadogmetric@<namespace>:<name>` format.
- Several HPA manifests omitted `scaleTargetRef.apiVersion`. Added `apiVersion: apps/v1` for Deployment targets to match Kubernetes examples and avoid ambiguity.
- The error-rate example claimed that a metric called `error_rate` represented errors per minute. Reworked it as a Datadog query that calculates an error percentage from `trace.<SPAN_NAME>.errors` and `trace.<SPAN_NAME>.hits`.
- The latency examples used non-existent millisecond metric names. Reworked them to use Datadog APM latency distribution queries with p95/p99 aggregators and adjusted HPA target values to seconds.
- The Python custom metric example initialized the Datadog client with API and application keys for DogStatsD. Updated it to initialize DogStatsD host and port, matching Datadog's Python DogStatsD examples.
- The custom metric HPA referenced a non-existent `datadog.custom.orders.processed_per_second` metric. Replaced it with a `DatadogMetric` query for the emitted `orders.processed` DogStatsD metric.
- Monitoring and troubleshooting commands still referred to raw invented metric names and selector labels. Updated them to use DatadogMetric resources and DatadogMetric query terminology.

## Review Notes
The APM examples use `trace.web.request` as a representative span name. Real deployments must replace `web.request` with the span name generated by their Datadog integration, such as `rails.request`, `pylons.request`, or another service entry span name.
