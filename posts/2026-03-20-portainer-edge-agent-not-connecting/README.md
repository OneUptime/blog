# How to Fix Edge Agent Not Connecting to Portainer Server - A Practical Guide

Author: [nawazdhandala](https://www.github.com/nawazdhandala)

Tags: Portainer, Docker, Troubleshooting, Edge Agent, Edge Computing

Description: Diagnose and resolve Edge Agent connection failures to the Portainer server, including tunnel configuration, key issues, and network connectivity problems.

## Introduction

The Portainer Edge Agent is designed for environments where the Portainer server cannot directly reach the Docker host - the agent polls outbound to the server and, when needed, establishes a reverse tunnel back to it. When this connection fails, edge devices appear offline and cannot be managed. This guide covers all common failure points.

## How Edge Agent Connectivity Works

Unlike the standard agent (where the server connects to the agent), the Edge Agent:
1. Polls the Portainer server over the API/UI port (typically 9443) for work
2. Opens a reverse tunnel to the Portainer server on port 8000 when interactive management is required
3. Portainer uses this tunnel to send management commands

This means the edge device only needs outbound access to the Portainer API/UI endpoint and tunnel endpoint - no inbound ports required on the edge device.

## Step 1: Verify the Edge Agent Is Running

```bash
# On the edge device, check if the agent is running

docker ps | grep portainer-edge-agent

# Check logs
docker logs portainer-edge-agent --tail 50

# Look for connection messages
docker logs portainer-edge-agent 2>&1 | grep -i "tunnel\|connect\|server\|error"
```

## Step 2: Verify the Edge Key

The Edge Agent requires a key generated by the Portainer server:

```bash
# The key should have been provided when you created the Edge environment in Portainer
# Check the agent's configured key
docker inspect portainer-edge-agent | grep EDGE_KEY
```

If the key is missing or wrong:

1. In Portainer UI, go to **Environments** and select the Edge environment
2. Open the **Edge information** section
3. Verify the deployment uses the correct `EDGE_ID` and `EDGE_KEY`
4. Redeploy the agent with the correct values

## Step 3: Correct Edge Agent Deployment

```bash
# Example Edge Agent deployment command (match the agent image to your Portainer server version)
docker run -d \
  -v /var/run/docker.sock:/var/run/docker.sock \
  -v /var/lib/docker/volumes:/var/lib/docker/volumes \
  -v /:/host \
  -v portainer_agent_data:/data \
  --restart always \
  -e EDGE=1 \
  -e EDGE_ID=<your-edge-id> \
  -e EDGE_KEY=<your-edge-key> \
  -e EDGE_INSECURE_POLL=1 \
  --name portainer-edge-agent \
  portainer/agent:<match-your-portainer-version>
```

## Step 4: Verify Outbound Connectivity to Portainer

```bash
# Test outbound connection to Portainer server on port 8000
# (This is the tunnel port)
nc -zv portainer-server.yourdomain.com 8000

# Test HTTPS access to Portainer (port 9443) and surface TLS errors
curl -v https://portainer-server.yourdomain.com:9443

# If using Portainer Cloud or a custom tunnel host/port
nc -zv your-tunnel-host your-tunnel-port
```

## Step 5: Check Portainer Server Tunnel Port Configuration

For standard Edge Agent deployments, the Portainer server must expose port 8000:

```bash
# Verify Portainer server has port 8000 exposed
docker inspect portainer | grep -A 20 '"PortBindings"'

# If 8000 is not exposed, recreate Portainer with the tunnel port published
docker stop portainer && docker rm portainer
docker run -d \
  -p 9000:9000 \
  -p 9443:9443 \
  -p 8000:8000 \
  --name portainer \
  --restart=unless-stopped \
  -v /var/run/docker.sock:/var/run/docker.sock \
  -v portainer_data:/data \
  portainer/portainer-ce:<match-your-portainer-version>
```

## Step 6: Check Portainer Server Firewall

```bash
# On the Portainer server, ensure port 8000 is open
sudo ufw allow 8000/tcp
sudo ufw status

# Test from the edge device
nc -zv portainer-server-ip 8000
```

## Step 7: Configure a Non-Default Tunnel Port

If your Edge environment must reach Portainer on a non-standard tunnel port:

```bash
# Publish the same tunnel port that Portainer listens on
docker run -d \
  -p 9000:9000 \
  -p 9443:9443 \
  -p 8001:8001 \
  --name portainer \
  -v /var/run/docker.sock:/var/run/docker.sock \
  -v portainer_data:/data \
  portainer/portainer-ce:<match-your-portainer-version> \
  --tunnel-port 8001
```

The Edge key stores both the Portainer API URL and the tunnel server address, so regenerate the key after changing the Portainer URL or tunnel port. `--tunnel-addr` only changes the local listen address on the Portainer server.

## Step 8: Debug with Verbose Logging

```bash
# Run Edge Agent with debug logging
docker stop portainer-edge-agent && docker rm portainer-edge-agent

docker run -d \
  -v /var/run/docker.sock:/var/run/docker.sock \
  -v /var/lib/docker/volumes:/var/lib/docker/volumes \
  -v /:/host \
  -v portainer_agent_data:/data \
  --restart always \
  -e EDGE=1 \
  -e EDGE_ID=<your-edge-id> \
  -e EDGE_KEY=<your-edge-key> \
  -e EDGE_INSECURE_POLL=1 \
  -e LOG_LEVEL=DEBUG \
  --name portainer-edge-agent \
  portainer/agent:<match-your-portainer-version>

# Watch logs
docker logs -f portainer-edge-agent
```

## Step 9: Fix Clock Synchronization Issues

TLS certificate validation can fail when clocks drift significantly:

```bash
# Check current time on edge device
date

# Sync with NTP
sudo timedatectl set-ntp true
sudo systemctl restart systemd-timesyncd

# Verify sync
timedatectl show | grep NTPSynchronized
```

## Step 10: Verify Edge Environment Status in Portainer

1. In Portainer, go to **Environments**
2. Find the Edge environment - check the **Last Check-in** timestamp
3. If it is not updating at roughly the configured poll frequency (5 seconds by default), the agent is not polling successfully
4. Click the environment name and review the **Edge information** details
5. Re-generate the key if needed and redeploy the agent

## Conclusion

Standard Edge Agent connection failures are most often caused by the Portainer API port (`9443` by default) or tunnel port (`8000` by default) not being accessible, an incorrect or missing `EDGE_KEY`, or the wrong server address being encoded in the agent configuration. Always verify that the edge device can reach both the Portainer API endpoint and the tunnel endpoint before debugging other factors.
