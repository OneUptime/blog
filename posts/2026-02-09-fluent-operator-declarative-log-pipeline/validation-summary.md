## Issues Found
- The manifest install commands used the development `master` setup path plus a separate operator deployment apply. Updated this to the stable release `setup.yaml` flow from the official Fluent Operator README.
- The FluentBit example used the generic `fluent/fluent-bit:2.2` image. Updated it to the operator-compatible `ghcr.io/fluent/fluent-operator/fluent-bit:5.0.6` image used by current upstream examples.
- The pipeline resources were shown without the `ClusterFluentBitConfig` selector resource needed to assemble the generated Fluent Bit configuration. Added the referenced `ClusterFluentBitConfig`.
- The Loki output used `autoKubernetesLabels: false`, but the CRD expects `"on"` or `"off"`. Changed it to `"off"`.
- The OpenSearch example used the Elasticsearch output key `es` and a deprecated mapping `type`. Changed the output key to `opensearch` and removed the type field.
- The S3 output used lower-camel fields, but the current Fluent Operator S3 CRD uses capitalized fields such as `Bucket`, `Region`, and `S3KeyFormat`. Updated the field names.
- The namespace-scoped output examples matched `kube.production.*` and `kube.development.*`, which does not match the `kube.*` tag generated by the Tail input example. Updated both matches to `kube.*`.
- The Kustomize example used deprecated `bases`, `patchesStrategicMerge`, and `commonLabels` fields. Updated it to `resources`, `patches`, and `labels`.
- The ServiceMonitor used the Fluent Bit v1 Prometheus metrics path. Updated it to `/api/v2/metrics/prometheus`.
- The buffer usage metric referenced a non-existent `fluentbit_input_mem_buf_limit` Prometheus metric. Replaced it with `fluentbit_input_storage_chunks_busy_bytes`.

## Review Notes
The namespace-scoped output examples are schema-valid after the fixes, but a production multi-tenant setup should also document the corresponding namespace `FluentBitConfig` selection strategy and filtering policy so each namespace output receives only the intended records.
