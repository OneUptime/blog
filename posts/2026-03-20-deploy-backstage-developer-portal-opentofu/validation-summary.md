## Issues Found

1. **Outdated Node base image (`node:18-bookworm-slim`).** Backstage 1.46.0+ supports only Node 22 and Node 24, and Node 18 reached end-of-life in April 2025. Updated all three Dockerfile stages to `node:22-bookworm-slim`.

2. **Incorrect health-check endpoint (`/healthcheck`).** The current Backstage backend exposes its readiness/liveness probes at `/.backstage/health/v1/readiness` and `/.backstage/health/v1/liveness` via `rootHttpRouter`. There is no `/healthcheck` route in modern Backstage. Updated the ECS `healthCheck.command` curl to hit `/.backstage/health/v1/readiness`.

3. **Invalid `APP_CONFIG_backend_auth_keys` mapping.** `backend.auth.keys` is not a single-string config — historically it took an array of `{secret: ...}` objects, and modern Backstage replaced it with `backend.auth.pluginKeyStore` (auto-generated by default) and `backend.auth.externalAccess` for static external tokens. Mapping a Secrets Manager string to `APP_CONFIG_backend_auth_keys` would not produce a valid config. Removed the `BACKEND_SECRET` entry from both the Secrets Manager `secret_string` and the ECS task definition's `secrets` array; modern Backstage auto-generates the necessary signing keys at startup, so no static secret is required for a basic deploy.

4. **Dockerfile missing Yarn 4 (Berry) configuration files.** Current Backstage scaffolds projects with Yarn 4, which requires `.yarn/` and `.yarnrc.yml` to be present in the image (and in many setups a `plugins/` folder and `backstage.json`). Without them, `yarn install` fails inside the container. Added `COPY .yarn ./.yarn`, `COPY .yarnrc.yml ./`, `COPY backstage.json ./`, and `COPY plugins plugins` to the `packages` stage; copied `.yarn` and `.yarnrc.yml` into the runtime stage; and switched `yarn install --frozen-lockfile` to `yarn install --immutable` (the Yarn 4 equivalent) and the production install step to `yarn workspaces focus --all --production` (the supported Berry equivalent of `--production`).

## Review Notes
- The `APP_CONFIG_` env-var prefix and underscore-to-dot mapping (e.g. `APP_CONFIG_backend_database_client` → `backend.database.client`) is documented and correct.
- The GitHub auth config path `auth.providers.github.development.clientId` / `clientSecret` is the documented path for the GitHub OAuth provider in Backstage.
- Backstage's default backend port `7007` is correct.
- The Secrets Manager `valueFrom` ARN-with-`:KEY::` JSON-key syntax is the documented ECS pattern for pulling individual fields out of a JSON secret.
- The "in-memory SQLite" comment in the conclusion is accurate — `@backstage/create-app` defaults to `better-sqlite3` with `connection: ':memory:'`, which is unsuitable for multi-task Fargate deployments because state is per-container and lost on restart.
- The PostgreSQL 15.4 engine version is valid but is from August 2023; AWS RDS will continue to support the 15.x major line, but a newer minor (or PostgreSQL 16.x) would be a better default in March 2026. Left as-is since it is not technically incorrect.
- Fargate task sizing of `cpu = "2048"` / `memory = "4096"` (2 vCPU / 4 GB) is a valid Fargate combination and a sensible minimum for Backstage.
- The post intentionally omits VPC/subnet/SG/IAM/ALB resources and the random_password resources; that is a scope choice, not a correctness issue.
