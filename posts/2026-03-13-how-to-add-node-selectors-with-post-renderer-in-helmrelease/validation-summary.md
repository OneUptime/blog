## Issues Found
- The introduction said Flux post-renderers can add node selectors to any workload resource generated by a Helm chart. Flux documents that Helm post-renderers are not applied to chart hooks, so this was narrowed to chart-generated workload resources except chart hooks.
- The verification command piped `kubectl -o jsonpath='{.spec.template.spec.nodeSelector}'` into `jq`. Kubernetes JSONPath output prints result objects using their string representation, so a map is not guaranteed to be valid JSON for `jq`. The command was changed to `kubectl get deployment my-app -n production -o json | jq '.spec.template.spec.nodeSelector'`.

## Review Notes
- The HelmRelease examples use the current `helm.toolkit.fluxcd.io/v2` API and the current `.spec.postRenderers.kustomize.patches` field.
- The Kustomize patch examples are valid strategic merge patches. When a `target` is specified, Kustomize still requires `metadata.name` in inline strategic merge patches, but does not use that name for target selection.
- Kustomize patch target `name` values are regular expressions, so component selectors such as `.*grafana.*` are valid.
- The Kubernetes scheduling claims about `nodeSelector`, tolerations, and node labels are consistent with the official Kubernetes scheduling documentation.
