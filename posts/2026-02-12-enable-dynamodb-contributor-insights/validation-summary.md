## Issues Found
- The post implied that DynamoDB always creates four Contributor Insights rules. Updated the explanation to say the partition-key-plus-sort-key rules are created only for tables or indexes that have a sort key.
- The CDK snippet used `contributorInsightsEnabled`, which is now deprecated in AWS CDK v2. Replaced it with `contributorInsightsSpecification: { enabled: true }`.
- The Python examples used `datetime.utcnow()`, deprecated in Python 3.12. Replaced it with timezone-aware `datetime.now(timezone.utc)`.
- The CloudWatch alarm example used `aws cloudwatch put-managed-insight-rule`, which is not a valid singular AWS CLI command and would not create an alarm. Replaced it with `aws cloudwatch put-metric-alarm` using `INSIGHT_RULE_METRIC(..., "MaxContributorValue")`.
- The pricing section said Contributor Insights costs about `$0.02 per 100,000` DynamoDB events, but CloudWatch pricing examples show `$0.02 per million` matched events in US East. Corrected the unit and clarified the 1000 requests-per-second estimate.
- The limitations section said data retention is 14 days. Updated it to match CloudWatch's documented report window: a 24-hour window up to 15 days ago.

## Review Notes
- The AWS CLI `update-contributor-insights` and `describe-contributor-insights` commands are valid for DynamoDB tables and global secondary indexes.
- The CloudFormation `ContributorInsightsSpecification` snippet is valid for a DynamoDB table.
- CloudWatch Contributor Insights pricing varies by Region, and DynamoDB billing differs between accessed-and-throttled mode and throttled-keys-only mode.
