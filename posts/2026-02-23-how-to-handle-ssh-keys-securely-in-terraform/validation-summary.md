## Issues Found
- **`terraform taint` is deprecated.** The original post recommended `terraform taint tls_private_key.ssh` followed by `terraform apply` to force key rotation. The `taint` command was deprecated in Terraform 0.15.2 (May 2021); the recommended replacement is `terraform apply -replace="ADDRESS"`, which surfaces the replacement in the plan output before applying. Updated the "Key Rotation" section to use `terraform apply -replace="tls_private_key.ssh"` and added a brief note that `taint` is deprecated.

## Review Notes
- **S3 backend locking:** The post uses `dynamodb_table` for state locking in the S3 backend. This still works, but Terraform 1.10 (November 2024) introduced native S3 locking via `use_lockfile = true`, and `dynamodb_table` is now slated for removal in a future minor version. Not factually wrong, but readers running Terraform ≥ 1.10 may prefer the native lockfile approach.
- **`tls_private_key` OpenSSH attributes:** `private_key_openssh` and `public_key_openssh` are valid for the algorithms used in the post (ED25519). They are not available for ECDSA with curve P224, but that's not relevant here.
- **Vault role attributes:** `ttl` and `max_ttl` are correctly specified as strings (`"30m"`, `"4h"`). `default_extensions` is correctly given as a map with `permit-pty = ""`.
- **SSM Session Manager:** All resource definitions, IAM policy ARN, and CLI invocations (`aws ssm start-session --target ...` and the `AWS-StartSSHSession` document in `ProxyCommand`) match current AWS documentation.
- **Security claim accuracy:** The statement that private keys generated by the `tls_private_key` resource end up in the Terraform state file in plain text is accurate — Terraform does not encrypt sensitive attributes at rest in the state file.
