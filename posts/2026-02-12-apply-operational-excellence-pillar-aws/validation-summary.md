## Issues Found
- The post described the Operational Excellence pillar as having five areas and treated "everything as code" as one of those areas. The current AWS Well-Architected documentation presents four best-practice areas: organization, preparation, operation, and evolution. I updated that description and kept operations as code as a supporting practice.
- The post listed five Operational Excellence design principles from older guidance. The current AWS documentation lists eight design principles, including organizing teams around business outcomes, observability, safe automation, and managed services. I updated the count and list.
- The EventBridge example said it remediated failed health checks, but the event pattern matched EC2 instance state-change notifications for `stopping` and `stopped`. I updated the comment, rule name, and Terraform references so the example accurately describes stopped-state remediation.

## Review Notes
- The CodePipeline ECS deployment snippet is structurally valid, but a real ECS standard deployment action also needs an `imagedefinitions.json` file in the input artifact, either committed in the source artifact or generated by a build step.
- AWS X-Ray remains valid for tracing examples, but AWS has placed the X-Ray SDKs and daemon in maintenance mode as of February 25, 2026 and recommends OpenTelemetry-based instrumentation for new application instrumentation.
