## Issues Found
- The Portainer install command was pinned to the old `ce2-19` manifest path. I updated it to the current `ce-lts` manifest path from Portainer's Kubernetes install documentation.
- The k3s setup snippet did not configure readable kubeconfig access for non-root use and relied on `sudo cat` instead. I updated it to install with `K3S_KUBECONFIG_MODE="644"` and export `KUBECONFIG` so the subsequent `kubectl` commands work as written.
- Several Portainer UI navigation labels were outdated (`Workloads`, `Manifests`, and `Configuration`). I updated them to the current `Applications`, `Create from code > Manifest`, and `ConfigMaps & Secrets` labels from the Portainer docs.
- The training progress script could overcount empty resource lists because `kubectl get ... --no-headers` can still emit a `No resources found` line. I updated the counters to use `-o name` and a precise filter for the autogenerated `kube-root-ca.crt` ConfigMap.
- The `envFrom` example used a placeholder image reference (`myapp:latest`). I replaced it with `nginx:alpine` so the snippet is runnable when embedded in a complete Deployment spec.

## Review Notes
- `storageClassName: local-path` remains correct for the default k3s local-path provisioner.
- The example `nginx:1.25-alpine` and `nginx:1.26-alpine` tags are older but still valid example image tags; they may be worth refreshing in a future content pass if the team wants version examples to track newer nginx releases.
