## Issues Found
- The initial installation command omitted `express` and `jsonwebtoken`, even though the examples require Express and use `jwt.sign()`. Updated the command to install both packages.
- The JWT section installation command installed only `passport-jwt`, but the following login example also uses `jsonwebtoken`. Updated the command to include `jsonwebtoken`.
- The JWT strategy configured `issuer` and `audience`, but the token generation example did not set matching claims. Added `issuer` and `audience` to the `jwt.sign()` options so tokens generated by the example pass the configured verifier checks.
- The account-linking routes used `passport.authorize('google')` while the authorization strategy was registered as `google-authz`. Updated both linking routes to use `passport.authorize('google-authz')`, matching Passport's named-strategy pattern for delegated authorization.
- The Redis session store example used the older `connect-redis` default import and `ioredis`. Current `connect-redis` uses a named `RedisStore` export and v9 no longer supports `ioredis`. Updated the install command and example to use the `redis` package with `createClient()`.

## Review Notes
- The code examples are intentionally simplified and assume a `User` model, environment secrets, body parsing, and provider app configuration exist where needed.
- For production deployments behind a reverse proxy, secure cookies generally also require correct Express `trust proxy` configuration.
- Cookie-based JWT extraction requires cookie parsing middleware to populate `req.cookies`; the snippet is syntactically safe because it uses optional chaining, but a real app must configure cookie parsing for that extractor to return a cookie value.
