# How to Use Omni SaaS for Talos Cluster Management

Author: [nawazdhandala](https://github.com/nawazdhandala)

Tags: Talos Linux, Sidero Omni, SaaS, Cluster Management, Kubernetes

Description: A complete guide to using Sidero Omni SaaS for managing Talos Linux clusters including setup, cluster operations, and day-two management

---

Sidero Omni SaaS is a hosted management platform for Talos Linux infrastructure. Instead of running your own management tools, you connect your Talos nodes to Omni's cloud service and manage everything through its web interface and CLI. This removes the operational burden of maintaining a management plane while giving you full control over your Talos clusters.

This guide covers how to get started with Omni SaaS, create and manage clusters, and handle day-to-day operations.

## Getting Started with Omni SaaS

Setting up Omni SaaS takes just a few minutes:

```bash
# Step 1: Sign up at https://omni.siderolabs.com

# You will receive an account and a unique Omni endpoint

# Step 2: Install the Omni CLI tools
brew install siderolabs/tap/sidero-tools

# Step 3: Configure omnictl with the omniconfig.yaml file from the Omni UI
omnictl config merge ./omniconfig.yaml

# Step 4: Verify your connection and authenticate in the browser if prompted
omnictl get clusters
omnictl get machines
```

Your Omni SaaS endpoint is your central management point. All nodes you connect will report to this endpoint through SideroLink WireGuard tunnels.

## Registering Machines

Before you can create clusters, you need to register Talos machines with Omni. There are several ways to do this:

### Download an Omni-Enabled Image

The simplest approach is to boot machines with an image generated by Omni:

```bash
# Download ISO for bare metal
omnictl download iso --output talos-omni.iso

# Download for cloud or virtualization platforms
omnictl download aws --output talos-omni-aws.raw
omnictl download vmware --output talos-omni-vmware.raw
```

Machines booted with this image automatically establish a SideroLink connection to your Omni account and appear in the Machines list.

### Register Existing Talos Nodes

For nodes already running Talos Linux, add the SideroLink connection:

```bash
# Get a partial machine configuration that joins the node to Omni
omnictl jointoken machine-config > join-config.yaml

# Apply the join configuration to an existing node
talosctl patch machineconfig --nodes 10.0.0.1 \
  --patch @join-config.yaml
```

### Local Machine Registration for Testing

For testing, you can create local QEMU-based Talos machines that connect to Omni:

```bash
# Create local machines that connect to Omni
talosctl cluster create qemu \
  --omni-api-endpoint https://your-account.omni.siderolabs.com
```

## Creating Clusters Through the Web UI

The Omni web UI provides a visual interface for cluster creation:

1. Navigate to Clusters in the sidebar
2. Click "Create Cluster"
3. Select machines for control plane nodes (minimum 1, recommended 3)
4. Select machines for worker nodes
5. Configure cluster settings (Talos version, Kubernetes version, optional features, etc.)
6. Click Create

The UI shows real-time progress as Omni bootstraps the cluster, installs components, and brings nodes online.

## Creating Clusters Through the CLI

For automation, define a cluster template and apply it with omnictl:

```yaml
# cluster.yaml
kind: Cluster
name: production-cluster
kubernetes:
  version: v1.34.1
talos:
  version: v1.11.3
---
kind: ControlPlane
machines:
  - machine-id-1
  - machine-id-2
  - machine-id-3
---
kind: Workers
machines:
  - machine-id-4
  - machine-id-5
```

```bash
# Validate and create the cluster
omnictl cluster template validate -f cluster.yaml
omnictl cluster template sync -f cluster.yaml --verbose
omnictl cluster template status -f cluster.yaml
```

## Using Cluster Templates

For repeatable cluster deployments, use cluster templates:

```yaml
# cluster-template.yaml
kind: Cluster
name: production-cluster
kubernetes:
  version: v1.34.1
talos:
  version: v1.11.3
---
kind: ControlPlane
machineClass:
  name: control-plane
  size: 3
patches:
  - name: custom-sysctls
    inline:
      machine:
        sysctls:
          vm.max_map_count: "262144"
          net.core.somaxconn: "65535"
---
kind: Workers
machineClass:
  name: worker
  size: 5
patches:
  - name: worker-sysctls
    inline:
      machine:
        sysctls:
          vm.max_map_count: "262144"
          net.core.somaxconn: "65535"
```

```bash
# Apply the template
omnictl cluster template validate -f cluster-template.yaml
omnictl cluster template sync -f cluster-template.yaml

# Check cluster status from the template
omnictl cluster template status -f cluster-template.yaml
```

## Managing Cluster Configuration

Omni allows you to apply configuration patches to clusters and individual machines through the UI or cluster templates:

```yaml
# Add this patch to a Workers document in cluster-template.yaml
kind: Workers
machineClass:
  name: worker
  size: 5
patches:
  - name: worker-tuning
    inline:
      machine:
        sysctls:
          net.core.somaxconn: "65535"
          vm.max_map_count: "262144"
        kubelet:
          extraConfig:
            maxPods: 200
            serializeImagePulls: false
```

```bash
# Validate and apply the updated template
omnictl cluster template validate -f cluster-template.yaml
omnictl cluster template sync -f cluster-template.yaml
```

Configuration patches are tracked as Omni resources, so you can review changes and roll back by applying a previous template revision.

## Upgrading Clusters

Rolling upgrades are one of Omni's strongest features. Omni handles the complexities of upgrading Talos Linux and Kubernetes versions across your cluster. For clusters managed by templates, update the versions in the `Cluster` document and sync the template:

```yaml
kind: Cluster
name: production-cluster
kubernetes:
  version: v1.34.2
talos:
  version: v1.11.4
---
kind: ControlPlane
# existing control plane definition
---
kind: Workers
# existing worker definition
```

```bash
# Apply the version change and check upgrade status
omnictl cluster template sync -f cluster-template.yaml
omnictl cluster status production-cluster
```

Omni performs Talos upgrades in a rolling fashion:
1. Drain and cordon a node
2. Upgrade Talos Linux on the node
3. Wait for the node to rejoin the cluster
4. Uncordon the node and move to the next node

Control plane nodes are upgraded one at a time to maintain etcd quorum. Worker upgrade parallelism is configurable in the `upgradeStrategy` for the worker machine set.

## Accessing Clusters

Get kubeconfig files for your clusters directly from Omni:

```bash
# Download kubeconfig for a cluster
omnictl kubeconfig --cluster production-cluster ./kubeconfig.yaml

# Use kubectl with the downloaded kubeconfig
kubectl --kubeconfig kubeconfig.yaml get nodes
kubectl --kubeconfig kubeconfig.yaml get pods -A

# You can also generate a kubeconfig for a Kubernetes service account
omnictl kubeconfig --cluster production-cluster \
  --service-account \
  --user ci-bot \
  ./service-account-kubeconfig.yaml
```

## Monitoring and Observability

Omni provides built-in status views for your clusters:

```bash
# View cluster status
omnictl cluster status production-cluster

# View machine health
omnictl get machines -o table

# View cluster resources
omnictl get clusters production-cluster -o yaml

# Download a Talos config for direct Talos operations
omnictl talosconfig --cluster production-cluster ./talosconfig

# View logs from a specific machine
omnictl machine-logs machine-id --tail 100
```

The web UI provides dashboards showing:
- Node health
- Kubernetes cluster status
- Recent events and alerts
- Configuration and upgrade status

## Machine Lifecycle Management

Manage the lifecycle of machines through Omni:

```bash
# Remove a machine from a template-managed cluster:
# delete the machine ID from the ControlPlane or Workers document, then sync.
omnictl cluster template sync -f cluster-template.yaml

# Lock or unlock a worker machine during rollout operations
omnictl cluster machine lock machine-id
omnictl cluster machine unlock machine-id

# View machine labels
omnictl get machinelabels machine-id -o yaml
```

When a reachable machine is removed from a cluster through Omni, Omni resets its Talos state partition and returns it to maintenance mode. If the machine is unreachable, Omni may remove its record without resetting the node, and you will need to reset it outside of Omni before reuse.

## Access Control

Omni provides role-based access control for team management:

```bash
# Invite a team member
omnictl user create user@example.com --role Admin

# Change a user's role
omnictl user set-role user@example.com --role Operator

# List users
omnictl user list

# Remove a user
omnictl user delete user@example.com
```

## Scaling Clusters

Add or remove nodes from existing clusters:

```bash
# Increase worker capacity by changing the worker machineClass size
# in cluster-template.yaml, then sync:
omnictl cluster template sync -f cluster-template.yaml

# Remove specific machines by removing their IDs from the template, then sync:
omnictl cluster template sync -f cluster-template.yaml
```

## Backup and Disaster Recovery

Omni can create and manage etcd backups for clusters:

```bash
# Create a manual backup request
cat <<EOF > etcd-manual-backup.yaml
metadata:
  namespace: ephemeral
  type: EtcdManualBackups.omni.sidero.dev
  id: production-cluster
spec:
  backupat:
    seconds: $(date +%s)
    nanos: 0
EOF

# Trigger a manual etcd backup
omnictl apply -f etcd-manual-backup.yaml

# Check backup status
omnictl get etcdbackupstatus production-cluster -o yaml

# Export cluster configuration
omnictl cluster template export --cluster production-cluster \
  --output cluster-backup.yaml

# The cluster template includes cluster settings, patches, and machine assignments
# Use it to recreate or manage the cluster if needed
```

## Conclusion

Sidero Omni SaaS provides a production-ready management platform for Talos Linux without the operational overhead of self-hosting management tools. From initial machine registration through cluster creation, day-to-day operations, and rolling upgrades, everything is handled through a single interface. The SideroLink VPN ensures secure connectivity regardless of where your machines are located, and the role-based access control makes it suitable for team environments. Start with a few nodes to evaluate, and scale up as your confidence grows.
