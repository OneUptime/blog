## Issues Found
- The post described `dependsOn` as providing "higher priority." Flux `dependsOn` expresses a readiness dependency between Kustomization resources, not a priority system. Changed the wording to say that dependent Kustomizations wait for the ConfigMap Kustomization.
- The three-level nesting diagram used "inherits," which could imply implicit variable inheritance even though the post correctly states there is no implicit inheritance. Changed this wording to "receives" to reflect explicit variable passing.
- The debugging commands used `flux get kustomization`. The documented Flux CLI command for Kustomization status is `flux get kustomizations`. Updated both examples.

## Review Notes
The core substitution behavior is accurate: `.spec.postBuild.substitute` and `.spec.postBuild.substituteFrom` apply to the manifest generated by the individual Kustomization, and each Flux Kustomization has its own `postBuild` configuration. The shared ConfigMap examples are valid as written because the Kustomizations and ConfigMap are in `flux-system`; in other namespaces, `substituteFrom` references should point to a ConfigMap or Secret in the same namespace as the referring Kustomization.
