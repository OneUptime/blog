## Issues Found
- The broker-info extraction command incorrectly redirected `subctl show connections` output into `broker-info.subm`. Updated it to use the `broker-info.subm` generated by `subctl deploy-broker`.
- The join examples used unsupported or incorrect Globalnet flag names (`--enable-globalnet=false` and `--enable-globalnet`). Replaced them with the current `--globalnet=false` and `--globalnet` flags.
- The WireGuard join examples used IPsec NAT traversal flags. Removed those from WireGuard examples and kept NAT traversal under Libreswan IPsec using the documented `--nattport` spelling.
- Service export examples used the old `submariner.io/export=true` service label. Replaced them with `subctl export service` or explicit `ServiceExport` resources.
- The NetworkPolicy federation section described a non-existent `submarine.io/v1alpha1` NetworkPolicy API with `clusterSelector`. Replaced it with a standard `networking.k8s.io/v1` NetworkPolicy using `ipBlock`, matching Submariner's documented NetworkPolicy caveats.
- The gateway examples used unsupported `--gateway-count` join flags and a user-created `Gateway` resource with invalid fields. Replaced them with gateway node labels, gateway status inspection, and monitoring notes.
- The multi-region Deployment manifest was missing the required `apps/v1` selector and pod labels, and the service was no longer exported after removing the invalid label. Added a valid selector/template label pair and a `ServiceExport`.
- The port description incorrectly mapped WireGuard to UDP/4800. Updated it to the documented Submariner ports: UDP/4500 dataplane, UDP/4490 NAT discovery, and UDP/4800 intra-cluster VXLAN path.
- The Lighthouse verification command used a label selector that is not documented as stable. Replaced it with a namespace-wide component listing.
- The WireGuard performance claim gave an unsupported exact CPU-overhead percentage. Reworded it as qualitative guidance to benchmark in the target environment.

## Review Notes
The post is now technically aligned with current Submariner documentation. Some deployment details remain environment-specific, especially gateway node reachability, CNI behavior, cloud load balancer use, and whether Globalnet is appropriate for a given cluster set.
