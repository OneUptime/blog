## Issues Found

1. **Incorrect authentication flow description**: The post stated that clients send credentials via "HTTP Basic Auth in the Authorization header." This is wrong. Ceph RGW LDAP auth for S3 uses tokens generated by `radosgw-token --encode --ttype=ldap`. The token is used as the S3 access key with an empty secret key. Fixed the flow to accurately describe the token-based process.

2. **`rgw_ldap_dnattr` mislabeled as "Search filter"**: The inline comment described `rgw_ldap_dnattr` as a "Search filter (restrict which users can log in)." It is actually the DN attribute name used to construct the search filter (e.g., `uid` or `cn`), not a filter itself. Fixed the comment.

3. **Non-existent `rgw_ldap_token_expire` config option**: The post included `rgw_ldap_token_expire` as a configuration parameter. This option does not exist in Ceph's documented configuration. Replaced with `rgw_s3_auth_use_ldap = true`, which is the actual config option needed to enable LDAP auth for S3.

4. **Invalid `rgw_enable_apis` value "ldap"**: The post instructed readers to add "ldap" to `rgw_enable_apis`. "ldap" is not a valid API — the valid values are s3, s3website, swift, swift_auth, admin, sts, iam, notifications. LDAP authentication is enabled via `rgw_s3_auth_use_ldap`, not through `rgw_enable_apis`. Replaced the entire section with instructions for generating LDAP tokens using `radosgw-token`.

5. **Test command used Swift auth, labeled as S3**: The curl command tested the Swift auth endpoint (`/auth/1.0` with `X-Auth-User`/`X-Auth-Key` headers) but was labeled as "Test LDAP login via the S3 API." Replaced with a correct S3 test using `radosgw-token` and the AWS CLI.

6. **ConfigMap override included non-existent option**: The `rook-config-override` ConfigMap included `rgw_ldap_token_expire`. Replaced with `rgw_s3_auth_use_ldap = true`.

## Review Notes
- The Rook integration section creates a Kubernetes Secret for the LDAP password but does not show how to mount it as a volume into the RGW pods. In practice, users would need to configure volume mounts so that `/etc/ceph/ldap.secret` is available inside the container. This is a completeness gap rather than a technical error.
- The post does not mention `rgw_ldap_searchfilter`, which allows more advanced LDAP search filtering beyond the basic `rgw_ldap_dnattr` approach. This could be a useful addition for complex LDAP setups.
