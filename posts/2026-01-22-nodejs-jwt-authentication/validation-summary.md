## Issues Found
- The installation command omitted `cookie-parser` and `ioredis`, even though later examples require both packages. Updated the command to install those dependencies.
- The role-based authorization example checked `req.user.role`, but the access token generated by the complete auth example did not include a role claim. Added a default `role: 'user'` to created users and included `role` in the access token payload.
- The Redis blacklist example used `redis.setex()`. Redis documents `SETEX` as deprecated since Redis 2.6.12 and recommends `SET` with the `EX` option for new code. Updated the example to use `redis.set(key, value, 'EX', ttl)`, which is supported by ioredis.
- The token payload best-practices example manually set `iat: Date.now()`. RFC 7519 requires `iat` to be a NumericDate value in seconds, while `Date.now()` returns milliseconds; jsonwebtoken also adds `iat` automatically unless disabled. Removed the manual `iat` claim.
- The token payload best-practices code block declared `const token` twice in the same scope. Renamed the intentionally bad example variable to `badToken` so the block remains syntactically valid JavaScript.

## Review Notes
- The examples are suitable for a tutorial, but the mock in-memory user and refresh-token stores are not production persistence mechanisms.
- The examples assume `JWT_SECRET` and `REFRESH_SECRET` are configured in the environment; the later strong-secret section correctly shows failing fast when a secret is missing.
