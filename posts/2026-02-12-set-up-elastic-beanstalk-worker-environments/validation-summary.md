## Issues Found
- The `eb create` example used `--instance-type`, but the EB CLI documents `--instance_type` for specifying a single On-Demand instance type. Updated the command to use `--instance_type`.
- The `eb create` example used `--platform python-3.11`, which is less consistent with the EB CLI's documented platform branch examples. Updated it to `--platform "Python 3.11"`.
- The queue URL lookup used `eb printenv worker-env | grep SQS`, but the worker queue URL is an Elastic Beanstalk `aws:elasticbeanstalk:sqsd` option, not a guaranteed application environment variable. Replaced it with an AWS CLI `describe-configuration-settings` query for `WorkerQueueURL`.
- The SQS daemon configuration comment described `RetentionPeriod` as the retry count before DLQ. Corrected the comment and added `MaxRetries: 3`, which is the documented sqsd option for retry count before a configured DLQ.
- The architecture diagram showed failed messages going directly to the DLQ. Updated it to show retry behavior first, with DLQ routing only after the configured retry policy.
- The DLQ section implied Elastic Beanstalk always creates the dead-letter queue automatically. Updated it to distinguish autogenerated worker queues, where DLQ is enabled by default, from existing SQS queues, where DLQ must be configured in SQS.
- The scaling section claimed Elastic Beanstalk worker environments scale directly based on SQS queue depth using `aws:autoscaling:trigger` and `ApproximateNumberOfMessagesVisible`. The documented built-in trigger metrics for that namespace do not include SQS queue metrics. Replaced the snippet with a CPU-based EB trigger and noted that queue-depth-based scaling requires a CloudWatch alarm or scaling policy using SQS metrics.
