## Issues Found
- The `nftables` example activated a global limit rule and a per-source meter in the same live chain. That changes the stated behavior because the meter can continue accepting packets after the global limit is exceeded. I kept the global rule active and converted the per-source meter into an alternative rule to use instead.
- The `nftables` example used `policy drop` in an ICMP-focused `/etc/nftables.conf` snippet, which would drop unrelated inbound traffic if copied as-is. I changed it to `policy accept` so the snippet stays focused on ICMP rate limiting.
- The `net.ipv4.icmp_ratelimit` explanation said the default value `1000` meant `100ms`. Kernel documentation defines the value in milliseconds, so the default is `1000ms` (1 second). I corrected that and clarified that these sysctls rate-limit outbound ICMP generated by the kernel, not inbound echo requests.
- The monitoring section implied that comparing `InEchos` and `OutEchoReps` proves firewall rate limiting. `/proc/net/snmp` exposes stack-level ICMP counters, not direct firewall-drop counters. I replaced that guidance with `OutRateLimitGlobal` / `OutRateLimitHost` for kernel ICMP rate limiting and kept firewall rule counters as the confirmation method for dropped echo requests.
- The `nstat` note referenced `-a`, but the example command used `-z`. I made the comment and command consistent with `nstat -az`.

## Review Notes
- The `iptables` commands are syntactically correct per `iptables-extensions(8)` and local CLI help. Rule order still matters on a live firewall: if broader ICMP `ACCEPT` rules already exist earlier in the chain, these example rules must be inserted before them.
- `ping -f` is an appropriate test command for flood traffic, but it is a privileged mode on Linux in practice. The post now notes that it requires root.
