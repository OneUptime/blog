## Issues Found

1. **`cilium policy trace` no longer exists.** Step 4 instructed readers to run `cilium policy trace --src-k8s-pod ... --dst-k8s-pod ...`, but this subcommand was removed from the in-agent CLI. The current `cilium-dbg policy` only exposes `get` (deprecated), `selectors`, `subject-selectors`, and `wait`. Rewrote Step 4 to use the modern equivalents — `cilium-dbg policy selectors`, `cilium-dbg identity list`, and `cilium-dbg identity get` — which let you inspect which identities a policy applies to, and noted that real-time verdict checking is now done via Hubble (Step 3). Kept the section heading and step numbering to avoid restructuring.

2. **In-agent CLI renamed `cilium` → `cilium-dbg` in Cilium 1.15.** Steps 2, 5, and 6 invoked `cilium endpoint list`, `cilium endpoint get`, `cilium policy get`, and `cilium monitor` inside the cilium agent pod via `kubectl exec`. The in-pod binary has been renamed to `cilium-dbg` since Cilium 1.15 (released Jan 2024), so the old commands fail on any current cluster. Updated all in-pod invocations to `cilium-dbg ...` and added a one-line note in Step 2 explaining the rename. The standalone `cilium` CLI commands (`cilium status`, `cilium connectivity test`, `cilium hubble enable`, `cilium hubble port-forward`) are unchanged because the standalone CLI was not renamed.

3. **Wrong Hubble IP filter flag.** Step 3 used `hubble observe --ip-src 10.244.1.5`. Verified against the Hubble flow filter source (`hubble/cmd/observe/flows_filter.go`): the supported flags are `--from-ip`, `--to-ip`, and `--ip` (not `--ip-src`/`--ip-dst`). Changed to `--from-ip 10.244.1.5`.

## Review Notes
- Verified `--verdict DROPPED` is valid; the Verdict enum supports `VERDICT_UNKNOWN`, `FORWARDED`, `DROPPED`, `ERROR`, `AUDIT`, `REDIRECTED`, `TRACED`, `TRANSLATED`.
- Verified `kubectl get pods -n kube-system -l name=cilium-operator` works because the upstream Helm chart sets both `name=cilium-operator` and `io.cilium/app=operator` on operator pods. Either selector is valid; left as-is.
- `cilium-dbg policy get` is marked **deprecated** in the upstream cmdref but still functions. Worth flagging for a future revision but no replacement is documented for the use cases in Steps 2 and 5, so it was left in place.
- Step 1's `cilium status` and `cilium connectivity test` are correct standalone-CLI commands.
- The post's lead-in/Description still mentions "policy trace commands"; not strictly accurate after the Step 4 rewrite, but kept as a high-level descriptor since the post still covers policy-related diagnostics.
