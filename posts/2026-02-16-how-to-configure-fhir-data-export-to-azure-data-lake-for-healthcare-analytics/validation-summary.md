## Issues Found
- The post used `az healthcareapis fhir-service`, but current Azure Health Data Services FHIR service commands are under `az healthcareapis workspace fhir-service`. Updated the managed identity lookup command and added an explicit managed identity enablement command.
- The post configured export with a non-documented CLI flag, `--export-storage-account-name`, on an update command. Replaced it with an `az resource update` that sets `properties.exportConfiguration.storageAccountName`, matching the ARM resource schema.
- The export examples created a `fhir-export` container but did not pass `_container` to `$export`, so Azure would create an autogenerated container instead. Added `_container` to the full, filtered, incremental, and scheduled export examples.
- The output examples and Synapse queries assumed fixed files such as `Patient.ndjson`. Azure FHIR export writes each job into a new folder and can create multiple files per resource type with generated names. Updated output URLs and Synapse `OPENROWSET` paths to use job-folder and filename wildcards.
- The access token example referenced `APP_ID` and `CLIENT_SECRET` without defining them. Added placeholder assignments for those variables.
- The storage container creation command assumed key-based authorization. Added `--auth-mode login` to align with Microsoft Entra authorization and RBAC-based setup.
- The de-identification section described a `$de-identify` operation and used an undocumented `X-MS-FHIR-De-identify` header. Replaced it with the documented de-identified `$export` query parameters using `_anonymizationConfig`.
- The prerequisites did not explicitly mention the FHIR Data Exporter role required to start exports. Added that role requirement.

## Review Notes
The Logic Apps snippet is illustrative rather than a complete workflow because the referenced `getToken` action is not included. That is acceptable for the post's scope, but a production-ready version should include the token acquisition action and polling loop.
