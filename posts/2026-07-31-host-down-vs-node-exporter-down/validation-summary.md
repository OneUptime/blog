## Issues Found

- The Blackbox Exporter scrape example used the `icmp` module without stating that the module must be configured and that the exporter needs operating-system permission to send ICMP probes. Added those prerequisites immediately before the example.
- The simultaneous Node Exporter scrape failure and failed host probe were described as proving that the host was unreachable by both methods. A failed scrape can also result from HTTP, authentication, parsing, or limit errors, so the wording now states only that both observations failed from the monitoring location.
- The Alertmanager inhibition recommendation could be read as applying to the two example alerts, even though those alerts require mutually exclusive `probe_success` values. Scoped the recommendation to an additional generic Node Exporter scrape-failure alert and made the non-overlap explicit.
- The advice to monitor each prober's "own `up` series" was ambiguous because `up` is generated by Prometheus for a scrape target. Clarified that each Blackbox Exporter's `/metrics` endpoint should be scraped and that the resulting target `up` series should be monitored.

## Review Notes

- Both YAML examples are syntactically valid and follow the current Prometheus scrape and alerting-rule schemas.
- The PromQL comparisons, logical/set operators, `on (host)` matching, and `unless` membership check are valid with current PromQL semantics.
- Prometheus currently documents `body_size_limit` as experimental; the post only identifies it as a possible scrape-failure cause and does not depend on its stability.
- `expected_node_target` is intentionally an illustrative metric that must be supplied by an independent inventory system.
