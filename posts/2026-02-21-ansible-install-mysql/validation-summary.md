## Issues Found
- The role structure omitted the `templates/root-my.cnf.j2` file that the secure task uses. Added the `templates/` directory and template file to the structure.
- The MySQL APT repository package version was stale. Updated it from `0.8.29-1` to the current `0.8.39-1` release package and moved the value into `mysql_apt_config_version`.
- The Debian/Ubuntu flow did not explicitly select the MySQL 8.0 repository series, so a noninteractive install could use the current default series instead of the article's stated MySQL 8.0 target. Added `mysql_apt_repo_series` and an Ansible `debconf` task for `mysql-apt-config/select-server`.
- The RHEL/Rocky repository RPM URL used an obsolete `mysql80-community-release` filename pattern. Replaced it with current MySQL 8.4 repository setup RPM URLs for EL8 and EL9, then explicitly disabled the 8.4 repo and enabled `mysql80-community` when `mysql_version` is `8.0`.
- The RHEL/Rocky tasks used `dnf config-manager` without installing the package that provides it. Added `dnf-plugins-core` to prerequisites.
- The built-in MySQL module disable step applies to EL8-based systems in the official MySQL Yum instructions. Added a condition limiting it to major version 8.
- The RHEL/Rocky socket path differed from the Debian default. Added a RHEL-specific `mysql_socket` fact using `/var/lib/mysql/mysql.sock`.
- The root password task ignored errors and did not handle the temporary root password generated by MySQL RPM installations. Replaced it with a Debian/socket-auth path using `check_implicit_admin` and a RHEL temporary-password path using `mysqladmin --connect-expired-password`.
- The `.my.cnf` description called the access "passwordless" even though it stores credentials in a protected file. Reworded it to say the CLI can be used without typing the password each time.
- The Mermaid installation flow listed `.my.cnf` creation after the hardening tasks, while the task file creates it before those tasks. Updated the diagram order.
- The example role invocation set `mysql_bind_address`, but the role snippets do not include configuration-management tasks that consume that variable. Removed the unused override from the example.

## Review Notes
- The role now reflects the official repository setup paths for MySQL 8.0 on current Debian/Ubuntu and EL8/EL9 systems. Future updates may be needed when Oracle publishes newer MySQL repository setup RPM revisions or changes supported distro versions.
- The `disable_gpg_check: true` setting still bypasses RPM package signature checking for the repository setup RPM. It works as written, but production roles should verify repository package integrity and GPG signatures.
