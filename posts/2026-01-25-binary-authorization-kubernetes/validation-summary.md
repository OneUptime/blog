## Issues Found
- Removed the obsolete `COSIGN_EXPERIMENTAL=1` requirement from the keyless signing example and added `--yes` for non-interactive signing.
- Updated the GitHub Actions Cosign installer to `sigstore/cosign-installer@v4.0.0` and Docker build action to `docker/build-push-action@v6`, matching current official examples.
- Fixed keyless verification identity regular expressions. The original `https://github.com/.../*` regex would not match GitHub Actions workflow certificate subjects as intended.
- Corrected custom attestation creation. The original examples passed full in-toto statements to `cosign attest --predicate`; Cosign expects a predicate file unless `--statement` is used.
- Added `--yes` to `cosign attest` commands for CI-friendly keyless attestation creation.
- Corrected the custom attestation type from `custom` to the URI used by the policy, so `verify-attestation` and Policy Controller predicate matching align.
- Adjusted the SLSA provenance predicate example to use `slsaprovenance02` and to avoid claiming complete parameters/environment data that the example does not include.
- Fixed Policy Controller Helm values. The chart uses `webhook.replicaCount`, `webhook.namespaceSelector`, and `webhook.configData.no-match-policy`, not the top-level fields shown originally.
- Fixed the exception policy. `mode: allow` is not a valid permissive mode for `ClusterImagePolicy`; static allow policies use `authorities[].static.action: pass`.
- Replaced unverified Policy Controller metric names with documented Kubernetes API server admission webhook metrics for rejections and webhook call failures.
- Clarified that attestations are signed statements rather than signatures themselves.

## Review Notes
The examples are now technically aligned with current Sigstore and Kubernetes documentation. The provenance snippet is still illustrative; production pipelines should prefer provenance generated by the build system, such as BuildKit/GitHub Actions provenance, rather than hand-written provenance JSON.
