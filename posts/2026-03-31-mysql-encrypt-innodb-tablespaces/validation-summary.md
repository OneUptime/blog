## Issues Found

1. **Misleading key rotation example (removed)**
   - **What was wrong:** The post included `ALTER TABLE orders ENCRYPTION='Y'` with the comment "Re-encrypt a specific table with a new key." Running this on an already-encrypted table is not a documented key rotation method. The tablespace key is not regenerated by re-applying the same `ENCRYPTION='Y'` setting.
   - **What was changed:** Removed the misleading `ALTER TABLE` line, keeping only `ALTER INSTANCE ROTATE INNODB MASTER KEY` which is the correct and documented master key rotation method.
   - **Why:** The MySQL documentation specifies `ALTER INSTANCE ROTATE INNODB MASTER KEY` as the key rotation mechanism. It rotates the master key and re-encrypts all tablespace keys with the new master key.

2. **Incorrect comment about decrypting general tablespaces**
   - **What was wrong:** The comment on `ALTER TABLESPACE secure_ts ENCRYPTION='N'` said "all tables must be moved out first," which is incorrect.
   - **What was changed:** Removed the inaccurate parenthetical. `ALTER TABLESPACE ... ENCRYPTION='N'` works directly on a general tablespace without needing to move tables out.
   - **Why:** Per MySQL documentation, general tablespace decryption works in-place using the `INPLACE` algorithm. The only case where it fails is if a table in the tablespace belongs to a schema with `DEFAULT ENCRYPTION='Y'`, which is a specific edge case, not the general rule.

## Review Notes
- The `keyring_file` plugin (`keyring_file.so`) was deprecated in MySQL 8.0.34 and removed in MySQL 8.4.0. The recommended replacement is the `component_keyring_file` component. Since the post does not target a specific MySQL version and the plugin is still valid for many MySQL 8.0 installations, no change was made, but readers on MySQL 8.0.34+ or 8.4+ should use the component-based keyring instead.
- The `default_table_encryption` variable was introduced in MySQL 8.0.16, so the techniques in this post implicitly require MySQL 8.0.16 or later for full compatibility.
- The system tablespace (`ibdata1`) claim that it "cannot be encrypted directly" is correct per official MySQL documentation, which states: "Encryption is not supported for other tablespace types including the InnoDB system tablespace." Note that the separate `mysql` system tablespace (`mysql.ibd`) can be encrypted starting from MySQL 8.0.16.
- All SQL syntax, `information_schema` column names, and configuration directives were verified as correct.
