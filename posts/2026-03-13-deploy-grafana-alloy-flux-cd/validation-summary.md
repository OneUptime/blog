## Issues Found
- The introduction said the guide configures a metrics and logs pipeline, but the provided Alloy configuration only sends Prometheus metrics. Changed this to "metrics pipeline" so the claim matches the implementation.
- The HelmRelease referenced an existing `alloy-config` ConfigMap without setting `alloy.configMap.create: false`. Grafana's Alloy Helm documentation requires `create: false` when using an existing ConfigMap, so this value was added.
- The chart version range was open-ended (`>=0.9.0`), which could automatically select a future breaking major chart version. Changed it to `>=1.0.0 <2.0.0` and updated the best-practice example to match.
- The Alloy config comment claimed it discovered pods with Prometheus annotations, but the snippet scraped all discovered pods. Added a `discovery.relabel` component to keep only pods with `prometheus.io/scrape=true` and to apply an annotated metrics path when present.
- The Flux Kustomization manifest was shown as `clusters/my-cluster/grafana-alloy/kustomization.yaml`, which conflicts with Flux's documented handling of `kustomization.yaml` as a Kustomize build file under `.spec.path`. Updated the example path comment to place the Flux Kustomization resource outside the reconciled application directory.
- The Flux Kustomization health check targeted the DaemonSet generated by the Helm chart. Flux documents checking the `HelmRelease` itself when a Kustomization applies HelmRelease objects, so the health check was updated to target the `grafana-alloy` HelmRelease.
- The best-practices section used `serviceMonitor: true`, but the Alloy Helm chart uses `serviceMonitor.enabled: true`. Updated the text to use the correct value path.
