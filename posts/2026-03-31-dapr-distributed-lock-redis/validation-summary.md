## Issues Found

1. **API URL path used `v1.0` instead of `v1.0-alpha1` (Critical)**: The lock/unlock curl examples used `http://localhost:3500/v1.0/lock/...` and `v1.0/unlock/...`. The Dapr distributed lock API is still in alpha status and requires the `v1.0-alpha1` prefix. Fixed both endpoints to use `v1.0-alpha1`.

2. **Redis key prefix was `dapr||` instead of `lock||` (Significant)**: The mermaid diagram, redis-cli verification commands, key naming comment, and MONITOR command all used `dapr||{appId}||{resourceId}` as the key format. The actual prefix generated by Dapr's `GetModifiedLockKey` function is `lock||`, not `dapr||`. Fixed all four occurrences.

3. **Redis command was `SET NX PX` instead of `SET NX EX` (Minor)**: The introduction, mermaid diagram, and summary stated Dapr uses `SET NX PX` (milliseconds). The Go Redis client's `SetNX` with a `time.Duration` in whole seconds sends `SET key value NX EX <seconds>`. Fixed to `SET NX EX` and updated the diagram parameter label from `{expiryMs}` to `{expirySeconds}`.

4. **Lua script return values were incomplete (Minor)**: The mermaid diagram stated the unlock Lua script returns `1 (deleted) or 0 (not owner)`. The actual return values are `1` (deleted), `-1` (key not found), and `-2` (owner mismatch). Fixed the diagram to show all three return values.

5. **Added alpha API note to prerequisites**: Added a note in the prerequisites that the lock API uses the `v1.0-alpha1` prefix since it is still in alpha status, to set correct expectations for readers.
