## Issues Found
1. **Incorrect description of the MAC scheme (Introduction).** The post claimed Calico uses `ee:ee:ee:ee:ee:ee` "modified with interface-specific bytes" for all pod interfaces. This is wrong: the host-side `cali*` veth uses the literal `ee:ee:ee:ee:ee:ee` for every pod (no modification), and the pod-side `eth0` MAC is kernel-generated by default. Rewrote the introduction to accurately describe host-side vs pod-side behavior and to mention the `cni.projectcalico.org/hwAddr` annotation as the only user-controllable knob.

2. **Wrong command in "Configure MAC Prefix" section.** The post showed `calicoctl patch felixconfiguration default --type merge --patch '{"spec":{"deviceRouteProtocol":80}}'` as a way to configure the MAC prefix. `deviceRouteProtocol` is the Linux routing protocol identifier (the `proto` value on routes Felix programs into the kernel) — entirely unrelated to MAC addresses. There is no `macPrefix` or equivalent setting in FelixConfiguration. Replaced the command with a pod-level example using the `cni.projectcalico.org/hwAddr` annotation, which is the actual mechanism Calico exposes for setting a pod-side MAC, and renamed the section heading to "Configure Pod MAC Address" to reflect reality.

3. **Misleading MAC in the architecture diagram.** The mermaid diagram labeled the pod-side `eth0` with `ee:ee:ee:xx:xx:xx` and the host-side `cali*` only as "host side of veth pair". This inverted reality. Updated the diagram so the host-side node displays `ee:ee:ee:ee:ee:ee` and the pod-side shows "kernel-generated or annotation MAC".

4. **Inaccurate conclusion.** The conclusion claimed "deterministic assignment based on interface identifiers, ensuring unique MACs within a node" — incorrect for the host-side, which is intentionally the same MAC on every veth. Rewrote the conclusion to accurately summarize the fixed host-side MAC and the optional pod-side override.

## Review Notes
- The `kubectl get pods -A -o wide | while read ns pod rest; do … done` loop will also consume the header row (NAMESPACE NAME …) on its first iteration, so the first line of output will be a failed `kubectl exec` against a pod literally named "NAME". This is a minor scripting quirk rather than a technical error and was left in place to avoid restructuring; users may want to add `tail -n +2` before the loop.
- The `arp` command is from `net-tools` and is deprecated on many modern distros in favor of `ip neigh show`. The example still works where `net-tools` is installed, so it was left unchanged.
- The post's framing emphasizes "securing" MAC addresses, but Calico's L3 dataplane makes pod-side MAC spoofing largely irrelevant to its security model (Calico enforces policy by source IP, not MAC). The post does not overstate this, but readers should be aware that MAC-based attack surface is minimal in a default Calico setup.
- `calicoctl` is referenced in commands that were removed; the corrected post no longer requires it, but it remains a valid tool for FelixConfiguration changes if used elsewhere.
