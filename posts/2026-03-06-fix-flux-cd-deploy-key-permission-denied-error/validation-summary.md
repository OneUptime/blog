## Issues Found
- The post stated that SSH secrets must contain `identity`, `identity.pub`, and `known_hosts`. Flux requires `identity` and `known_hosts`; `identity.pub` is generated by `flux create secret git` and is useful for registering the deploy key, but it is not required by source-controller. Updated the wording and YAML comments.
- The key-format comments implied `OPENSSH PRIVATE KEY` specifically meant ed25519 or ecdsa. OpenSSH private key format can be used for multiple key algorithms. Updated the comments to describe the file format instead of tying it to specific algorithms.
- The ECDSA P-521 example was described as "wide compatibility." Flux documents ECDSA P-521 as an example, but compatibility depends on the Git provider and client stack. Changed the comment to "Flux example."
- The `kubectl patch secret` command embedded base64 output directly in JSON. Some `base64` implementations wrap output, which can break JSON payloads. Changed the command to strip newlines from the base64 output.
- The post said GitHub periodically rotates SSH host keys. GitHub can rotate host keys, but official documentation does not describe this as a fixed periodic process. Updated the phrasing.
- The in-cluster SSH test did not authenticate with the Flux deploy key and would commonly end with a public key authentication failure. Clarified that this test checks SSH reachability and host-key validation, with the deploy-key test handled separately.
- The HTTPS fallback used `--username=git` for a GitHub personal access token. GitHub documentation shows using a GitHub username with the token as the password. Updated the placeholder to `<github-username>`.
