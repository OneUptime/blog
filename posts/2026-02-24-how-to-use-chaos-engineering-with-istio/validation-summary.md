## Issues Found
- The introduction described Istio fault injection as happening at the network layer. Istio's VirtualService fault injection is an HTTP traffic policy applied by the client-side proxy, so the wording was changed to "in the HTTP traffic path" and "emulate slow or failed upstream calls."
- The combined delay and abort example said 40% of the remaining requests would be delayed after 20% were aborted. Istio documents delay and abort faults as independent, so the explanation now says requests can be delayed, aborted, or both.
- The outlier detection section implied VirtualService abort faults would make the circuit breaker eject endpoints. Istio outlier detection tracks individual upstream hosts, while VirtualService aborts are generated by the caller's proxy. The section now says to use real upstream 5xx responses and notes that client-side aborts are not a reliable ejection test.
- The rollback command deleted VirtualServices by the `chaos-experiment=true` label even though the examples did not add that label. The comment was clarified to say it applies to fault injection VirtualServices labeled as chaos experiments.

## Review Notes
The YAML snippets use the current `networking.istio.io/v1` API and non-deprecated `percentage.value` fields. The Chaos Mesh and Prometheus examples are structurally consistent with current official documentation, but the Helm installation may require environment-specific Chaos Mesh values for non-default container runtimes in production.
