## Issues Found
- The `awk '{print $6, $7}'` command was described as printing response code and flags, but with Istio's default text format those positions are response flags and response code details. Changed it to `awk '{print $5, $6}'`.
- The path/code/duration `awk` pipeline printed connection termination details instead of duration. Replaced it with an `awk -F'"'` command that extracts the path, response code, and duration from the correct quoted and unquoted segments.
- The JSON `jq` summary used `.duration_ms`, but Istio's default JSON key is `duration`. Changed the example to `.duration`.
- The `x-envoy-upstream-service-time` explanation said it was only upstream processing time to response headers. Updated it to include network latency between Envoy and the upstream host, matching Envoy's router filter documentation.
- The Duration vs Upstream Service Time relationship overstated what the difference represents. Updated it to describe downstream-side latency, queue waiting, and proxy overhead outside the upstream request/response time.
- The request ID description said it is assigned by Istio. Updated it to say it comes from `x-request-id` and can be generated by Envoy when absent.
- The `PassthroughCluster` description said traffic bypasses the mesh. Updated it to describe unknown outbound traffic passed through without service-registry routing.
- The `BlackHoleCluster`, `NR`, and `RLSE` descriptions were tightened to match Envoy/Istio semantics.

## Review Notes
The post is technically relevant and largely aligned with Istio's current default text access log format. The examples assume the default Istio access log format and default JSON field names; custom `meshConfig.accessLogFormat` settings can change field positions and JSON keys.
