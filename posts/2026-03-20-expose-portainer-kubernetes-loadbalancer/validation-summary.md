## Issues Found
1. The Helm install snippet assumed the `portainer/portainer` chart repository was already configured. I added `helm repo add` and `helm repo update` so the command works as a standalone example, matching Portainer's documented installation flow.

2. The Service manifest used `selector.app: portainer`, which does not match the labels generated by Portainer's Helm chart. I changed the selector to `app.kubernetes.io/name: portainer` and `app.kubernetes.io/instance: portainer` so it aligns with the chart's Service and Deployment templates for the documented release name.

3. The AWS annotation example used `service.beta.kubernetes.io/aws-load-balancer-internal`, which current EKS documentation marks as unsupported in favor of `service.beta.kubernetes.io/aws-load-balancer-scheme`. I updated the annotation accordingly.

4. The GCP annotation example used `cloud.google.com/load-balancer-ip`, which is not the current GKE guidance for static IP assignment on `LoadBalancer` Services. I replaced it with the current `networking.gke.io/load-balancer-ip-addresses` annotation and clarified that it expects a reserved address resource name.

5. The external access example only showed `http://<EXTERNAL-IP>:9000`, which underemphasized Portainer's HTTPS endpoint on port `9443`. I changed the example to use HTTPS first and noted that HTTP on port `9000` is only applicable when HTTP remains enabled.

6. The MetalLB installation command pinned `v0.14.0`, while MetalLB's current installation docs use `v0.15.3`. I updated the manifest URL to the current release shown in the official install documentation.

7. The TLS section created a Kubernetes TLS secret but did not configure Portainer to use it. I added the required `helm upgrade` command with `tls.existingSecret=portainer-tls` and `tls.force=true`, which matches the Portainer chart's documented and templated behavior.

## Review Notes
- The corrected Service selector assumes the Helm release name is `portainer`, which matches the post's install command. If readers use a different release name, the `app.kubernetes.io/instance` selector must change accordingly.
- Provider-specific `LoadBalancer` annotations continue to vary by Kubernetes distribution and controller implementation. The post is now correct for the cited AWS EKS and GKE documentation, but future controller changes may require updates.
