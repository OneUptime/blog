## Issues Found
- The console steps listed max/min as Contributor Insights rule aggregations. AWS documents only Count and Sum for `AggregateOn`, so this was corrected.
- The first CLI rule used CLF with a named `client_ip` field and a nonexistent `request_count` `ValueOf`. Contributor Insights CLF rules require field indexes or aliases, and `ValueOf` is only for Sum rules. The example was changed to a JSON access-log Count rule using `$.client_ip`.
- The 5xx endpoint rule summed `$.count`, which is not generally present in API Gateway access logs. It now counts matching 5xx events.
- The DynamoDB section said one table command also enables Contributor Insights for all GSIs. AWS documents enabling a GSI with `--index-name`, so the text now states that explicitly.
- The Python example used `datetime.utcnow()` and could divide by zero when there were no contributors. It now uses timezone-aware UTC datetimes and returns early when the total is zero.
- The dashboard JSON included a JavaScript-style comment and an undocumented `insightRule` widget property. It now uses a documented metric widget with an `INSIGHT_RULE_METRIC` expression.
- The alarm example used a nonexistent direct metric namespace/dimension pattern for Contributor Insights. It now uses `put-metric-alarm --metrics` with the documented `INSIGHT_RULE_METRIC("TopIPAddresses", "MaxContributorValue")` expression.
- The pricing section said the first month of each new rule is free. Current AWS pricing describes a monthly free tier of one Contributor Insights rule and the first 1 million matching log events, so the wording was updated.
- The limits section said each rule can track up to 4,000 unique contributors. I could not verify that in current AWS documentation; the post now cites the documented 100 rules per account per Region and the 1-100 `get-insight-rule-report` contributor return range.

## Review Notes
Pricing varies by AWS Region and can change, so the post should avoid relying on exact dollar amounts without a dated pricing check.
