## Issues Found
- The prerequisites incorrectly showed `docker extension install docker/extensions-sdk` as a way to install the Extensions CLI. `docker extension install` installs an extension image, while Docker Desktop provides the Extensions CLI. Changed the command to `docker extension enable` and verified availability with `docker extension ls`.
- The prerequisites used `docker version --format '{{.Client.Version}}'` while describing Docker Desktop version verification. Changed it to `docker desktop version`.
- The metadata example specified both `vm.image` and `vm.composefile`. Docker metadata requires the VM section to define either an image or a Compose file. Changed the example to use `composefile` only.
- The frontend dependency commands installed only the TypeScript types package, but the sample imports `@docker/extension-api-client` at runtime. Added installation of `@docker/extension-api-client` and made the types package a dev dependency.
- The Go backend listened on TCP port `:8080`, but Docker recommends extension frontend/backend communication through a socket to avoid host port collisions. Updated the backend to listen on a Unix socket and updated the Dockerfile command accordingly.
- The Compose file mounted `/var/run/docker.sock` directly from the host. Docker recommends using `/var/run/docker.sock.raw` for backend containers inside the Docker Desktop VM. Updated the mount to `/var/run/docker.sock.raw:/var/run/docker.sock`.
- The Compose file used a local `build` block for the backend service even though extension runtime services should be included in the packaged extension image. Changed the service to `image: ${DESKTOP_PLUGIN_IMAGE}`.
- The backend calls the Docker CLI, but the final Alpine image did not install the Docker CLI. Added `apk add --no-cache docker-cli` to the Dockerfile.
- The hot-reload instructions enabled the UI source before starting the development server. Reordered the commands to start the UI dev server first, matching Docker's test/debug guidance.
- The debugging section used `docker extension logs`, which is not listed in the current Extensions CLI reference. Replaced it with Docker Desktop Containers view guidance plus `docker logs <backend-container-id>`.

## Review Notes
The post is technically relevant and salvageable. The examples remain simplified and assume the scaffolded project uses `ui/`; Docker documentation also shows scaffold variants that refer to a `frontend/` directory, so future revisions could add a short note about following the directory names generated by the local `docker extension init` version.
