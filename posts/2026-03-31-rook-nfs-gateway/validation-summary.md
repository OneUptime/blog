## Issues Found

1. **Description mentioned RGW buckets but post only covers CephFS**: The description claimed the post covers "CephFS or RGW buckets" but no RGW/Object Gateway content was present. Fixed the description to only mention CephFS.

2. **Deprecated `spec.rados` block in CephNFS resource**: The CephNFS YAML included `spec.rados.pool` and `spec.rados.namespace` fields, which were deprecated in Rook v1.10 and removed in v1.11+. In modern Rook, the Ceph NFS module automatically manages configuration storage in RADOS. Removed the `rados` block from the CephNFS spec.

3. **Minimum Rook version too low**: The prerequisite listed "Rook operator version 1.9 or later" but the CephNFS spec (after removing `rados`) requires v1.10+. Updated the minimum version to 1.10.

4. **CLI syntax error in `ceph nfs export create`**: The command used `path=/` (positional style) instead of the correct `--path=/` (flag style). The Ceph CLI requires the double-dash prefix for the path option. Fixed to `--path=/`.

5. **Step 3 presented manual Service creation as required**: Rook v1.10+ automatically creates a ClusterIP Service for CephNFS servers. The step was misleading as a required step. Updated the text to explain that Rook auto-creates the service, and changed the example to show a LoadBalancer service type for external access (which is the actual use case for manual service creation).

6. **Step 5 ConfigMap approach is outdated**: The ConfigMap-based NFS export configuration was an older pattern. In modern Rook (v1.10+), exports are managed through the `ceph nfs export` CLI and stored in RADOS automatically. Updated the section to frame it as a reference for the underlying Ganesha EXPORT block syntax rather than a recommended configuration method.

## Review Notes
- The `CephNFSExport` resource mentioned in Step 4 as available in "Rook 1.13+" could not be confirmed as an officially shipped CRD. The `ceph nfs export` CLI approach shown is the established and documented method. Left the mention as-is since it may refer to a future or recently added CRD, but readers should verify against current Rook documentation.
- The post focuses exclusively on CephFS-backed NFS exports. NFS-Ganesha also supports RGW (Object Gateway) via FSAL_RGW for S3-bucket-as-NFS access, which could be a follow-up post.
- The Ganesha EXPORT block in Step 5 includes `Secret_Access_Key = <generated-key>` as a placeholder. This is fine for reference but readers should understand this key is auto-generated by the Ceph NFS module when using the CLI approach.
