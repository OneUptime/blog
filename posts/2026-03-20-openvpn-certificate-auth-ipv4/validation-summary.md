## Review Notes
- Easy-RSA paths are correct: `pki/ca.crt`, `pki/issued/client1.crt`, and `pki/private/client1.key` are the standard locations produced by `easyrsa gen-req` + `easyrsa sign-req`. `ta.key` is not generated by Easy-RSA itself (it is created with `openvpn --genkey secret ta.key`); the post assumes the operator has placed it under `~/openvpn-ca/pki/ta.key`, which is a reasonable convention but worth knowing if the file is not found there.
- `cipher AES-256-CBC` still works in OpenVPN 2.x but is considered legacy. OpenVPN 2.5+ prefers `data-ciphers AES-256-GCM:AES-128-GCM` (with `data-ciphers-fallback` for older peers). Not technically incorrect for compatibility-oriented setups, but a future revision could mention modern AEAD ciphers.
- `tls-auth` with `key-direction 1` is correct legacy syntax. OpenVPN 2.4+ also offers `tls-crypt` (encrypts the control channel rather than just authenticating it), which is generally recommended for new deployments. Again, not wrong — just a modernization opportunity.
- The systemd service name `openvpn-server@server` is correct for the upstream/RHEL/Ubuntu 18.04+ packages (which split server and client templates). On older Debian-style packaging, the unit was `openvpn@server`. The post's choice is the current convention.
- Revocation flow (`easyrsa revoke` → `easyrsa gen-crl` → copy `crl.pem` → `crl-verify` directive → restart) matches the official OpenVPN HOWTO.
- The inline `.ovpn` build pattern via heredoc + `cat ... >>` is valid; the resulting file structure (block tags on their own lines) is what OpenVPN's parser expects.
