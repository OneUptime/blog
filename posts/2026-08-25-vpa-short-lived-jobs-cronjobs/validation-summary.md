## Issues Found
- The manifest used the unquoted value `updateMode: Off`. Kubernetes' YAML conversion treats bare `Off` as the boolean `false`, but the VPA CRD requires a string enum. Changed it to `updateMode: "Off"`.
- The example combined a fixed `memory: 4Gi` container limit with `controlledValues: RequestsOnly` and `maxAllowed.memory: 16Gi`. VPA caps a requests-only recommendation to the unchanged container limit, so 16 GiB could never be applied. Changed `maxAllowed.memory` to `4Gi` to make the conservative example internally consistent.
- Clarified that it is the CronJob template labels used to derive the selector that must remain stable. Per-Job labels generated by Kubernetes can change without preventing aggregation through the stable selector.
- Replaced the imprecise description of a history-length-only confidence multiplier. Current VPA widens recommendation bounds using confidence derived from both the span and count of historical CPU samples.
- Corrected the Job retry explanation. A disruption normally counts toward `.spec.backoffLimit`; `podFailurePolicy` can ignore `DisruptionTarget`, and Indexed Jobs can use `.spec.backoffLimitPerIndex`. Also clarified that eviction remains subject to the updater's checks.
- Expanded the Prometheus history requirements. The provider needs matching identity-label settings, a historical range-vector Pod-label query, and a resolution fine enough for short runs; retained cAdvisor series alone are insufficient. Also clarified that checkpoint and Prometheus storage are alternative modes and made the TTL/retention statement mode-specific.

## Review Notes
- Reviewed against Kubernetes autoscaler commit `22115908908a2fc94a4f3c47f28f1fb754fe585a` dated 2026-08-24 and current Kubernetes documentation. The post's GitHub `master` links are valid but mutable.
- All `kubectl` commands and all six links in the post were verified. `kubectl top` requires Metrics Server and can miss Pods that finish before the resource-metrics pipeline reports them.
- Upstream VPA's updater defaults to `--min-replicas=2`, so a singleton Job is normally protected from `Recreate` eviction unless the global value or `spec.updatePolicy.minReplicas` is lowered.
