# How to Configure K3s to Use containerd - Configuration

Author: [nawazdhandala](https://www.github.com/nawazdhandala)

Tags: k3s, Containerd, Container Runtime, Kubernetes, SUSE Rancher, CRI, Registry

Description: Learn how to configure K3s's embedded containerd runtime, including registry mirrors, snapshot settings, custom configuration overlays, and runtime class configuration.

---

K3s ships with a built-in containerd runtime. Unlike Docker-based runtimes, containerd integrates directly with Kubernetes via the CRI without an additional shim layer. This guide covers how to configure and customize the embedded containerd.

---

## K3s containerd Configuration Locations

| File | Purpose |
|---|---|
| `/var/lib/rancher/k3s/agent/etc/containerd/config.toml` | Auto-generated by K3s - do not edit directly |
| `/var/lib/rancher/k3s/agent/etc/containerd/config-v3.toml.tmpl` | Override template for containerd 2.0 / config version 3 |
| `/var/lib/rancher/k3s/agent/etc/containerd/config.toml.tmpl` | Legacy override template for containerd 1.7 / config version 2 |
| `/etc/rancher/k3s/registries.yaml` | Registry mirrors and credentials |

## Step 1: Configure Registry Mirrors

The simplest way to configure mirror endpoints for image pulls:

```yaml
# /etc/rancher/k3s/registries.yaml

mirrors:
  "docker.io":
    endpoint:
      - "https://mirror.gcr.io"
      - "https://registry.example.com"
  "registry.k8s.io":
    endpoint:
      - "https://k8s-mirror.example.com"

configs:
  "registry.example.com":
    auth:
      username: myuser
      password: mypassword
    tls:
      # Keep TLS verification enabled while trusting a custom CA
      insecure_skip_verify: false
      ca_file: /etc/ssl/certs/internal-ca.crt
```

Containerd will try the listed mirror endpoints first, then fall back to the registry's default endpoint unless the node is started with `--disable-default-registry-endpoint`.

Restart K3s to apply:

```bash
sudo systemctl restart k3s        # server nodes
sudo systemctl restart k3s-agent  # agent nodes
```

## Step 2: Customize containerd via Template

If you need to modify containerd settings beyond what K3s exposes, use a config template. On current K3s releases, prefer a version 3 template for containerd 2.0. For options K3s already exposes, such as the snapshotter, prefer the corresponding K3s flags or config file options.

```toml
# /var/lib/rancher/k3s/agent/etc/containerd/config-v3.toml.tmpl
{{ template "base" . }}

[plugins.'io.containerd.cri.v1.runtime'.containerd.runtimes.'custom']
  runtime_type = "io.containerd.runc.v2"

[plugins.'io.containerd.cri.v1.runtime'.containerd.runtimes.'custom'.options]
  BinaryName = "/usr/bin/custom-container-runtime"
  SystemdCgroup = true
```

## Step 3: Use the NVIDIA Runtime Class (Optional)

For nodes with NVIDIA GPUs, install the NVIDIA Container Runtime and restart K3s. K3s automatically detects supported alternative runtimes, adds the matching containerd configuration, and ships a corresponding `RuntimeClass`.

```bash
# Confirm that K3s detected the NVIDIA runtime
sudo grep nvidia /var/lib/rancher/k3s/agent/etc/containerd/config.toml
```

If you have not set `--default-runtime nvidia` on that node, request the bundled RuntimeClass in your Pod spec:

```yaml
spec:
  runtimeClassName: nvidia
```

## Step 4: Verify containerd Configuration

```bash
# Check the configured containerd endpoint
sudo k3s crictl info | jq -r '.config.containerdEndpoint'

# List running containers via containerd
sudo k3s crictl ps

# Check pulled images
sudo k3s crictl images

# Pull a test image after configuring the mirror
sudo k3s crictl pull docker.io/library/nginx:latest
```

## Best Practices

- Use `config-v3.toml.tmpl` on current K3s releases; `config.toml.tmpl` is the legacy version 2 template.
- Extend the K3s base template instead of editing the auto-generated file or copying a rendered `config.toml` into the template.
- If you add custom runtime definitions on systemd-based hosts, set `SystemdCgroup = true`.
- Use `registries.yaml` for mirror configuration and credentials; containerd will still try the default registry endpoint unless `--disable-default-registry-endpoint` is set.
