## Issues Found
- The post used `spec.resources.requests` and `spec.resources.limits`, but the current `PolicyServer` CRD exposes top-level `spec.requests` and `spec.limits`. Updated both PolicyServer examples accordingly.
- The anti-affinity and operational `kubectl` selectors used `app=kubewarden-policy-server`, which does not match the default PolicyServer labels generated by Kubewarden. Updated the examples to use `kubewarden/policy-server=default`.
- The service account example referenced `kubewarden-policy-server`, while the default Kubewarden installation uses `policy-server`. Updated the example to the documented default service account name.
- The logging section listed only `text` and `json` as `KUBEWARDEN_LOG_FMT` values. Updated it to include `otlp`, which is supported by the current `policy-server` CLI.
- The tracing example set `OTEL_EXPORTER_OTLP_ENDPOINT` but did not enable OTLP log/trace export. Replaced the unsupported `OTEL_SERVICE_NAME` example with `KUBEWARDEN_LOG_FMT: "otlp"` and kept the OTLP endpoint plus metrics flag.
- The custom PolicyServer example used unsupported `nodeSelector` on `PolicyServer`. Replaced it with supported `affinity.nodeAffinity`.
- The `ClusterAdmissionPolicy` example incorrectly set `metadata.namespace` on a cluster-scoped resource. Removed the namespace.
- The policy module reference used an outdated and incomplete image reference. Updated it to the official `registry://ghcr.io/kubewarden/policies/safe-labels:v1.0.9` artifact and added `mandatory_labels` settings so the example actually enforces labels as named.
- The private registry section implied `imagePullSecret` was for the Policy Server image itself. Clarified that it is used for fetching policy modules from private OCI registries.
- The signature verification section defined the verification source as a `Secret`, but `verificationConfig` expects a `ConfigMap` containing a `verification-config` key. Updated the manifest to use `ConfigMap` and `data`.
- The health-check section implied the metrics endpoint is always locally exposed. Clarified that the `8080` endpoint check applies when Kubewarden telemetry is enabled in sidecar mode.

## Review Notes
- The post still uses `ghcr.io/kubewarden/policy-server:latest` for PolicyServer image examples. This is technically valid and matches upstream samples, but pinning a specific version would improve reproducibility.
