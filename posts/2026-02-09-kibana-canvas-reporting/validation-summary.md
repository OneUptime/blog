## Issues Found
- Replaced deprecated `filters` Canvas expressions with the current `kibana | selectFilter` pattern.
- Corrected the metric expression to use the `metricFont` argument instead of an unsupported `font` argument on `metric`.
- Quoted Elasticsearch SQL identifiers that contain special characters, including `@timestamp`, `log.level`, `service.name`, and `http.response.status_code`.
- Replaced the unsupported `DATE_HISTOGRAM(...)` SQL example with Elasticsearch SQL's documented `HISTOGRAM(..., INTERVAL 1 DAY)` grouping function.
- Updated `pointseries` measures to use TinyMath expressions such as `sum(errors)` and `sum(error_count)`.
- Replaced the unsupported SQL aggregate `COUNT(*) FILTER (WHERE ...)` example with `SUM(CASE WHEN ... THEN 1 ELSE 0 END)`.
- Corrected the time filter example to pass filter context through `selectFilter` and set `essql timeField="@timestamp"`.
- Replaced the hand-built `/api/reporting/generate/canvas` request body with Kibana Reporting's documented copied POST URL flow and use of the response `path`.
- Rewrote the week-over-week SQL example to avoid unsupported scalar subqueries in the SELECT list.
- Replaced unsupported HTML/CSS-in-Markdown styling with Canvas expression styling using `markdown`, `font`, `render`, and `containerStyle`.
- Clarified the gauge color wording so it no longer claims a static `valueColor` changes automatically based on the metric value.

## Review Notes
Canvas is still documented by Elastic, but the current docs note that Canvas is only available in Serverless for upgraded installations with existing workpads. The post remains broadly applicable to Elastic Stack installations with Canvas enabled. Kibana Reporting PDF export is a subscription and permissions-dependent feature, so users must have reporting access and a copied POST URL generated by their Kibana instance.
