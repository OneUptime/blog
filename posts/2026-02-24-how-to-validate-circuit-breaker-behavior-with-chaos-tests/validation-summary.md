## Issues Found
- The setup used the Istio 1.22 httpbin sample. Istio 1.30 is the current release as of 2026-05-21, so the sample URL was updated to `release-1.30`.
- The post introduced multiple top-level `DestinationRule` resources for the same `host`. Istio's best practices warn that only the first top-level traffic policy is used when multiple destination rules define one for the same host, so the later examples now update the existing `httpbin-cb` rule instead of creating competing rules.
- The bad-pod example used a malformed inline Python/Flask command and listened on port 8000. The current Istio httpbin Service routes service port 8000 to target port 8080, so the example now uses a syntactically valid Python standard-library HTTP server listening on 8080 and returning HTTP 500.
- The description of `baseEjectionTime` implied a fixed 30-second ejection. Istio documents it as a minimum duration multiplied by the number of times the host has been ejected, so the text now says "at least" 30 seconds and clarifies the first ejection behavior.
- The combined fault-injection test implied proxy-generated aborts would identify and eject specific upstream instances. The text now clarifies that injected aborts are generated by the proxy, and that the bad pod must remain in place to validate outlier ejection.
