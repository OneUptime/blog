## Issues Found
- The post said OIDs were deprecated in PostgreSQL 12. PostgreSQL 12 removed the special `WITH OIDS` table feature, while the `oid` type and catalog OIDs still exist. Updated the wording to describe the removed table feature.
- The OID uniqueness explanation said OIDs were only unique within a table. PostgreSQL documentation warns not to assume OIDs are unique across tables and also warns about wraparound, so the wording was corrected to "not safely unique."
- The `pg_dump --no-oids` command was incorrect. PostgreSQL documents `--oids`, not `--no-oids`; row OID data is excluded by default unless `--oids` is used. Replaced the example with removing table OIDs on the source database before dumping.
- The archive restore example piped `pg_restore` errors through `grep -v`, which would hide errors but not fix the archive contents. Updated it to convert archive formats to plain SQL, remove `WITH OIDS`, then restore with `psql`.
- The identity-column example used `OVERRIDING SYSTEM VALUE` with a `GENERATED BY DEFAULT` column. PostgreSQL allows explicit values directly for `GENERATED BY DEFAULT`; `OVERRIDING SYSTEM VALUE` is needed for `GENERATED ALWAYS`. Updated the example accordingly.
- The migration script used unqualified `regclass` references for public tables. Updated the sample to schema-qualify table names so it works regardless of `search_path`.
- The version table incorrectly said PostgreSQL 14 system tables no longer use OIDs. Replaced it with the PostgreSQL 12 change: `WITH OIDS` was removed for user tables and hidden catalog OID columns became ordinary `oid` columns.
- The version table said PostgreSQL 7.x-11 supported `WITH OIDS`; PostgreSQL 7.2 documentation shows `WITH OIDS`, while PostgreSQL 7.1 does not. Updated the range to PostgreSQL 7.2-11.
