## Issues Found
- The Datadog Agent HelmRelease reused the Flagger Datadog credential secret. Flagger expects `datadog_api_key` and `datadog_application_key`, while the Datadog Helm chart expects `api-key` and `app-key` in the Agent release namespace. I changed the examples to create separate secrets and updated the Helm values to reference `datadog-agent-credentials`.
- The ExternalSecret example used `external-secrets.io/v1beta1`. Current External Secrets documentation uses `external-secrets.io/v1`, so I updated the API version and added a second ExternalSecret for the Agent secret.
- The Datadog Helm values enabled legacy `kubeStateMetricsEnabled`, which the chart notes will be removed in chart 4.0. I replaced it with `kubeStateMetricsCore.enabled`.
- The Flagger HelmRepository example was missing. I added the current OCI HelmRepository source for Flagger charts published at `oci://ghcr.io/fluxcd/charts`.
- The APM queries filtered on `service:{{ target }}-canary`, but Datadog APM `service` is the logical service tag, not the Kubernetes Service generated by Flagger. I changed the examples to filter on `service:{{ target }}` plus `kube_deployment:{{ target }}` and `kube_namespace:{{ namespace }}`.
- The latency example used `p99:trace.http.request.duration`, but Datadog documents `trace.<SPAN_NAME>.duration` as a legacy metric that does not support percentile aggregations. I changed it to the latency distribution metric form `p99:trace.http.request`.
- The CPU example compared `kubernetes.cpu.usage.total` directly to an 80% threshold, but Datadog reports that metric as core usage shown in nanocores, not a percentage. I changed the query to divide usage by CPU limits and multiply by 100.
- The dashboard metric list referenced the legacy duration metric and canary service filtering. I updated it to use `trace.http.request` percentiles and canary workload filtering.

## Review Notes
- The APM span name `http.request` is a common example, but Datadog trace metric names depend on the instrumented service's span name. Users should confirm the actual trace metric names and tags in Datadog Metrics Explorer.
- The CPU percentage query depends on CPU limits being configured for the workload. If the workload has no CPU limits, the metric may return no usable value.
- I could not run a full YAML parser locally because Ruby and `js-yaml` were not installed in the workspace, but I verified the Markdown contains the expected YAML blocks after editing.
