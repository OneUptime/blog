## Issues Found
- The setup section used a manual `docker run` command instead of the Docker Compose workflow generated by `@grafana/create-plugin`. Updated the commands to install dependencies, build with `npm run dev`, and start Grafana with `docker compose up`.
- The `plugin.json` examples omitted metadata fields that are required by the current plugin metadata schema, such as `keywords`, `logos`, `updated`, and app `dependencies`. Added minimal valid fields.
- The data source example used `MutableDataFrame`, which is deprecated in current `@grafana/data` declarations. Replaced it with `createDataFrame` and standard `DataFrame` values.
- The data source example used Observable `.toPromise()`, which is deprecated in RxJS. Replaced it with `lastValueFrom(getBackendSrv().fetch(...))`.
- The data source comments implied `backendSrv` alone handles authentication and proxying. Clarified that authenticated HTTP APIs should use Grafana data proxy routes so secrets remain server-side.
- The config editor destructured `jsonData` without using it. Removed the unused variable.
- The panel gauge calculation divided by `max - min` without guarding against equal min and max values. Added a range guard.
- The app plugin example used `AppPlugin.addConfigPage()`, which is not present in the current `@grafana/data` AppPlugin type declarations. Removed that call and kept registration via `setRootPage`.
- The publishing section said to submit a pull request to a Grafana plugin repository. Updated it to the current Grafana Cloud My Plugins submission flow.
- The signing section omitted the required access policy token setup and used a direct `npx @grafana/sign-plugin` command. Updated it to export `GRAFANA_ACCESS_POLICY_TOKEN` and run the generated `npm run sign` command with `--rootUrls` for private plugin signing.

## Review Notes
- The snippets are illustrative and still assume local `types.ts`, page components, icons, and logo files exist in the scaffolded plugin project.
- For real authenticated HTTP data source plugins, a data proxy route or backend component should be added before relying on secure configuration values at query time.
