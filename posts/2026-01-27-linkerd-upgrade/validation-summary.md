## Issues Found
- The staging upgrade example only applied `--context` to `kubectl`, while `linkerd upgrade` also needs the staging context because it reads cluster state. Updated the commands to use `linkerd --context staging-cluster` and added the CRD upgrade step.
- The CLI install command used the older generic install endpoint. Updated it to the documented `install-edge` endpoint with TLS options and an explicit `LINKERD2_VERSION` example.
- The control plane upgrade flow omitted `linkerd upgrade --crds` and `linkerd prune`. Added both steps and replaced the invalid install-vs-upgrade diff with `kubectl diff -f`.
- The extension upgrade flow omitted pruning old extension resources. Added `linkerd viz prune | kubectl delete -f -`.
- The rolling proxy update script selected deployments by a pod label that is not a reliable deployment selector. Changed it to restart deployments in the namespace, with wording that only meshed pods receive new proxies.
- The proxy-version verification command used `linkerd viz stat`, which reports traffic stats rather than proxy image versions. Replaced it with `linkerd check --proxy` plus the existing Kubernetes image inspection command.
- The certificate hierarchy diagram claimed a 10-year trust anchor validity as a general fact. Updated it to reflect Linkerd's documented default of 365 days when generated by `linkerd install`, or a custom value.
- The issuer rotation example read trust roots from a Secret and patched the issuer Secret directly. Updated it to read the documented `linkerd-identity-trust-roots` ConfigMap and apply issuer changes through `linkerd upgrade --identity-issuer-*`.
- The trust anchor rotation example patched the trust roots ConfigMap directly. Updated it to follow the documented bundle rotation flow using `step certificate bundle` and `linkerd upgrade --identity-trust-anchors-file`.
- The selective proxy rollback snippet used the wrong annotation key and an unused image variable. Updated it to use `config.linkerd.io/proxy-version` with a version variable.
- The backup script used a broad `grep -A1000` over all CRD YAML and exported an install manifest. Updated it to select Linkerd CRDs by name and export a current upgrade manifest.

## Review Notes
The post is now technically aligned with Linkerd edge documentation as of 2026-06-12. Production users on vendor-provided stable distributions should still follow their vendor's release-specific upgrade and rollback guidance, because Linkerd's official edge documentation notes that stable distributions may have alternative procedures.
