## Issues Found
1. **curl `--connect-to` with bare IPv6 address (line 118).** The example
   `curl --connect-to example.com:443:2001:db8::10:443 https://example.com`
   would not parse correctly: `--connect-to` uses the form `HOST1:PORT1:HOST2:PORT2`
   and an IPv6 address (which itself contains colons) must be wrapped in square brackets
   to disambiguate. Updated to:
   `curl --connect-to example.com:443:[2001:db8::10]:443 https://example.com`.
   Verified against the curl manpage and the curl/curl discussion #6651, which
   confirms libcurl requires brackets around IPv6 literals.

## Review Notes
- The `listen 443 ssl http2;` / `listen [::]:443 ssl http2 ipv6only=on;` syntax in
  the "HTTP to HTTPS Redirect (Dual-Stack)" section is **deprecated** as of Nginx
  1.25.1 (June 2023). Modern best practice is to use a separate `http2 on;`
  directive inside the `server` block. The existing syntax still works (Nginx
  emits a deprecation warning, not an error), so it was left unchanged, but a
  future revision should switch to the new directive form.
- `ipv6only=on` is the documented default for `listen [::]:...` sockets, so the
  parameter is technically redundant. Including it explicitly is a reasonable
  documentation/clarity choice and is not incorrect — left as written.
- The HSTS header uses only `max-age=31536000`. For HSTS preload submission,
  `includeSubDomains` and `preload` are required, but for a basic HSTS example
  the post's value is correct and intentionally conservative.
- `ssl_dhparam /etc/letsencrypt/ssl-dhparams.pem;` and the
  `options-ssl-nginx.conf` include are standard files generated by older
  versions of certbot's nginx installer. Newer certbot releases may not always
  create the dhparams file by default; readers should check whether these files
  exist on their system.
- The `openssl s_client -6` flag is valid in OpenSSL 1.1.0+ (and current 3.x),
  which is the baseline on all supported modern distributions.
