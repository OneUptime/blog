## Issues Found
- The post title and description said Edge IDs were being enforced, but the post omitted the actual Portainer setting. I added the required **Settings > Edge Compute > Enforce use of Portainer generated Edge ID** step because that is the control that enforces the behavior.
- The networking explanation was inaccurate. The original text implied all Edge Agent traffic used port `8000`. I corrected it to reflect Portainer's documented behavior: standard mode polls Portainer over the UI/API port and opens a tunnel on `8000` only when needed, while async mode uses only the UI/API port.
- The API example for creating the environment was incorrect. The original draft used a JSON body for `POST /api/endpoints`, but Portainer documents this endpoint as multipart form data. I updated the example to use form fields, added the required `URL` field for Edge environments, and changed the section to retrieve `EdgeID` and `EdgeKey` from the response instead of claiming the API returns a deployment script.
- The authentication example used lowercase JSON field names. I updated them to `Username` and `Password` to match the official Portainer examples and schema.
- The async installation example used unsupported environment variables `EDGE_CHECKIN_INTERVAL` and `EDGE_SNAPSHOT_INTERVAL`. I removed them after validating the supported agent options and clarified that async intervals are configured in Portainer, not via those agent env vars.
- The async section omitted a product limitation. I added that Edge Agent Async mode is only available in Portainer Business Edition.
- The deployment commands used `portainer/agent:latest`, which is not the recommended guidance. I changed the examples to a version-matched tag approach because Portainer documents that agent and server versions should be kept aligned.
- The Windows example was too generic and risked being misleading. I replaced it with an accurate note to use the Windows-specific deployment command generated by Portainer and the Windows named pipe URL when creating the environment via the API.

## Review Notes
- `--insecure` is only appropriate when testing with self-signed certificates. If Portainer uses a publicly trusted certificate, it should be removed from the API examples.
- The examples use `lts` as the default agent tag. That is appropriate for Portainer's LTS track, but the agent tag should always match the Portainer Server release in use.
- Validation was performed against current Portainer documentation, the current Portainer API schema, and the Portainer agent source. The commands were not executed against a live Portainer instance during this review.
