## Issues Found
- Updated BIND zone examples and conditions from `master` to `primary`, and secondary-zone configuration from `slave`/`masters` to `secondary`/`primaries`. BIND still accepts the older terms as synonyms, but current BIND documentation prefers `primary`, `secondary`, and `primaries`.
- Replaced `ansible.builtin.ini_file` with `ansible.builtin.lineinfile` for the systemd-resolved task because `ini_file` is no longer part of the current `ansible.builtin` module set.
- Updated service-management examples from `ansible.builtin.systemd` to `ansible.builtin.systemd_service`, the current module name. `ansible.builtin.systemd` remains a compatibility alias.
- Fixed the `resolv.conf.j2` template so it does not emit both `domain` and `search`. The Linux `resolv.conf` documentation treats `domain` as the obsolete one-entry form of `search`, so the template now emits one `search` line.
- Changed resolver options rendering from one `options` line per option to a single `options` line containing all configured options, matching the documented `options option ...` syntax.
- Added the missing `zone_reverse.j2` template that was referenced in the role structure and tasks. The added template includes SOA and NS records and renders PTR records from the reverse-zone variables.
- Expanded the reverse-zone default example with SOA fields required by the added reverse-zone template and by valid zone files.

## Review Notes
- The role is written for Debian/Ubuntu-style BIND packaging because it uses `apt`, `/etc/bind`, and Debian/Ubuntu BIND packages. Other distributions may require different package names, service names, paths, and users.
- `dns_bind_service: named` is appropriate for current Ubuntu BIND packages, where the systemd unit is `named.service` and `bind9.service` may be an alias.
- The post intentionally keeps resolver management simple. On systems where `/etc/resolv.conf` is generated by NetworkManager, DHCP clients, or systemd-resolved, direct templating of `/etc/resolv.conf` may be overwritten unless the host is configured to let Ansible manage it.
