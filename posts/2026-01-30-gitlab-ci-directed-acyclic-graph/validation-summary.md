## Issues Found
- Corrected the optional dependency explanation. `needs:optional` handles jobs that might not be added to the pipeline because of `rules`, `only`, or `except`; it does not make a downstream job ignore a failed dependency.
- Fixed the `parallel:matrix` example. The previous `SERVICE: $SERVICE` dependency used a CI/CD variable where GitLab requires matrix identifiers or matrix expressions. It now uses `$[[ matrix.SERVICE ]]`.
- Simplified the deploy dependency for matrix tests to `needs: [test]`, which depends on all parallel instances of the `test` job.
- Replaced the `CI_PARALLEL_JOBS` example. A custom variable with that name does not limit GitLab CI concurrency. The post now uses `resource_group` for a valid GitLab-supported concurrency control example.
- Updated the DAG visualization guidance. GitLab documents `needs` visualization in the Pipeline editor's Visualize tab, not a "Needs" tab in the pipeline view.
- Replaced the Jobs API debugging command. The documented Jobs API response does not expose a `needs` field for the shown endpoint, so the post now uses the CI Lint API to validate dependency errors.
- Fixed the monorepo example. The original used dotenv variables generated by one job inside later jobs' `rules`, but GitLab evaluates `rules` before any jobs run. The example now uses `rules:changes`.

## Review Notes
- The examples are illustrative and still assume project-specific images, credentials, package scripts, Docker-in-Docker or Docker socket access, Kubernetes access, and scanner setup.
- The matrix expression syntax used in the corrected example requires GitLab 18.6 or later.
