## Issues Found
- The Unbound configuration examples were fenced as `yaml`, but Unbound uses its own `unbound.conf` format. Changed the code fences to `text` so readers do not mistake the snippets for YAML files.
- The `nscd` section said "Configure cache sizes" while the example primarily configured host-cache TTL behavior and hash-table size. Changed the wording to "Configure the hosts cache."
- The `nscd` example implied `positive-time-to-live hosts 3600` controls DNS host lookup TTLs. The `nscd.conf(5)` manual states that for DNS, the TTL returned by DNS is used instead. Added a clarification immediately after the snippet.
- The monitoring command used `unbound-control stats` without enabling Unbound remote control. NLnet Labs documents that `unbound-control` requires `remote-control: control-enable: yes` and keys generated by `unbound-control-setup`. Added the minimal prerequisite commands before the stats example.

## Review Notes
- The Unbound cache options (`msg-cache-size`, `rrset-cache-size`, `cache-max-ttl`, `cache-min-ttl`, `prefetch`, `prefetch-key`, `num-threads`, and `cache-max-negative-ttl`) are valid according to `unbound.conf(5)`.
- `prefetch: yes` is correctly described as refreshing popular cached entries near expiry, though it can increase resolver traffic and load.
- `cache-min-ttl` is valid, but operators should use it conservatively because it can keep records cached longer than the domain owner intended.
- The Python `cachetools.TTLCache` and `socket.getaddrinfo(hostname, None)` example is syntactically valid. It is suitable for a simple example, but production multi-threaded applications should consider synchronization and should avoid caching DNS results longer than appropriate for their traffic pattern.
