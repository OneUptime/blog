## Issues Found
- The introduction and conclusion described gateway-router NDP tables as an authoritative inventory of active IPv6 addresses. RFC 4861 and vendor documentation describe these as neighbor caches, so I changed the wording to say they are a high-signal view of recently observed neighbors on directly connected links, not a complete inventory by themselves.
- The Linux parser only recognized a subset of valid neighbor states and failed on lines that include extra tokens such as the `router` flag. I expanded the regex to handle the states documented by `ip-neighbour(8)`/`ip -6 neigh help`, accept optional flags, and normalize the parsed state value.
- The parser walked every dated directory under `/var/audit/ipv6-ndp`, which would mix historical snapshots into one audit and overcount “active” addresses. I changed it to load a single snapshot directory at a time, defaulting to the newest dated collection directory unless an explicit path is provided.
- The stale-record report said an address was “not seen on network for >7 days,” but the code only compared the current NDP snapshot to IPAM and had no seven-day history. I corrected the wording to match the implemented behavior.
- The conclusion said privacy extension addresses would appear untracked unless IPAM integrates with DHCPv6. RFC 8981 defines temporary privacy addresses as a SLAAC extension, so I corrected the explanation to say they are generated by SLAAC rather than DHCPv6 and usually require observed-address inventory to track.

## Review Notes
- The post’s `show ipv6 neighbors` examples for Cisco IOS and Junos are valid per the vendor command references.
- The NetBox and `pynetbox` usage shown in Step 3 is consistent with current documentation for `pynetbox.api(...)`, endpoint filtering, and choice-field access such as `ip.status.value`.
- I validated the Python syntax and the updated Linux parser behavior locally, but I could not run the NetBox example end-to-end in this environment because `pynetbox` is not installed and no NetBox instance is available.
- The example still deduplicates only by IPv6 address and stores one router per address. That is acceptable for a simple audit walkthrough, but multi-VRF or anycast-heavy environments would need richer keys.
