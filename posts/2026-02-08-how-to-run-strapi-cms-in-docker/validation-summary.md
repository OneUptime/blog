## Issues Found
- The project creation example used `create-strapi-app@latest --quickstart`, but Strapi 5 documents `create-strapi@latest` as the current command and marks `--quickstart` as deprecated. Updated the command to use `create-strapi@latest`, PostgreSQL flags, `--js`, `--use-npm`, and `--skip-cloud`.
- The post described GraphQL APIs as automatically generated by default. Strapi 5 provides GraphQL through the `@strapi/plugin-graphql` plugin, so the wording now says REST is automatic and GraphQL is available when the plugin is installed.
- The production Dockerfile copied `/app/build`, but Strapi 5's production Docker guidance uses the built application output under the current project layout and requires native dependencies for Sharp on Alpine. Updated the Dockerfile to use Node 22 Alpine, install build/runtime native dependencies, build with `NODE_ENV=production`, install runtime dependencies with `npm ci --omit=dev`, and copy the built application from the builder stage.
- The Docker Compose file included the obsolete top-level `version: "3.8"` key. Removed it to match the current Compose Specification.
- The Compose and `.env` examples omitted `ENCRYPTION_KEY`, which Strapi's Docker documentation lists with the required container environment variables. Added it to Compose, `.env`, and the secret generation commands.
- The database pool used `min: 2`, but Strapi's Docker documentation recommends `min: 0` because Docker may kill idle connections. Updated the database configuration.
- The post set `PUBLIC_URL` in Compose without showing the matching Strapi server configuration. Added a `config/server.js` example that reads `HOST`, `PORT`, `PUBLIC_URL`, and `APP_KEYS`.
- The admin URL pointed only to the HTTPS production hostname before the reverse proxy section. Updated it to use `http://localhost:1337/admin` for the direct Compose mapping and the HTTPS URL after reverse proxy setup.
- The Content-Type Builder instructions were presented after a production deployment, but Strapi documents the Content-Type Builder as available only in development. Updated the wording to specify a development environment.
- The REST API example used numeric ID lookup (`/api/articles/1`) for a Strapi 5 content type. Strapi 5 content APIs use `documentId` for document lookup, so the example now uses `{documentId}`.
- The REST API filter example referenced a `published` boolean field that was not created in the tutorial. Replaced it with Strapi 5's `status=published` parameter and kept sorting by `publishedDate`.

## Review Notes
The examples are now aligned with current Strapi 5 documentation. The Dockerfile remains a concise tutorial example; production deployments may still prefer binding the Strapi port to localhost only, using external object storage for uploads, and managing secrets through an orchestrator or secret manager.
