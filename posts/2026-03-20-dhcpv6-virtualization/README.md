## Introduction

Stateful DHCPv6 assigns IPv6 addresses to virtual machines, unlike SLAAC which is stateless. In virtualization environments, DHCPv6 can run on the hypervisor host, within the virtual network (libvirt, OpenStack Neutron, NSX-T), or on a dedicated VM. DHCPv6 provides IPAM visibility - each lease is recorded with a timestamp and client identifier such as a DUID - making it preferable to SLAAC for environments that require IP tracking.

        "subnet": "2001:db8:100::/64",

          {

## dnsmasq DHCPv6 for KVM (libvirt)

```bash
# libvirt uses dnsmasq for DHCPv6 in virtual networks that include an IPv6 <dhcp> section
# Configure via virsh or XML

# Check dnsmasq configuration generated by libvirt
cat /var/lib/libvirt/dnsmasq/default.conf | grep dhcp
cat /var/lib/libvirt/dnsmasq/default.hostsfile

# Add DHCPv6 host entry for a VM on a dual-stack network
# --parent-index 1 selects the IPv6 <ip> element
virsh net-update default add ip-dhcp-host \
    '<host id="00:03:00:01:52:54:00:ab:cd:01" name="webserver" ip="fd00:100::10"/>' \
    --parent-index 1 --live --config

# For IPv6, prefer a DUID/client-id reservation rather than a MAC-only reservation
virsh net-update default add ip-dhcp-host \
    '<host id="00:01:00:01:18:aa:62:fe:52:54:00:ab:cd:02" name="dbserver" ip="fd00:100::11"/>' \
    --parent-index 1 --live --config

# List current DHCPv6 leases
virsh net-dhcp-leases default | grep -i "ipv6\|fd00\|2001"
```

## OpenStack Neutron DHCPv6

```bash
# In the reference DHCP agent, OpenStack Neutron uses dnsmasq for DHCPv6 on tenant networks

# Create subnet with DHCPv6 stateful
openstack subnet create \
    --network my-network \
    --ip-version 6 \
    --subnet-range 2001:db8:200::/64 \
    --dhcp \
    --ipv6-address-mode dhcpv6-stateful \
    --ipv6-ra-mode dhcpv6-stateful \
    --allocation-pool start=2001:db8:200::100,end=2001:db8:200::200 \
    my-ipv6-subnet

# Check DHCP agent is running
openstack network agent list | grep dhcp

# View assigned IPv6 addresses via Neutron
openstack port list --network my-network --long | grep "ip_address"
# Each port shows its IPv6 address for the subnet
```

## Proxmox Container DHCPv6

```bash
# LXC containers in Proxmox can use DHCPv6 on the attached bridge network

# /etc/pve/lxc/100.conf - Container network config
net0: name=eth0,bridge=vmbr0,hwaddr=52:54:00:aa:bb:cc,ip=dhcp,ip6=dhcp

# Start container - the guest networking configuration will request both DHCPv4 and DHCPv6
pct start 100

# Check container got IPv6 from DHCPv6
pct exec 100 -- ip -6 addr show
# Expected: inet6 2001:db8:100::xx/64 scope global dynamic

# Check DHCPv6 lease on host
grep -i "2001:db8:100" /var/lib/kea/dhcp6.leases
```

## Monitor DHCPv6 Leases

```python
#!/usr/bin/env python3
# monitor_dhcpv6_leases.py

import requests
from datetime import datetime

KEA_API = "http://127.0.0.1:8000/"

def get_dhcpv6_leases() -> list:
    """Retrieve all DHCPv6 leases from Kea."""
    response = requests.post(
        KEA_API,
        json={"command": "lease6-get-all"},
        timeout=10,
    )
    response.raise_for_status()
    result = response.json()
    if result and result[0]["result"] == 0:
        return result[0].get("arguments", {}).get("leases", [])
    return []

def print_lease_summary():
    leases = get_dhcpv6_leases()
    print(f"DHCPv6 Leases: {len(leases)}")
    for lease in leases:
        expire = datetime.fromtimestamp(lease.get("cltt", 0) + lease.get("valid-lft", 0))
        hostname = lease.get("hostname") or "unknown"
        print(f"  {lease['ip-address']:40s}  {hostname:20s}  expires: {expire}")

print_lease_summary()
```

## Conclusion

DHCPv6 in virtualization environments provides centralized, trackable IPv6 address assignment for VMs and containers. Kea DHCPv6 running on the hypervisor host listens on bridge interfaces (virbr0, br0) and serves addresses to VMs via the `subnet6` configuration. libvirt uses dnsmasq for DHCPv6 in virtual networks, configurable via network XML or `virsh net-update`, typically using a DUID/client-id for IPv6 host reservations. In the reference DHCP agent, OpenStack Neutron uses dnsmasq for stateful DHCPv6 when subnets use `dhcpv6-stateful` mode. DHCPv6 reservations by DUID, or by hardware address in platforms that support it, ensure specific VMs always receive the same IPv6 address, enabling stable DNS records and firewall rules. Monitor leases via the Kea management API or `virsh net-dhcp-leases` for IPAM tracking.
