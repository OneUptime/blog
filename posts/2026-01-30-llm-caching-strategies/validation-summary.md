## Issues Found
- The OpenAI examples used the older `gpt-4` model ID. Updated the examples to `gpt-4o-mini`, a current Chat Completions-compatible model for simple cost-sensitive examples.
- The Anthropic prompt caching example used the deprecated `claude-sonnet-4-20250514` model ID. Updated it to `claude-sonnet-4-6`, matching Anthropic's current migration guidance.
- The OpenAI prompt caching example attempted to call `.get()` on `usage.prompt_tokens_details`, which is an SDK object rather than a dictionary. Updated the code to read `cached_tokens` with `getattr`.
- The semantic Redis cache returned `response` and model metadata without declaring those JSON fields in the RediSearch schema. Added indexed aliases for the returned fields.
- The semantic cache lookup could reuse responses generated by a different model. Updated the lookup to retrieve multiple nearest neighbors and return only matches for the requested model.
- The multi-layer cache exact key did not include `system_prompt`, which could return a cached response generated under different system instructions. Added `system_prompt` to the exact cache key.
- The multi-layer semantic cache could reuse responses generated with a different model or system prompt. Added stored model and system prompt hash metadata, and filtered semantic hits against both values.
- Because the Redis clients use `decode_responses=False` in vector examples, returned fields may be bytes. Added small decoding helpers before comparing or returning Redis document fields.

## Review Notes
- The Redis JSON vector pattern is valid: official redis-py examples store JSON vectors as float lists and send query vectors as `float32` bytes.
- The Python code blocks were syntax-checked with `python3` after edits. Runtime execution was not attempted because it would require configured Redis, Redis Search/JSON support, and live OpenAI/Anthropic API credentials.
