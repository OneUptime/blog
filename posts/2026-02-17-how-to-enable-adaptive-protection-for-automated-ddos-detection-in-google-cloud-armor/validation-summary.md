## Issues Found
- The post used the old Managed Protection Plus name and an invalid `gcloud compute security-policies update --enable-ml` command for tier enrollment. I updated the terminology to Cloud Armor Enterprise and changed the command to `gcloud compute project-info update --cloud-armor-tier=CA_ENTERPRISE_PAYGO`.
- The Adaptive Protection enablement examples used the unsupported `--enable-ml` flag and showed enabling Adaptive Protection during policy creation. I changed the examples to create the policy first and then enable Adaptive Protection with `--enable-layer7-ddos-defense`.
- The Adaptive Protection settings example used unsupported `--adaptive-protection-config-*` flags. I replaced them with current `--enable-layer7-ddos-defense` and `--layer7-ddos-defense-rule-visibility=STANDARD` flags.
- The auto-deploy section omitted the required placeholder rule and used unsupported auto-deploy flag names. I added the `evaluateAdaptiveProtectionAutoDeploy()` placeholder rule and changed the threshold command to the current `gcloud beta compute security-policies update --layer7-ddos-defense-auto-deploy-*` flags.
- The alerting example created a Logging sink, not a log-based alerting policy, and used request-log fields for alert logs. I replaced it with a Cloud Monitoring log-based alerting policy using `conditionMatchedLog` and the `network_security_policy` alert log filter.
- The logging queries filtered `http_load_balancer` request logs and `jsonPayload.adaptiveProtection.autoDeployAlertId` for Adaptive Protection alerts. I updated the alert queries to use `resource.type="network_security_policy"` and `jsonPayload.alertId`, which match Adaptive Protection alert logs.
- The suggested rule example used the invalid expression `evaluatePreconfiguredExpr('adaptive-protection-auto-deploy')`. I changed it to the documented `evaluateAdaptiveProtection('ALERT_ID')` pattern.
- The manual mitigation command used a hand-written regional and user-agent expression instead of the suggested-rule expression generated by Adaptive Protection. I changed it to deploy `evaluateAdaptiveProtection('11275630857957031521')`.
- The Terraform example configured auto-deploy thresholds but did not include the required auto-deploy placeholder rule. I added a Terraform rule using `evaluateAdaptiveProtectionAutoDeploy()` and adjusted the WAF rule priorities to avoid a conflict.
- The prerequisite referred to an external HTTP(S) load balancer. I updated it to external Application Load Balancer, matching current Google Cloud Armor documentation.

## Review Notes
- The example alerting policy uses `CHANNEL_ID` as a placeholder; users must replace it with the notification channel ID returned by `gcloud monitoring notification-channels create`.
- The Terraform `auto_deploy_config` block is documented as beta in the provider docs, so production Terraform configurations might need the `google-beta` provider depending on the provider version in use.
