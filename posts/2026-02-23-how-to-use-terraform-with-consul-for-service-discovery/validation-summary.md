## Issues Found
- The Consul server security group omitted port 8302 for WAN Serf traffic. Added TCP and UDP ingress rules for port 8302, which Consul documents as the default WAN Serf port for server communication.
- The `consul_service` examples used EC2 instance IDs and an RDS label directly as Consul node names without defining corresponding catalog nodes. Added `consul_node` resources and updated `consul_service.node` references to use the Consul node names, matching the provider's catalog model for Terraform-managed external services.
- The reusable module registered a service against `var.instance_id` without ensuring that node existed in the Consul catalog. Added a `consul_node` resource to the module and pointed the service at that node.
- The service intentions example set `Precedence` values in source entries. Current Consul service-intentions documentation describes `Precedence` as read-only and generated by Consul, so those fields were removed.

## Review Notes
The snippets are still illustrative and depend on surrounding resources and variables that are not shown, such as IAM instance profiles, AMI selection, Consul server bootstrap user data, AWS database resources, and ACL/TLS setup. The Consul provider documentation also notes that `consul_service` is best suited for external services; services running a local Consul agent are usually better registered with the local agent to avoid anti-entropy removing catalog-only registrations.
