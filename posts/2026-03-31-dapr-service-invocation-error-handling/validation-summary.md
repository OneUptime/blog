## Issues Found

### 1. Status code table was inaccurate
**What was wrong:** The table listed six HTTP status codes (400, 403, 404, 408, 500, 503) and attributed all of them to the Dapr sidecar. In reality, the Dapr sidecar only generates three codes for service invocation errors: 400 (method name not given), 403 (invocation forbidden by access control), and 500 (request failed). The codes 404, 408, and 503 are not generated by the sidecar — they can only appear as pass-through responses from the called service.

**Specific inaccuracies:**
- 400 was described as "Bad request from the application" — the actual meaning is "Method name not given."
- 404 was described as "App ID or method not found" — Dapr returns 500 (not 404) when an app ID is not found.
- 408 was described as "Request timed out" — Dapr returns 500 with "context deadline exceeded" for timeouts, not 408.
- 500 was described as "Application error" — it is actually a catch-all "Request failed" covering timeouts, app not found, network errors, and circuit breaker open.
- 503 was described as "Service unavailable or circuit open" — Dapr returns 500 for circuit breaker open, not 503.

**What was changed:** Replaced the six-row table with the three actual sidecar-generated codes and their correct descriptions. Added explanatory text clarifying that the Dapr sidecar passes through HTTP status codes from the called service (e.g., 404, 408, 503).
