## Issues Found
- The post did not mention that CDKTF is deprecated as of December 10, 2025. Added a short caveat in the introduction.
- The setup used `npm install @cdktf/provider-aws`, but the prebuilt AWS provider package is deprecated. Replaced it with `cdktf provider add hashicorp/aws --force-local` and updated provider imports to use locally generated `.gen/providers/aws/...` bindings.
- The infrastructure section claimed it created an ECS service, but the code only created networking and RDS resources. Updated the description to match the code.
- The prod stack used `vpcCidr: "10.1.0.0/16"` while subnet CIDRs were hard-coded under `10.0.0.0/16`, which would fail because the subnets were outside the VPC CIDR. Replaced hard-coded subnet CIDRs with `Fn.cidrsubnet(config.vpcCidr, 8, ...)`.
- The `InfrastructureStack` class was imported by the test snippet but not exported. Exported the class and wrapped app synthesis in a `require.main === module` guard so tests can import it cleanly.
- The reusable bucket example assigned `dataBucket` without using it, which conflicts with the strict `noUnusedLocals` setting generated by CDKTF's TypeScript template. Added a `data_bucket_arn` output.
- The Terraform module JSON snippet included a JavaScript-style comment inside a `json` code block. Removed the invalid comment.
- The Jest test snippet used CDKTF matchers without loading the Jest adapter and passed raw Terraform resource type strings to `toHaveResourceWithProperties`. Added the adapter import and changed assertions to pass generated resource constructors (`Vpc` and `DbInstance`).
- The validity test used `Testing.synth(stack)` with `toBeValidTerraform`; CDKTF documentation requires a full synth for Terraform validation. Updated it to `Testing.fullSynth(stack)`.
- The Terraform module snippet assigned the module to `const vpc` without using it. Changed it to instantiate the module directly.
- The introduction implied `async/await` is the dependency mechanism for infrastructure. Reworded it to describe TypeScript composition and control flow more accurately.

## Review Notes
- The examples are now aligned with current CDKTF v0.21 documentation, but CDKTF itself is deprecated and no longer maintained by HashiCorp.
- `toBeValidTerraform` requires the Terraform CLI to be installed because it runs Terraform validation against the synthesized output.
- The example still uses placeholder database passwords for brevity; production code should use secret management instead of fallback literals.
