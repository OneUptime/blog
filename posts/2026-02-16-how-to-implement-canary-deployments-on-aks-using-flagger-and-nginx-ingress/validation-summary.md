## Issues Found
- The prerequisites did not state Flagger's documented minimum versions for the NGINX tutorial. Added Kubernetes 1.19+ and NGINX Ingress Controller 1.0.2+.
- The ingress-nginx Helm command enabled metrics but did not add the Prometheus scrape annotations used by Flagger's Prometheus add-on. Added the documented `prometheus.io/scrape` and `prometheus.io/port` pod annotations.
- The Flagger install command used `provider=nginx` and a separate `flagger-prometheus` install. Updated it to the current documented Helm values, `prometheus.install=true` and `meshProvider=nginx`.
- The post instructed users to create the `podinfo` Service manually, but Flagger generates the apex, primary, and canary ClusterIP Services from the Canary `service` spec. Changed the service snippet to show it as generated by Flagger and removed the manual `kubectl apply` step.
- The Ingress used the deprecated `kubernetes.io/ingress.class` annotation. Updated it to `spec.ingressClassName: nginx`.
- The Canary resource omitted `spec.provider: nginx`. Added it to match the Flagger NGINX tutorial and make the provider explicit.
- The comments described `progressDeadlineSeconds` and `analysis.threshold` incorrectly. Corrected them to explain that `progressDeadlineSeconds` is the maximum progress time and `threshold` is the maximum number of failed metric checks before rollback.
- The load test webhook targeted `podinfo-canary` directly, bypassing NGINX Ingress metrics. Updated it to send traffic through `http://app.example.com/` so NGINX traffic splitting and metrics are exercised.
- The rollback test referenced a non-documented broken image tag. Replaced it with a real podinfo image update and a documented `/status/500` ingress request pattern to generate failures during analysis.

## Review Notes
- The tutorial assumes `app.example.com` resolves to the NGINX ingress controller's external address. In a future revision, the post could mention configuring DNS or using a temporary host override.
- Kubernetes Ingress is stable but frozen; Kubernetes recommends Gateway API for newer designs. This does not invalidate the tutorial because Flagger and ingress-nginx still document NGINX Ingress canary support.
