## Review Notes
- The `kubectl get events --field-selector reason=OOMKilling` command relies on the node-problem-detector being installed in the cluster. The "OOMKilling" event reason is generated by node-problem-detector's kernel-monitor plugin, not by the kubelet itself. Without node-problem-detector, this command returns no results. Many production clusters do have it installed, so this is not incorrect, but readers on clusters without it may need to use alternative approaches (e.g., checking `containerStatuses[].lastState.terminated.reason == "OOMKilled"` directly).
- The `maxConnections` and `connectionPoolSize` metadata fields shown in the connection pool example are generic. Actual metadata field names vary by Dapr component (e.g., Redis, PostgreSQL). Readers should consult the specific component documentation for exact field names.
- The circuit breaker `maxRequests: 100` value is high for a half-open state (typical values are 1-10). This controls how many requests pass through while testing recovery, so a lower value is generally recommended in production.
