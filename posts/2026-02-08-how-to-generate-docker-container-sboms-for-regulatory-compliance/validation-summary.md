## Issues Found
- The opening compliance statement overstated that container SBOMs are universally mandatory. Updated it to say SBOMs are a compliance expectation and may be required depending on regulatory scope.
- The Syft install command used the raw GitHub install script URL. Replaced it with Anchore's documented installer URL, `https://get.anchore.io/syft`, with `sudo` for installation into `/usr/local/bin`.
- The Docker BuildKit section claimed build-time SBOM generation is categorically more accurate than post-build scanning. Adjusted the wording to match Docker's attestation behavior and its build-time visibility benefits.
- The Docker SBOM inspection command printed `.SBOM`, but Docker's documented example accesses `.SBOM.SPDX` for the raw SPDX SBOM. Updated the command.
- The CI example scanned a Syft-generated SBOM with Trivy, while Trivy documents that SBOMs generated by other tools may produce less accurate results. Added Trivy SBOM generation for the vulnerability-gating step and stored that SBOM as an artifact.
- The SBOM diff script only handled CycloneDX `.components` even though the post discusses SPDX and CycloneDX. Updated the jq expressions and package counts to handle both CycloneDX `.components` and SPDX `.packages`.
- The SBOM diff script claimed to show updated packages, but the implementation only shows added and removed package-version entries. Corrected the script comment.
- The validation script only checked CycloneDX-style versions and missed some current CycloneDX tool metadata shapes. Updated it to handle SPDX package versions and CycloneDX metadata tools components.
- The compliance mapping table incorrectly presented PCI DSS and EU CRA as requiring the same explicit SBOM fields as NTIA. Revised the table to distinguish NTIA minimum elements, PCI DSS software inventory support, and the CRA's machine-readable SBOM/top-level dependency requirement.
- The summary statement called SBOM generation a universal compliance necessity. Softened it to "often a compliance necessity."

## Review Notes
Syft, Trivy, and ORAS were not installed in the local environment, so their commands were verified against official documentation rather than executed locally. Docker Buildx and jq were available locally and their relevant help/version output was checked.
