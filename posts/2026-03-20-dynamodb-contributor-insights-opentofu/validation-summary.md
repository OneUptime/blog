## Issues Found
- The GSI example used deprecated AWS provider arguments (`hash_key` and `range_key`) inside `global_secondary_index`. I replaced them with `key_schema` blocks because current provider docs mark the old arguments as deprecated.
- The Contributor Insights resources relied on the default mode while the post described “most frequently accessed” keys. I made the mode explicit with `ACCESSED_AND_THROTTLED_KEYS` so the code matches the behavior being described.
- The CloudWatch dashboard section was technically inaccurate: it labeled standard `AWS/DynamoDB` table metrics as if they were Contributor Insights top-key graphs. AWS documents Contributor Insights graphs separately and exposes them through Contributor Insights rule metrics, not through `ConsumedReadCapacityUnits`. I corrected the section to describe the dashboard as complementary table-level monitoring instead.
- The CloudWatch dashboard metric widgets were missing the required `region` property. I added `data "aws_region" "current" {}` and used `data.aws_region.current.name` in each widget.
- The throttling alarm description overstated causality by implying throttles directly indicate hot partitions. I revised the language to say throttling can indicate hot partitions or insufficient capacity.
- The prerequisites understated the required permissions for first-time enablement. AWS documents that the initial setup creates a service-linked role, so I added the `iam:CreateServiceLinkedRole` requirement for first use.

## Review Notes
- The workspace did not have the `aws` or `tofu` CLIs installed, so CLI verification was done against official documentation rather than local `--help` output.
- AWS also documents Contributor Insights alarms based on `INSIGHT_RULE_METRIC(...)`. For DynamoDB-managed Contributor Insights rules, the rule names are service-generated, so the revised post appropriately avoids pretending the standard table-metric dashboard is the Contributor Insights graph itself.
