## Issues Found
- The post described trace-derived RED metrics as the Metrics Generation Processor. Current OpenTelemetry documentation defines `metricsgeneration` as a metrics-to-metrics processor; trace-derived RED metrics are generated by the Span Metrics Connector. Updated the post terminology and examples to use `span_metrics`.
- The examples used removed/deprecated spanmetrics processor wiring with `metrics_exporter`. Replaced it with connector wiring where traces export to `span_metrics` and metrics receive from `span_metrics`.
- Several snippets declared unsupported connector fields, including `span_kind`, `span_filter`, `metrics`, and `debug`. Replaced filtering with the Filter processor, computed attributes with the Transform processor, and metric naming with the connector `namespace` setting.
- Several snippets re-declared default dimensions such as `service.name`, which is invalid in current `span_metrics` configuration. Removed those duplicate dimensions.
- Histogram buckets were written as bare numbers. Updated buckets to duration values such as `10ms` and set `histogram.unit: ms` where appropriate.
- The Kubernetes example pinned `otel/opentelemetry-collector-contrib:0.93.0`, an old version from before the current connector naming and schema. Updated it to `0.153.0`.
- The Kubernetes liveness probe used the health check endpoint without enabling the `health_check` extension. Added the extension and exposed the health port.
- Prometheus queries used OpenTelemetry dot-style names directly and included custom metric names that the connector does not generate. Updated them to normalized names based on the configured namespaces.
- The slow-query PromQL example counted requests under 1 second while describing requests over 1 second. Corrected it to subtract the `le="1000"` bucket from total calls.
- Internal telemetry examples referenced old/nonexistent spanmetrics processor metrics and an outdated `address` field. Updated the monitoring guidance to current Collector telemetry patterns.
