## Issues Found
- The `flux bootstrap github` examples used `--personal` with an organization-style owner (`myorg`). Flux documents `--personal` for repositories owned by a GitHub user account, while organization-owned repository examples omit it. Removed `--personal` from the three bootstrap commands.
- The SOPS example showed AWS KMS metadata but configured Flux decryption with an age secret named `sops-age`. Updated the encrypted Secret example to use age-style SOPS metadata and clarified that only clusters with the matching age private key can decrypt it.

## Review Notes
- The Flux `Kustomization` examples use the current `kustomize.toolkit.fluxcd.io/v1` API and valid fields such as `dependsOn`, `healthChecks`, `decryption`, `prune`, `timeout`, and `sourceRef`.
- The `HelmRelease` example uses the current `helm.toolkit.fluxcd.io/v2` API and valid `CreateReplace` CRD policies.
- The Kustomize overlay examples use the current `patches` field correctly for strategic merge style patches. The encrypted values are illustrative placeholders and would need to be generated by `sops` for a real deployment.
