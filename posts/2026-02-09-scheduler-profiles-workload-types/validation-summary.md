## Issues Found
- The post used `NodeResourcesMostAllocated` as a scheduler plugin. Current Kubernetes `kubescheduler.config.k8s.io/v1` uses the `NodeResourcesFit` plugin with `scoringStrategy.type: MostAllocated` for this behavior, so the examples and explanation were updated.
- The batch profile placed `DefaultPreemption` under a `preempt` extension point. The scheduler framework uses `postFilter` for `DefaultPreemption`, so the configuration was corrected.
- The batch Job example omitted `restartPolicy`, which is required in a Job pod template and must be `OnFailure` or `Never`. The example now uses `restartPolicy: OnFailure`.
- The latency-sensitive profile described `DefaultBinder` as minimizing scheduling latency. Binding is the default binding mechanism, so the comment was corrected to avoid implying it is a latency optimization.
- The data-processing section implied scheduler profiles provide gang scheduling behavior. That claim was removed because gang scheduling requires separate scheduler capabilities beyond the shown profile configuration.
- The metrics example used `scheduler_scheduling_attempt_duration` instead of the current metric name `scheduler_scheduling_attempt_duration_seconds`, and described `scheduler_queue_incoming_pods_total` as queue wait time. The commands now use `scheduler_scheduling_attempt_duration_seconds`, `scheduler_schedule_attempts_total`, and `scheduler_pending_pods`.

## Review Notes
The examples are illustrative scheduler configurations. In production, administrators should verify the full static Pod manifest generated by their Kubernetes distribution or kubeadm setup before editing it, because replacing the whole kube-scheduler manifest with a minimal example can omit environment-specific flags, volumes, and security settings.
