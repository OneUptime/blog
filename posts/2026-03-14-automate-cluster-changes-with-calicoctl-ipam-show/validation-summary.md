## Issues Found
- The CronJob used `command: ["/bin/sh", "-c", ...]`, but the `calico/ctl:v3.27.0` image does not contain `/bin/sh`; Docker runtime verification returned `exec: "/bin/sh": stat /bin/sh: no such file or directory`. Changed the CronJob to use the image entrypoint with `args: ["ipam", "show"]`.
- The CronJob did not explicitly set the Calico datastore type. Added `DATASTORE_TYPE=kubernetes`, matching Calico's documented Kubernetes datastore configuration.
- The CronJob used the older `calico/ctl:v3.27.0` image. Updated the example to the current documented `calico/ctl:v3.32.0` image while leaving the existing version-matching troubleshooting note.
- The multi-cluster script executed `calicoctl` inside the `calico-kube-controllers` pod, which is not a documented or reliable place to find the `calicoctl` binary. Changed the script to use local `calicoctl` with a per-context kubeconfig generated by `kubectl config view --raw --minify`.
- The CI/CD example ran `calicoctl ipam show` without Calico datastore configuration. Added `DATASTORE_TYPE=kubernetes` and a `KUBECONFIG` environment variable.
- The troubleshooting note referenced `kubectl exec` timeouts after the multi-cluster script no longer used `kubectl exec`. Updated the note to refer to kubeconfig context reachability and API server connectivity.

## Review Notes
The post is technically relevant and the main `calicoctl ipam show` command is current. The examples still assume that the `calicoctl` service account, RBAC, and CI kubeconfig provisioning are handled outside the snippets, which is reasonable for the post's scope but should be made explicit in a longer production-ready guide.
