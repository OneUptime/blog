## Issues Found
- The `curl` connectivity example used `http://AGENT_HOST_IP:9001/ping`, but Portainer documents standard Agent communication on port `9001` as HTTPS with certificates generated by the agent. I changed the probe to `curl -vk https://AGENT_HOST_IP:9001/ping` and documented the expected `204 No Content` response.
- The `docker exec portainer nc -zv ...` example assumed that `nc` exists inside the Portainer container. Docker documents that `docker exec` runs an executable inside the container, but does not guarantee that diagnostic tools are present in the image. I removed that command.
- The secret verification step only inspected the agent side even though the text said the secret must match on both sides. I replaced it with two documented `docker inspect --format` checks so both the agent container and the Portainer Server container can be verified.
- The expected listener output for `ss`/`netstat` was too specific to one formatting style. I generalized it to "a LISTEN entry on :9001".
- The UI guidance referenced `Reconnect` or `Update` buttons that I could not verify in current Portainer documentation. I changed the section to a documented configuration check around the Environment URL / Address field and the required `host:9001` format without a protocol.
- The certificate/TLS guidance was too vague for standard Portainer Agent behavior. I updated it to reflect the actual failure mode here: using HTTP instead of HTTPS, or strict certificate validation against the agent's self-signed certificate.
