## Issues Found

1. **Wrong OpenTofu version for write-only attributes.** The intro claimed write-only attributes were introduced in OpenTofu 1.10. They were actually introduced in **OpenTofu 1.11** (released December 9, 2025). Fixed in the introduction.

2. **Wrong OpenTofu version for ephemeral resources.** The "Ephemeral Resources" section header said "OpenTofu 1.10+". Ephemeral resources (as managed resource type) also landed in **OpenTofu 1.11**. Updated the header to "OpenTofu 1.11+".

3. **Misleading `aws_iam_user_login_profile` example.** The first code block implied `password` on `aws_iam_user_login_profile` is write-only. That resource does not accept a password input at all (the password is generated by AWS and returned as an output attribute), and it has no `password_wo` argument. Removed the example; the `aws_db_instance` example that followed is a correct demonstration of the concept.

4. **Incorrect write-only attribute name for RDS.** The post set `password = var.db_password` and claimed this was write-only. The actual AWS provider write-only attribute is `password_wo` (with a companion `password_wo_version`), introduced in AWS provider v5.88.0. Updated all examples to use `password_wo` + `password_wo_version` and corrected the version note.

5. **Ephemeral value assigned to a non-write-only argument.** The ephemeral resource example assigned `ephemeral.aws_secretsmanager_secret_version.db_pass.secret_string` to `password`. Ephemeral values can only be assigned to write-only arguments - assigning to `password` would produce a configuration error. Fixed to use `password_wo` / `password_wo_version`.

6. **Incorrect update-handling pattern.** The "Lifecycle" section used `lifecycle.replace_triggered_by = [var.db_password]` to force replacement on password change. This wouldn't work (you cannot reference a variable in `replace_triggered_by`, which requires resource/data addresses) and it is not the documented mechanism for rotating write-only values. Replaced with the canonical pattern: bump the `password_wo_version` argument to trigger an update.

## Review Notes

- The `Understanding Write-Only vs Sensitive` comparison table is accurate: write-only values are not persisted to state, not visible via `tofu state show`, and not re-read on refresh.
- The `tofu providers schema -json` + `jq` command to inspect `write_only: true` on attributes is correct and useful.
- Readers should note the AWS provider version requirement (v5.83/5.88+ depending on resource) and OpenTofu 1.11+ runtime requirement for these features to work. The post now states the provider version correctly, but could be more explicit about the OpenTofu runtime requirement in each example.
- The `aws_secretsmanager_secret_version` ephemeral resource has been available in the AWS provider since v5.80.0; pairing it with `password_wo` requires at least v5.88.0 for `aws_db_instance`.
