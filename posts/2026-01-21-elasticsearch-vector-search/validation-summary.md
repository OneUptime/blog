## Issues Found
- The Inference API example created a `text_embedding` endpoint with `"service": "elser"`. ELSER is a sparse embedding model/service, not a dense text embedding endpoint for a `dense_vector` field. Changed the example to use the Elasticsearch service with the built-in `.multilingual-e5-small` E5 text embedding model.
- The ingest inference processor example used `input_output` as a single object. Updated it to the documented list form so it matches the current Elasticsearch inference processor examples.
- The similar-document Python examples retrieved `content_vector` from `_source` without requesting vectors. Current Elasticsearch excludes dense vectors from `_source` responses by default. Added `source_exclude_vectors=False` to the `get` calls before reading `content_vector`.
- The quantization example used `confidence_interval` under `dense_vector.index_options`. This is not a documented current `dense_vector` index option. Removed it and kept the valid `int8_hnsw`, `m`, and `ef_construction` settings.

## Review Notes
- The `query_vector` arrays containing ellipses are illustrative placeholders; real requests must provide a complete vector with the same dimensions as the mapped field and generated by the same model as the indexed document vectors.
- For production hybrid search, RRF retrievers are usually a better starting point than manually tuning text and vector boost values because BM25 and vector scores are not naturally on the same scale.
